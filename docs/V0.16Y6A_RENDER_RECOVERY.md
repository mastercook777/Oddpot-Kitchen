# Y6a · 3D 场景恢复与版本回归修复
2026-11-25：玩家暂时验收Y6；餐厅文字/UI遮挡细节，归入Z1优先约束；部分3D场景需刷新才显示，先修稳定性。PR119 3D烟测成功，核心615/619；4项版本正则要求数字后必有字母，Y.6不符合；共9/17工作流成功，8失败均需复验。
## 已发现代码缺陷（用户具体失败现场尚未复现）
- 启动 Promise.all 任一模块/Three 超时导致三场景均不启用；成功晚到也不再激活。
- 各 renderer fail() 永久 disabled；真实 WebGL contextlost 或初始化异常后无恢复。跨场景 RAF 原先先绘新场景再释放另一个 renderer，存在短暂并存；DOM 重建/隐藏尺寸需等待。
## 方案
- 核心游戏启动独立于3D；三个模块独立、异步启用，网络失败按有界重试策略重试，迟到成功可用，不阻塞存档/游戏。共享 Three import，失败后可用备用 CDN（同版本）并有限重试。静态模块重试仅使用有限 query variant；不无限请求。
- 各场景有独立恢复控制器：异常释放实例、回退原2D，冷却后自动重建，最多3次连续失败，离场/回场或用户主动重试恢复预算；成功渲染稳定后复位失败次数。contextlost 同样处理，正常 dispose 不触发重试。隐藏/零尺寸不创建新实例。先释放非目标场景，后渲染当前场景。状态/错误与可手动重试提示，不刷新页面、不触碰存档。
- 版本 Y.6a，四旧正则兼容 Y.6 及带后缀版本（仍检查标题/构建一致）；保持核心版本及2D离线兼容。
- 追加可控状态机测试和浏览器单页场景切换、人工 contextloss/延迟模块加载回归；真实设备是否仍复现由玩家验收。Z1 不启动实现，下一阶段先解决信息遮挡、场景主导、上下文操作与低噪声经营HUD。
