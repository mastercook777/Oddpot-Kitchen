# 怪味食堂 v0.9 · 咕噜小厅与奇幻经营成长（实现记录）

**实现来源：** v0.8.5 main，工作分支 `feature/v0.9-fantasy-diner-growth`。本轮仅使用现有 Canvas / CSS / 程序绘制像素素材，没有生成或引入正式美术资产。

## 核心变化

1. **可见的第一次扩店：** 初始 2 桌、4 座；营业至少第 3 天、声望 ≥2、金币 ≥160 时，可在营业后的成长页面花费 160 金币一次性建成「咕噜小厅」。从此 3 桌、6 座，真实作用于顾客占座、桌边交互范围、主厨碰撞、跑堂路线和 Canvas 桌椅绘制。扩建不可重复扣费，账本记 `expand-third-table`。
2. **有需求的店面：** 新客按日计划到场；坐不下的客人保留 `waiting` 等位状态，在门口以程序绘制小人呈现；新增等待高峰和未能入座记录。持续经营后潜在客流会有所增加，扩桌创造真实客容量，同时带来厨房压力。
3. **每日有限采购：** 四种原本可购买的基础食材，按当天种子随机上架 3–4 种，各限量 3–7 份（随机抽取），单价参考成本价的 85%–135%。`market.dayKey` 保证同一天重进界面或读档不会刷新。购买走原 `transact`，库存和金币只变动一次；野外/Boss 专属食材仍不可采购。
4. **长期营业账：** 延用原三日内部日历结构保存旧存档兼容，但 UI 改为累计营业天数；每晚累计写入 `history`，显示累计营业额、累计服务人数、今日等位高峰、未能入座人数。保留旧版 `report` 和交易账本。原首次 DAY3 厨王踢馆保留，后续每轮第三天不强制重复该踢馆；改为常规客流主题。
5. **奇幻包装：** 顾客化为铁甲矮人、菌帽一家、史莱姆街坊与幽灵鉴味师，更新程序绘制小人造型和独特对白。主要料理/食材重写为噼啪、咕噜、菌雾、吐息、跳跳等古怪主题；保留原始食材/配方 ID、熟度区间和售价以便存档与引擎兼容。

## 对旧版本的约束

- 存档 `version=4`、`SAVE_KEY=oddpot-prototype-v04` 不变；老存档会补 `dining`/`history`/`market` 默认值。
- 不替换 `src/cooking_v063.js` 的实时烹饪判定，不添加旧 3×3 棋盘作主玩法。
- 扩建只增加真实可用座位，不增加虚拟销售和不存在的订单；仍共用原服务时钟和账本。
- 目前 **未** 实现商人专供食材、隐藏菜单、长期熟客身份、广告活动、第三厨位。它们属于后续经营成长迭代，不应把本记录理解为完整 v0.9 终态。
- `standalone.html` 的离线包尚未重新打包；在线 Pages 以 `index.html` 为准。正式发布离线包前必须运行 `python scripts/build-standalone.py` 并回归。

## 回归目标

- iPhone Safari 检查第三桌是否可达、菜落桌位置正确、三个桌的气泡不拥挤、摇杆是否被等位提示挡住。
