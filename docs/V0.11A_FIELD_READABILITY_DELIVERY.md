# v0.11-A 地图轮廓与目标可读性 · 第一批交付

状态：开发分支已实现，自动测试与 iPhone 真机验收待确认。主线 v0.10.4 当前仍是发布基线；**本稿不代表 v0.11-B/C/D 已完成**。

设计来源：[V0.11_EXPLORATION_2_0.md](V0.11_EXPLORATION_2_0.md)。仅实施 v0.11-A，不改变原三段分支、HP/Boss/背包、采购与餐厅经济。

## 可验证的改动

- 新增 `src/field_rules_v011a.js`：`hazardPhase` 与 `fieldTilePath` 纯规则。同一个 4.2 秒计时、roots 3.15 秒 / 热泉 3.45 秒爆发阈值、0.55 命中半径供受伤判定和 Canvas 预警共用；不为动画另造伤害窗口。
- `src/field_biomes_v081.js`：保留两大区八生态、原始采集来源和关卡规模；用种子改变部分物理障碍与实际资源点分布。移动障碍必须避开所有备选食材格、危险格、出生和 Boss，并通过出生到所有节点/首领的连通验证；不能通过则回退原布局。
- `src/scenes_v04.js`：采集点用小椭圆地面标记与食材本体，目标用椭圆高亮；陷阱改为常驻尖裂轮廓，预警和伤害窗口使用共享相位，半径与伤害一致；场景奇遇改为可识别的背包旅人轮廓。沿真实可通行格显示低对比度采集引导路标。
- `src/field_v04.js`：伤害机制只改为调用 `hazardPhase`，不更改 HP、跳跃/攻击、奖励、价格或敌人规则。
- `tests/v011a_field_readability.test.js`：八生态×64 种子可达性/布局变化、危险点不覆盖掉落和出生、危险预警阈值、无障碍路径。
- `scripts/build-standalone.py`：将纯规则模块排在地图生成前，避免离线版漏依赖。

## 本批边界、待验收与已知风险

- 目前只是程序绘制的可读性与地图布局基础，**不是** v0.11-B 神秘商人/金币交易、v0.11-C 专供食材和稀有料理。现有奇遇背包旅人的行为依然是旧流浪调味师事件。
- 当前可达检查是基于真实整数障碍格的四方向通路；仍需多机型实际走位复验，尤其石头/巨根视觉边缘与近身碰撞是否一致。
- 视觉区分必须人工检查：暗森林、亮热泉、320×568、375×667、390×844，目标物/裂纹/旅人无需文案能辨认。自动测试只验证规则，不证明 iPhone 已通过。
- 待评估真实难度与地图节奏是否因变动障碍有变化，不能因为路径长度异常放慢日循环。
