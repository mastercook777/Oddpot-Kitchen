# CB0+CB1 · Cooking & Menu Build workshop v0.1
2026-11-27 · 依据 [GDD v0.2](COOKING_MENU_BUILD_V2_GDD.md) 第12节；正式0.15.0-alpha.11不变。首版必须含真实一晚，否则不作为可验收交付。
## Scope
独立 cooking-build-workshop.html；使用真实引擎、研究动作、Canvas餐厅、员工、实际波次/事件、订单与交易；初始实验配置厨房阶/桌/厨位/厨具/员工/客群/压力/库存/seed；真实研发、随机品质/词缀、收藏、Deck、备餐、正常手动+倍速、日报、A/B及同快照重试。无正式存档读取/写入、正式页面入口不变。
## Implementation contract
新增纯 CB 规则模块，蓝底→普通词缀→传说或第二普通/高级；基于真实结果、独立事务seed；成功且全熟+有效技法可达蓝；失败不鉴定。初版开放已真实接入的 quick/fine/aroma/aftertaste/wait/frugal/solo/stars 八条，其他16条不入池。每菜最多12个工艺，完全同签名合并，满时拒绝新增并提示（替换UI后置）。预置工艺明确标注。实验状态 cbExperiment 仅工坊创建：engine 的 craft snapshot、菜单合法性/点单权重/耐心/满意度/生产返料及实验客源计划采用有守卫的附加路径；默认未启用行为不变。老规则的价格/技法经济不叠加新词缀。真实库存、支付、员工/事件、交付/点评不改。正式游戏不保存实验字段；不做旧档迁移。预算 7/9/11/13，1–5 Cost，至少3道不同菜，大师最多4；实验中不开放特供或换菜绕过，原波次选择仍真实。开业前冻结菜单工艺与条件，备餐使用同快照，重试回到备餐前。报告按真实订单与交易汇总，不编造收益。1×/2×/4× 同一时间步推进移动/生产。边界：原引擎限制实际厨具/章节；蒸笼如需单独云港预设则明确；不承诺全部词缀/正式美术/长期经济已平衡。
## Test
纯规则、种子分布、预算、实际生产/点单/价格/耐心/满意度/返料、真实整晚及四槽，隔离原档、重复重试、三手机尺寸浏览器；旧CI全绿后合并。验证与已知差异在末尾追加。
