## 1. 与 v0.7.3 Lab 的关系

本版把「移动主厨 + 厨位值守 + 取餐上菜 + 小芽/阿火分工 + 主动消耗精力」接入正式经营。**没有创建第二份营业引擎**：所有订单、真实原料扣除、厨位制作、交易和每日回顾仍由 `src/engine.js` 管理。

独立的 `experiments/v07-walkable-diner-lab.html` 保留作对照；新开业时 `src/app.js` 调用 `createService(game,{walkable:true})`。**老存档如果已经在经营中，其原始 `service.walkable` 默认保持 false，完成这晚后下一场新开业才切换新玩法。** 这样防止用户读档瞬间进入无人的后厨，被迫等待。

## 2. 已实装的工作职责与交付链路

- **只有主角**：靠近其中一口正在处理订单的厨位才按正常速度制作；离开时无人工作的锅进度停止。主角只能在一口锅边加工；端菜时不能同时做菜。
- **阿火已雇佣**：按现有岗位设置驻守被分配的厨位，该厨位可在主角不在时持续生产；主角可照看另一口锅。仍保留原来厨位等级和工艺时间计算。
- **小芽已雇佣**：从出餐台依次取餐，沿厨房中线和桌边路线移动，然后才真正交付；送达后沿路线回到出餐台，不在桌间瞬移，不允许同时处理两份餐点。
- **未雇小芽**：菜在出餐台等待主角，若较长时间没人取餐，会以较慢的顾客自取作为轻度 Idle 兜底；不会瞬间送达。
- **物理交付**：厨房制作完成的订单从 `cooking` 进入 `pickup`，主角走近出餐台自动拿起一份，走到对应桌自动上菜；小芽处理 `delivering`，最终都进入原有 `flying` → `eating` → `review` → `served` 的落桌与评价环节。对人工/小芽配送，`flying` 是短暂的交接缓冲，不绘制原来的空中抛盘。**收入只通过原 `sale-orderId` 事务记一次**。
- **两种顾客服务**：手里持有该桌料理时，自动上菜；没有端盘且顾客耐心紧急不足时，玩家可以**主动点击**临时的安抚技能。普通取餐、上菜、煮菜不消耗精力。

## 3. 视觉与操控三条硬性约束

1. **所有人物保持正常比例：** `src/scenes_v04.js` 对 chef、helper、waiter、guests 都使用 `DINER_ACTOR_SCALE = 1.13`，不通过放大主角建立层级。原有 `pixelActor` 的动画与角色外观继续复用。
2. **移动合理、速度连续：** 角色在正式餐厅 Canvas 内的归一化世界坐标运行，和家具使用同一套 translate/scale；`src/walkable_restaurant_v07.js` 以约 0.40 横向单位/秒、0.32 纵向单位/秒和分轴碰撞来移动，阻止穿墙、穿越餐桌/吧台实墙。小芽沿 `PASS → 中央通道 → 目标桌 → PASS` 往返，串行一次一单，无瞬间跳桌。
3. **工作状态只用图标：** 唯一移动主厨头顶根据当前状态显示 🍳、🍽️、💛 等小图标。**不附带状态文字、放大文字气泡或标签。** 正式画面不得同时保留先前固定的主厨 sprite。能耗特殊技能的 UI 按钮也只显示功能图标和消耗精力值，并提供无障碍 aria-label。
4. **探索与经营使用同款摇杆：** 复用 `src/controls_v041.js` 的 `joystickVector`，手指在场景拖动触发动态摇杆；手机粗指针设备上旧座位/厨具透明点击区域不会抢走移动手势。PC 可继续用 WASD/方向键。
5. **精力自主权：** 全力烹饪和紧急安抚只有玩家主动点击临时按钮才会扣精力；不得再以“站在厨位几秒”自动扣。正常劳动永远免费，0 精力仍然可以移动、做菜、上菜。

## 5. 后续人工验收和调平

新经营会带来比旧自动模式更明显的时间压力。**这是玩法方向的自然变化，但不代表数值已经调平。**

优先在 iPhone 小屏检查：
- 站左锅/右锅自动加工，移动离开后计时停止；人物不穿桌、不在柜台隔墙处卡死
- 端盘后站在锅旁也不会分身做菜；端错桌不会自动交付；所有工艺售价和账本结算仍正确
- 小芽送菜/返回是连续路线，不存在跳跃或突然缩放；主角、顾客、阿火、小芽比例一致
- 工作状态图标与原有顾客台词气泡视觉区分，只显示图标，没有工作说明文字
- 全力烹饪/安抚仅主动点击消耗精力；同订单只触发一次
- 旧版营业中读档保持原有规则，正式升级会在**下一个新营业夜晚**生效
- 第一天单人开店的订单节奏是否过紧，是否需要适当增加等待时间、降低初始两锅并发，**不能因为玩家体验忙碌而让整场普遍失败**。
