# 《怪味食堂》v0.10.3 · 火候可视反馈与三色研发步骤复盘

**状态：功能已实现、GitHub 自动测试与网页/离线构建通过；iPhone 真机视觉及触摸体验仍待用户验收。** 基于 2026-10-13 `main` v0.10.2。用户明确提出：不要在实时烹饪中添加过量文字提示，利用已有成熟度和火候机制让玩家更清楚当前状态；研发后的 **recap 每个步骤用绿/黄/红标注**，让玩家知道下一次该修改什么。

## 1. 设计审查的重要发现（必须真实告知玩家）
当前主玩法源码：`src/cooking_v063.js` 中 `evaluateLiveCook`。品质计算：
- 基础 72
- 某香料比主要食材提前至少 1.05s：+4
- 翻炒（WOK）或轻搅（POT）：+5
- WOK 颠勺：主要食材下锅后 0–3.8s、至少两种材料同锅才得到锅气 +6
- POT 收汁：4s 后、至少两种材料同锅才得到收汁 +5
- 完全没有动作：+2（与动作加分互斥）
- 未完全成熟但达到“受热中”的食材：每项 -16；未下锅、偏生或焦糊可导致研发失败
- 全局上限虽写 90，但**当前 WOK 理论最高 72+4+5+6=87，POT 最高 72+4+5+5=86**。不可以对玩家说“90+ 是隐藏技巧”，也不可以把 87/86 明明做满的工艺染成黄色。
- `RECIPE_PROFILES` 不会给品质额外加分：每道菜 `playerCue` 以及 `resolveTechnique` 的适配现在影响**经济与客群价值**，尚不构成独立品质分。**不能凭空指责“动作先颠勺后翻炒”是错，现有公式根本不判这个顺序**。

## 2. 正确的三色复盘（真判定，不修改评分）
将已有两行“下料时间”和“操作时间”合并为**按实际时间排序的步骤列表**；每个步骤保留时间、动作、色标和一句**明确对应规则**的原因：
- **绿 · 有效**：食材最终熟透；提前下香料真正触发底香；翻炒/轻搅获得受热收益；颠勺/收汁满足了实际触发条件。
- **黄 · 可以优化但并非失败**：香料下锅太迟未触发底香；颠勺时机或在锅食材不足导致未获得锅气；收汁早于4秒或同锅食材不足；最终“受热中”少熟一截。不给并不存在的扣分。
- **红 · 已发生真实失误**：成品夹生/焦糊，或漏下料；具体红色标注真实问题，不把“没有拿到可选加分”标成错误。
- **出锅**作为最终步骤展示实际熟度与产出。重复食材、多动作同秒以 stable index 排序。各种标识都有**颜色 + 符号/文字**，不单靠色彩区分。
- 复盘页必须标出：`炒锅本机制最高87 / 深锅最高86`，达顶时显示“已达到当前机制的最高品质”；不要在此版本尝试解释或设计 100 分新评分。

## 3. 实时火候视觉反馈（不改操作）
保留现有成熟度四态 `偏生/受热中/熟透/焦糊` 与 19s 限时、锅具、按钮；额外做两层视觉：
- **食材按钮**：使用与裁决器一致的熟度与比例显示微型熟化进度条。偏生/熟化中=琥珀色，熟透=绿色，焦糊=红色；成熟后靠近现有焦糊阈值时用琥珀色“将焦”警示。进度条不代表新的火力数值。
- **锅下原信息条**：复用现有一行信息区域，用视觉状态清晰地说明 “尚需下料 / 仍有食材偏生 / 即将熟透 / 全部成熟可起锅 / 接近焦糊 / 已焦糊”。无需新浮窗、无需增加第三个文字教学区域、不要自动替玩家起锅。
- 状态与阈值基于 `liveCookAmount` / `liveIngredientState` 同一套代码，不另造伪百分比和新隐藏判定；`nearBurn` 是根据现有焦糊判定年龄/比率的提前风险展示。
- 保持 320px 竖屏、低于700px短屏按钮可触控、进度条不挤压锅面，颜色对比良好。

## 4. 技术范围与验收
- `src/cooking_v063.js`：只新增**纯展示辅助函数**，例如 `liveIngredientHeatFeedback`、`reviewLiveCook`。禁止修改 `evaluateLiveCook` 的评分、动作时间窗口、成功条件或 `RECIPE_PROFILES` 的经济效果。
- `src/engine.js`：`liveCookPreview` 可复用展示辅助函数输出，**不加持久字段，不改存档 schema**。
- `src/app.js`：结算页时间轴改成三色步骤，实时烹饪原状态栏变成清晰火候状态，RAF 原地更新，不每帧重绘 DOM。
- `src/cooking_v063.css`：色彩与窄屏样式。
- 新增测试：质量 87/86 可达上限、正常/黄/红样例、动作有效与无效的真实判定、接近焦糊警示、无状态改写、操作顺序与分数不虚构相关性、回放按时间排序。
- GitHub Actions 完整 `npm test`、网页打包、离线包重打包；**iPhone Safari 真机视觉与手势需用户验收**。

## 5. 不在本轮做
- 不改变真实研发的节奏、食材耗材、工艺与价格，**不重平衡到90–100**。若需要更大品质上限，必须单独设计数值，不可悄悄改分。
- 不强制每道菜有独立投料/翻炒顺序；当前 `RECIPE_PROFILES.styles[*].playerCue` 是指导口味风格的软建议，不是评分隐藏条件。
- 不新增正式美术资产，不加弹窗、不增加做菜中的长段文字教学。
