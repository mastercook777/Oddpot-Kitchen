# Z1 · 全局游戏化 UI/UX 设计规范
2026-11-25。Y6a 玩家明确确认稳定，PR120 17/17 CI 成功。Y6 暂验收，经营文字/UI遮挡模型细节。用户新增硬性约束：移动浏览器尤其摇杆操作不能误触选字、长按菜单。先确立统一设计契约，Z1a实际触摸修复；Z2分场景实现，不把视觉规格写成已实装。
## 核心方向：玩家在经营一个奇幻餐厅，不是在填写管理软件
场景优先、操作发生在世界中、信息按需逐层展开。统一日程仍是预测→探索→研发→菜单→备餐→营业→日报→成长；不强制改为开放世界，也不引入新资源或规则。保留真实操作路径、订单时钟、旧存档、默认2D及云港可玩性。3D通过Y6a恢复机制独立启用。所有新布局适配320/375/390竖屏、安全区与浏览器地址栏变化；桌面鼠标/键盘同样可玩。
## 信息与视觉体系
1. L0 世界画面：常驻主体，营业/探索优先留出至少70%有效游戏视口用于场景（实装后以可见场景面积、遮挡面积测量，不能仅靠放大canvas）；保持既有场景坐标与交互投影。无大面积顶部品牌、重复阶段说明或底部常驻操作表单。
2. L1 即时HUD：时间/进度、生命或精力、当前重要状态、暂停/技能，少量图标数字；状态色以暖金可操作、青绿正常、赤色告警；颜色必须配符号/文字。字体中文可读，常规信息>=12px，关键>=14px；按钮命中区至少44×44 CSS px、间距约8px；可视图标可较小。边缘安全区，避免覆盖人物/出餐台/危险信号。HUD不默认用全透明低对比。
3. L2 上下文引导：点餐/取餐/上菜由现有 dinerGuide 与实际状态驱动；只显示当前可执行的一个动作，场景中目的地高亮/方向引导优先。引导首次完整解释，熟练后仅动词+对象；空闲自动隐藏。桌上食客头顶改为小状态图标（等待/饥饿/吃饭/满意/不满），点击详情打开短信息卡。台词最多一条、短暂、不盖角色；原剧情与订单内容保留于详情。信息不能只靠颜色或不可见动作；保留 accessible labels。
4. L3 实体账册/抽屉：库存、图鉴、经营数据、员工、成长、菜单编辑用短列表/分类页/可滚动抽屉，保留原按钮和真实数据来源。报告以成果/关键瓶颈/下一步为首屏；详细账本按需展开。打开抽屉暂停移动输入，关闭恢复原场景；不改变现有模拟暂停规则。事件/结算例外可用模态层。
## 各阶段
|阶段|场景优先布局|移入二级或减噪|主要交互|
|---|---|---|---|
|清晨/预测|餐厅主画面+门口今日目标|客流/库存/雇员细节|点实体热点、门口出发|
|探索路线|地图节点与目的地卡|产出/风险/供应说明折叠|选路线/目标，不改变路径|
|探索行动|场景铺满，血量/背包/路线与技能贴边|撤离二次确认、冗长指引|左侧浮动摇杆/右技能、采集提示|
|研发准备|工作台、厨具和食材托盘|工艺长说明/图鉴|选2–3食材、选择厨具|
|实时研发|锅具占主视觉，食材条、火候与操作键紧凑|重复进度、文字说明|保留真实下料/翻炒/封笼/烤串动作|
|菜单/备餐|实体菜单板/厨房操作台|营销/员工成长/预制详细账本|可验证的菜单搭配、准备、开业|
|营业|场景最大化，上边缘短HUD、当前任务小提示、右技能|全部订单/详细财务/长期目标进抽屉|走近厨位/出餐台/桌位，保留实际dwell|
|日报/成长|星章/今日结果、餐厅扩张预览|交易明细、所有升级条件|确认结算、成长选择、下一天|
## 手机浏览器输入契约（Z1a 本轮实际落地）
游戏非编辑文本全局 user-select:none/-webkit-user-select:none、-webkit-touch-callout:none；阻止非编辑文字 selectstart、contextmenu、dragstart；input/textarea/select/contenteditable及明确可复制内容除外。禁止对整页 touch-action:none 或全局 touchmove preventDefault；只有探索、餐厅、烹饪手势面使用 touch-action:none。点击按钮 touch-action:manipulation，抽屉/详情/列表保留滚动；原生输入可编辑。摇杆按下只接受非操作控件、非弹窗的有效场景面，pointer capture 在稳定#app，触摸开始非被动 preventDefault，移动按拥有的手指ID过滤；第二根手指的技能/暂停/背包不能被全局拦截。触摸结束/cancel/lostcapture/页面hidden/blur/离场/暂停/事件/弹窗释放方向和选区，避免粘杆；每秒DOM重绘同场景时保留摇杆位置。烹饪手势同样取消浏览器长按/选字，但不吞按钮。CSS与事件层双保险，不能保证所有厂商浏览器系统级手势。Android Chrome、iOS Safari真机长按/跨文字拖拽/双指技能/事件后释放必验；自动测试 Chromium移动仿真与源码契约不等于Safari实机。
## Z2交付顺序与门槛
Z2a 营业+探索主HUD和场景遮挡（首先解决本用户无法看细节）；Z2b 研发与备餐/菜单；Z2c 清晨、路线、日报、成长、图鉴及抽屉；Z2d 全局一致性/可访问性/低端屏幕。每轮独立版本、实际画面和真实操作回归，用户验收后推进。Z3音效/转场/质感/性能。不可为美观删功能或绕开真实订单模拟。Z2a验收：场景有效面积与遮挡前后对比，文字数量下降，实际可上菜/烹饪/探索，错误信息仍可达，320/375/390不裁切，真机无选字及卡杆。Z1不承诺完成Z2的UI实现。
