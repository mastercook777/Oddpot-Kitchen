# 《怪味食堂》v0.7.6 · 开店前首屏 UI 信息层级重构

**实施日期：2026-10-12**  
**状态：已合并 \`main\`；代码级构建/回归和 Pages 部署以当前 GitHub Actions 为准。iPhone Safari 真实截图、实际手势和小屏验收仍需玩家确认。**  
**正式 H5：** https://mastercook777.github.io/Oddpot-Kitchen/

## 1. 来源问题：旧首页是三套信息层叠

玩家截图显示「怪味食堂」页在开店前同时出现：大 HUD（金币、声望、版本）、金色日期/今日情报/图鉴栏、覆盖餐厅锅具的大「今日情报卡」、覆盖桌子的长句教学说明、额外独立消息条、以及下方两次分层的工具操作区。主要问题不是个别边框，而是 **当天目标、长期收集、场景与阶段操作争夺同一块空间**。

因此本次没有继续叠浮层，而是 **在 \`forecast\` 阶段独立调整页面外壳与视觉层级**。不重做正式营业 UI、不改游戏库存/经济/任务规则。

## 2. 真正实施的视觉结构

由上到下四部分：

1. **紧凑 HUD**：怪味食堂 / 边境小食堂、真实金币与声望、设置。下一行仅显示「第 X 轮 · 第 Y 天」和「☀ 开店前」。**该阶段不在头部占用图鉴数量或显眼版本号**。其他阶段仍有版本和图鉴数量；在设置中可随时查到正式版本 \`v0.7.6\`。
2. **唯一一张今日任务卡**：使用现有 \`serviceDayPlan(game)\` 的真实 \`pressure\`、\`count\`、\`goal.label\`，第三日使用原有爆炎厨王提示。不新造固定「客群偏好 / 推荐料理」内容，也不再同时展示一大块原型教程。
3. **餐厅场景预览**：沿用 v0.7.5 正式餐厅的唯一 \`drawRestaurantV075\` Canvas，不再在厨房/餐桌上叠大段提示框。只在场景下缘给出非常短的两项静态标签：当前两口厨位类型、两桌四席。
4. **操作区**：一行简短「出发准备 · 库存 N 份」，三个轻量快捷入口「仓库」「便当」「图鉴」，下方只有一个突出主按钮「🌲 出门取材 →」。

**功能没有删掉：** 仓库采购和库存、当日探索便当、工艺图鉴及选用版本、去野外寻找食材均沿用原有 \`data-act\` 和引擎状态。主按钮始终是出门取材，因为目前阶段固定为 forecast→field；**不能为了视觉变化擅自根据库存绕过 field→research 的正式流程**。玩家下一页仍可选择跳过探索去研发。

## 4. 边界和回归要求

- 只改变 \`forecast\` 页面布局；\`field\`、\`research\`、\`menu\`、\`prep\`、\`service\`、\`report\` 等阶段维持原功能。**不删库存购买、便当或图鉴逻辑**。
- 保留 v0.7.5 全餐厅统一 Canvas 坐标和原有食堂画风，没有重新增加一套不可维护的家具 DOM 模型。
- 不显示固定大块“今天的菜单，不必和昨天一样……”与重复的状态条；如需帮助信息放设置或首次教学，不把长文章贴在场景中。
- **版本号纪律**：下一次版本更新需要同时调整 package.json、index.html 的 title 与 JS 资源查询、app.js 实际 HUD/设置显示，以及离线版脚本和生成结果。此前曾出现用户设备上仍看见 v0.6.3 的截图，因此不要只改 browser title。
- iPhone Safari 需验收：320×568、375×667、390×844 容器下首屏不遮挡、底部「出门取材」可点击、三次级入口至少 44px 易点、场景比旧版本有更大可见面积，顶部信息不抢占注意力。关闭/打开图鉴不会清存档。
- 自动测试可以验证状态和 DOM 结构，但 **不能取代真实设备排版截图验收**。
