## 复核方法和结果

- `tests/v015d_cloud_integration.test.js`：9 项覆盖实际研发动作→品质 84 的菜谱版本、迟封/早排反例、首日用 120 当地金币研发三道纯当地菜并真实营业、四档市场及旧报价迁移、三包券及跨章读档、6 种子两路线生态、蒸笼与折价、本地活动及星章客流。
- `node scripts/check-v015d-economy.mjs`：固定 30 种子，云港两厨位、相同三道本地菜，各自真实创建营业/逐秒结算。充足供料（每种 80 份）的**星前→星后**平均计划 7.4→10.4 单、实际完成 7.4→10.4 单、经营利润 133.3→191.2，峰值排队 0.4→2.4 人；供料稀缺（每种 2 份）时完成 2.37→2.37 单、利润 36.07→36.07，星章不会凭空补货。这是库存边界对照，非真实野外战斗收益、连续多日净现金或营销回本推断。
- `npm test` 的构建测试依赖 Vite。当前执行环境无 `node_modules/vite`，离线 npm 缓存也无包，因此这一项无法在本机完成；最终 `npm test` 共 524 项，其中 523 通过；唯一失败是构建门禁报 `vite: not found`（环境依赖缺失），不是已证明的源码通过构建。`scripts/check-v015-cloud-browser.mjs` 已加入 320/375/390 三档采购/兑换与蒸笼升级检查；本环境没有 Vite/Chrome，尚未执行浏览器、Pages、离线手机视觉和真机触控验收。

## 玩家继续试玩时需观察

1. 实际探索击败敌人/结算背包后的材料比例、当地市场开支和两店往返频率；上述供料对照不是探索收益测量。
2. 鸡葱、菌蒜、薯椒三包哪个常被选、委托是否值得回旧店营业；当地首星后缺料和排队是否同时增加。
3. 320/375/390 屏幕上的三包按钮、蒸笼动作反馈和客人图鉴，再用 iPhone/Android 检查中文、触控、帧率；未发布前不能声称线上生效。
