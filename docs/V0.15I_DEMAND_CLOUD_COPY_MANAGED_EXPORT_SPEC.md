# v0.15-I · 点单纠偏、云港地域化与旧世界托管设计
**状态：先行规格；本轮只实装点单纠偏与地区文案。托管/新生态为候选，未实装。**
**基线 main v0.15.0-alpha.8，2026-10-22。**

## 1 代码诊断
engine.js 的 selectArrivalDish 对每个顾客固定取顾客口味匹配分最高的料理，平分则取低价，缺少已点次数和非劣质菜之间的多样选择。这会系统性造成单品垄断。菜单重复栏位不应使一道菜更受欢迎。
云港部分今天仍用旧世界矿井、菌帽经营随机事件，cloud_weaver/cloud_docker 没有独立点评因而回退史莱姆口吻；探险 bossHint 把 cloud 地区错误识别为菌王。
现有云港只有 cloud、cloud_roost 两类生态模板（虽然地名较多），四种本地普通食材，手动旧料每天兑换一箱八份。旧店有独立日数、员工、仓库和交易账本；跨章券是全局 ferryCredits。

## 2 v0.15-I 本轮修复
点单候选按 recipeId 去重，保留原真实口味分（价格、顾客喜好、工艺与烤架）。只从至少45分、离最高分差不超过28分的菜抽签；口味分较高权重仍较高，已被点次数适度降低权重（非强行平均）。用 scenarioSeed、order.id 和食客种类派生可复现的随机抽签，不使用 Math.random，不跨档重掷，不修改已点订单。维持特殊评委优先辣菜、隐藏菜采购与合规出餐。顾客排队、卖出和口味评价沿用实际状态，不凭空均分销量。日报记录实际点单次数与实际售出数，诊断缺料/流失。
云港两个营业事件采用码头货船/云织夜市文本，同名 choice IDs sign/soup 按当地顾客转化，消费与运营事件保持旧有事务；新增当地两种食客全套点评，旧世界顾客作为旅客出现则保留原口吻。云港危险提示必须出现风暴晶核和风暴首领，不能出现菌王。

## 3 v0.15-J 候选 · 原店托管与定期航运（本轮不实装）
### 3.1 从因果到收益
玩家在旧店获得三星、传送门、至少一位雇员后开启托管。旧世界员工留守边境食堂，玩家到云港可选择托运偏好「香辛／菌香／野味」，旧店派商船定期送物资；云港新食材仍需本地探索，旧店亲自经营仍有金币、员工成长、三星/支线与一晚一张八份出口券的额外价值。
### 3.2 节奏和货物守恒
首版每完成 2 个真实云港营业日（关门日报时）才生成一次运输批次；最多积压1批，每批常规边境食材配额4–6份。只有旧世界真实仓库持有的食材可以转运；出货时在旧仓真实扣减，入云港时真实增加，两个 ledger 记录同一个序号，不会重复。库存不足只寄有货部分，缺货不补发 phantom goods。建议旧店金币支付8–12的运费，需经济测试后定稿。时间按游戏内已结算营业日推进，拒绝按现实系统时间/APP挂后台刷货。跨章传送、存读档、每天反复打开窗口不增加船期。初期可免费首批教学，但不可无穷免费。
托管与亲自完成同一旧店营业日互斥，不能重复做两次收益。同一旧世界库存既用于手动经营也用于真实转运，因此玩家需要返回旧世界采集/采购，或调整运营。保留原全局委托券作为比低额度托管更强的主动收益；托管不能取代手动游玩。
建议数据 global legacyDispatch：enabled、focus、cloudDaysSinceDispatch、shipmentSeq、pendingCargo、lastCloudDayKey；不写入 LOCAL_CHAPTER_FIELDS。出货与收货要验证分账和事务幂等。暂不加入无成本「自动虚拟营业生成金币/食材」，若以后需要真实自主运营，须另做金币、原料消耗、员工工资、欠薪、营业报告模拟和多日审计，不能每天空投。

## 4 v0.15-K 候选 · 云港第二生态与菜品增长（本轮不实装）
现有云港风道、雷羽巢缘为两个生态模板。新增区域必须差异化地形、战斗、食材、菜谱、客群，而不是换色。
第一优先镜露花园：浮空温室、反射湖、吊桥、镜面光照机关，原生新材料镜露番茄和银翼香草，4道精选菜分别覆盖炒锅/炖锅/蒸笼，新增至少一位喜酸香清爽的当地园丁客；至少一道食谱融合原世界进口香料，并由新本地食材+原食材组合真实研发。云港探索应按区域选择，每区域自带玩法/资源与敌人行为，不复用旧世界植被。
第二优先雷暴矿脉：断裂浮石、雷光线路、导电地面，原生材料磁纹块根与雷铃菇，新探矿客口味偏丰厚烧烤，展开4–6道独立配方。风险与风道也必须区分。
每新增原料必须加入独立采集点、地图配置、物理资源、熟化参数、图鉴、菜谱、真实口味需求/市集策略。所有新增食谱仍遵守物理厨位覆盖；不让旧世界旧菜在云港直接上架。

## 5 验收、开发次序
P0 本轮：点单分布通过固定 seed 多组模拟；偏好分显著差时强菜仍占优；客人真实已点与成交日报可核；云港当地顾客/事件与首领提示正确；无存档/旧档重新洗单；npm test、16组CI与离线构建同步。
P1 下轮：托管与真实库存转运 MVP，小批量两营业日一寄/商会角色包装/跨章独立账本，先一条完整物流闭环。
P2：镜露花园独立美术/地图/两食材/四菜/新顾客，再做雷暴矿脉。
审计线：两章 12–30日真实现金、仓库、委托产量、自动物流频次、食材短缺与菜品订单分布；直到量化后才调整免费八份手动券或者运输成本。
