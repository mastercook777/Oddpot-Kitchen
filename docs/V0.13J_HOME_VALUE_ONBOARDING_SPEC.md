# v0.13-J · 活的厨房、工艺价值与第一日引导

状态：已实装待手机真机验收（玩家 2026-10-16 完整重开存档反馈）。本稿先于功能代码提交到 GitHub 分支。

## 玩家体验

1. 开店前仍使用当前真实餐馆 Canvas。空店时同一比例的主厨和**已雇佣**员工做准备工作，沿现有可走通道短距离走动、停留、说两句简短闲聊；未雇佣角色不得出现。厨房炉火、蒸汽和小动作持续运动。背景生活动画不能产生订单、收入、库存、经验或虚构顾客，也不占触控层；营业时继续以真实服务状态绘制。
2. 菜谱的售价显示清晰的工艺差别。保持菜谱基础价，配对工艺的定制加价；仅经菜谱×工艺人工配对认定的招牌工艺另加 2 金币，再以品质 80–84 / 85–89 / 90+ 分别加 2 / 5 / 7 金币；72–79 不加价。低价基础菜的高品质收益可感知，但预算敏感的食客仍可能拒单。工艺的专属耗时和客群适配继续生效；不要给所有“爆炒”等风味词叠加通用 Buff。研发结算、图鉴、菜单、订单快照、隐藏菜和营业账本读同一 `recipeCraftSnapshot`。已开始的订单价格绝不因后来切换工艺而变。
3. 全新存档第 1 天给出简短、可跳过的逐步引导：主页认识循环与采购/出门，路线选采集或狩猎，回店研发可选择尝试或先用现有菜，菜单上架后备餐、营业与结算。仅提示当前可执行的动作，不强制学习、探索或开锅；首轮结束后不再弹出。旧存档不因缺少引导字段被判作新玩家。设置可重看引导，跳过不改游戏进度。

## 实现与边界

- 首页动画读 `game.crew`、`game.kitchen` 和餐厅坐标；不创建第二个营业模拟。员工闲聊频率低、同屏至多一个气泡，短屏不遮主按钮；减少动态效果设置下保留静态人物和厨房。
- 价格只改变**未来**订单快照；旧订单与日报按原记录结算，存档 schema/key 沿用。质量加价不修改菜谱基础价、材料成本、制作时间、采购、评级目标或顾客预算。需要跑实际订单对照，监测销量与利润，不把价格上涨直接等同利润上涨。
- 引导状态单独持久化在既有存档对象；新存档明确初始化，旧存档不补发。页内一条提示与按钮，不盖住摇杆、研究投料、餐厅动作区。阶段跳转后引导自动跟随；关闭后可从设置重开。
- 验收：320/375/390 竖屏和矮屏可点；新/旧存档、跳过/重看、离线包；价格等级、工艺差别、订单冻结、旧订单、隐藏菜倍率；首页未雇佣/已雇佣/第三厨位三种人物状态。iPhone 和 Android 主观体验由玩家验收。

## 未定与后续

第一日引导先覆盖主循环，不做手势教学或自动代玩。菜谱基础售价、各客群预算与稀有料理总体经济仍需多日真实经营审计；本轮先解决品质提升不反映售价的直接反馈。

## 实施与验证（2026-10-16）

- `home_kitchen_v013j.js` 在现有餐厅 Canvas 空店状态绘制主厨与实际雇佣的帮厨、跑堂；第三厨位组合购买后才出现小炭。19秒一轮的两句闲聊，不生成客人或业务事件；减少动态效果时人物静置、不绘制蒸汽和气泡。
- `recipe_value_v013j.js` 由唯一 `recipeCraftSnapshot` 计算品质、配对工艺加价与招牌加价。当前最高真实可达品质炒锅87、深锅86，90+档仅兼容历史/未来参数。订单价格仍在到店点菜时冻结；高价可能受原预算限制，未改 `customerFit`。
- `first_day_guide_v013j.js` 为新存档标记可跳过引导；旧存档缺少标记时保持安静。空店、选路线、研发起始、菜单、备餐、日报显示紧凑提示，探索摇杆和正在烹饪时不显示；设置可重看。
- 481/481 Node 测试通过，Vite 构建与单文件离线包生成通过。80个相同种子的第2天自动营业对照（原料各80份、三道初始菜、无雇员、相同事件处理）：原始工艺销量8.3625→8.3625、收入153.45→153.45；三道品质86且使用已定义工艺时销量8.3625→8.3625、收入153.575→212.1125、利润102→160.5375。此场景供货充足、客群与菜单固定，不能推出长线利润或高价菜不掉单。
- 本地Chrome可执行文件缺失；PR #70 的独立GitHub Actions已用真实Chrome验证320/375/390首页布局、阶段引导按钮、雇员动画、旧存档和离线包，并保存四张截图。iPhone/Android玩家体验与Pages部署仍须另行确认。
