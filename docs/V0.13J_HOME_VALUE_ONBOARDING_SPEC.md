# v0.13-J · 活的厨房、工艺价值与第一日引导

状态：已确认待实现（玩家 2026-10-16 完整重开存档反馈）。本稿先于功能代码入仓；实现与验收记录随后回写。

## 玩家体验

1. 开店前仍使用当前真实餐馆 Canvas。空店时同一比例的主厨和**已雇佣**员工做准备工作，沿现有可走通道短距离走动、停留、说两句简短闲聊；未雇佣角色不得出现。厨房炉火、蒸汽和小动作持续运动。背景生活动画不能产生订单、收入、库存、经验或虚构顾客，也不占触控层；营业时继续以真实服务状态绘制。
2. 菜谱的售价显示清晰的工艺差别。保持菜谱基础价，配对工艺的定制加价，再以品质 80–84 / 85–89 / 90+ 分别加 2 / 5 / 7 金币；72–79 不加价。低价基础菜的高品质收益可感知，但预算敏感的食客仍可能拒单。工艺的专属耗时和客群适配继续生效；不要给所有“爆炒”等风味词叠加通用 Buff。研发结算、图鉴、菜单、订单快照、隐藏菜和营业账本读同一 `recipeCraftSnapshot`。已开始的订单价格绝不因后来切换工艺而变。
3. 全新存档第 1 天给出简短、可跳过的逐步引导：主页认识循环与采购/出门，路线选采集或狩猎，回店研发可选择尝试或先用现有菜，菜单上架后备餐、营业与结算。仅提示当前可执行的动作，不强制学习、探索或开锅；首轮结束后不再弹出。旧存档不因缺少引导字段被判作新玩家。设置可重看引导，跳过不改游戏进度。

## 实现与边界

- 首页动画读 `game.crew`、`game.kitchen` 和餐厅坐标；不创建第二个营业模拟。员工闲聊频率低、同屏至多一个气泡，短屏不遮主按钮；减少动态效果设置下保留静态人物和厨房。
- 价格只改变**未来**订单快照；旧订单与日报按原记录结算，存档 schema/key 沿用。质量加价不修改菜谱基础价、材料成本、制作时间、采购、评级目标或顾客预算。需要跑实际订单对照，监测销量与利润，不把价格上涨直接等同利润上涨。
- 引导状态单独持久化在既有存档对象；新存档明确初始化，旧存档不补发。页内一条提示与按钮，不盖住摇杆、研究投料、餐厅动作区。阶段跳转后引导自动跟随；关闭后可从设置重开。
- 验收：320/375/390 竖屏和矮屏可点；新/旧存档、跳过/重看、离线包；价格等级、工艺差别、订单冻结、旧订单、隐藏菜倍率；首页未雇佣/已雇佣/第三厨位三种人物状态。iPhone 和 Android 主观体验由玩家验收。
