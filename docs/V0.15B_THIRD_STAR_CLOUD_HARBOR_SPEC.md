# v0.15-B · 第三星与首扇云港传送门一体交付规格

**状态**：实现前设计；本页与[三星规格](V0.15A_THIRD_STAR_FEAST_SPEC.md)合用。基线 v0.14.0-alpha.5。玩家 2026-10-19 明确要求三星和传送门一起做。两项不得分开发给玩家。

## 玩家体验与发布门槛

第一章二星后次日可主动报名「万味会宴」；三位已有类型评鉴客占用当晚原有自然客位，真实到店、点菜、等待、做菜、付钱与评价。至少两席真实成交且满意、当晚实际成交和利润达到校准门槛才获得三星。失败保留所有营业账本，次日可重试。成功后在日结/次日预告出现可操作的「云港浮岛」门；当晚报告不能留下空入口。实现必须沿用服务订单快照和唯一账本 `chapter-hearth-star-3`，恢复旧存档不重抽客人或重复授星。

进入门开启**新章节**，不是二周目或删除原存档。原食堂、三颗星、菜谱、员工等级和已购升级永久保留；玩家在预告时可往返。无离线收入。首次前往选择一位已雇员工与一种已有 Lv2 厨具专长随行，作为云港开局资源；没有 Lv2 时普通厨具可进入。旧世界可继续营业，云港当地从基础桌位/厨位、启动资金和有限库存经营。两地营业中的快照不得切换；未完成的野外行程也不得跨章切换。章节本地金币/库存/厨房/菜单/市场/天数/星章各自存储，菜谱知识与员工经验共享；同一营业只结算当前章。现有全店同类厨具共享升级需在章节本地厨房数据中体现，不能假装存在可带走的某个物理 Lv2 炉位。

## 云港首个完整闭环

世界主题是漂浮群岛间的港口食堂。港船班次提前公开，平日与停泊夜有不同真实客流和口味需求；一次不超过现有三波营业。新地图的风道/乱流是可见的走位和风险差异，玩家可走采集或狩猎路线。第一版至少两种真实新普通材料（例如云谷米、雷羽蛋）、一类当地怪与两类新客；其余至少两种新普通食材、首领材料与独立分支可分批在同一发布前补齐。正式目标是 4–5 种当地常见材料、1 种稀有材料、5–7 道精选菜，保留 2–3 种旧食材供应。新食材确实从当地采集/战斗或当地市场取得，撤离才入当地仓库；新菜需真实研发、上架、扣料、制作、成交、入账。旧菜因材料和新客偏好自然受到限制，不靠隐藏禁用。

当地「云汽蒸笼」在开店初期经探索所得部件解锁并付费装配。它必须改变研发操作/火候、厨房工位覆盖和客群需求；如果研发互动尚未可用，不把一组仅换标签的蒸菜当作已经实现。蒸笼暂不对应新探索武器。每章至少一项新经营取舍：已预告的停泊夜值得提前备料，但缺料或拥堵会损失真实订单。首门最低可玩验收：从满星进入门，完成一次当地探索并撤离、研发一道云港菜、上架、让当地客人真实点菜并完成日结。

## 内容与经济边界

当前 `src/data.js` 对八种基础食材生成全部 2/3 材料组合。云港新材料不得直接加入该全局组合池；仅手工登记当地精选菜和少量有明确用途的跨章菜，避免配方数量爆炸。当地普通材料市场同样有可见库存和价格，稀有材料不直接售卖。章节资金和材料不能复制：进入/返回只是保存和恢复各地状态；有限旅费或携带材料应走明确的、唯一账本交易。原仓库和金币保留，不得一键搬空到云港并消除当地供料策略。两章共享图鉴时需按真实到店/真实发现登记，不补发虚构熟客关系。

云港后续也有独立的章节星章：第一阶段本地菜成立、第二阶段停泊夜供需、第三阶段离港宴。首个发布至少展示真实已可玩的初段目标；未开发的后续门不可点击或冒充奖励。

## 验收与文档

1. 第三星采用真实早期进度而非 P1 双星起步 21 日充分菜谱样本校准阈值；同种子双炉/三炉、无烤架、低库存、失败重试与重复日结核验，且真实玩家约第 10–15 日可尝试。
2. 云港从真实两星旧档、三星刚通过、全新存档分别核验；各章切换后金币、库存、菜单、员工、星章与未完成快照正确。原世界继续可玩。
3. 新地图与怪、材料、蒸笼、菜谱、两类顾客、市场和订单使用真实引擎。至少一条完整探索→研发→营业自动/浏览器回归；320/375/390px 和独立离线包验收。性能与中文字形真机反馈单列。
4. 实现 PR 引用本规格，回填最终数值、实际内容及未达项目，更新 `PROJECT_STATE`/`ROADMAP`；三星与门同一发布，任何未完成环节不能在发布记录中宣称可玩。
