# v0.10 设计讨论稿：稀有隐藏菜单 × 特殊食客 × 熟客关系

**状态：方向修订中；隐藏菜单定义已由用户澄清，准入机制和具体参数未最终确认；尚未开发。**
**基线：** 2026-10-13 GitHub main v0.9.5，编码前请重新读取源码。
**本稿替代原 v0.10 假设：** “招牌菜”不是普通三菜中指定一款加推广 Buff，而是**在三道日常菜之外再增加一个独立、隐藏、限量、高价的稀有料理槽位**。Boss 食材先行，未来可扩展为其他稀有食材来源。

## 一、玩家主循环（方向确认）

击败 Boss / 其他来源获得珍稀材料 → 研发稀有菜及工艺 → 在独立隐藏槽选择今日限定料理和供应份数 → 合资格食客到店并可能点单 → 共享原餐馆厨具制作、送餐、落桌消费与真实评价 → 精品利润、特殊食客关系与餐馆名声 → 解锁更丰富的高端需求。

三道常规菜单不变；隐藏菜不是第四道全体顾客可选的普通菜单，不强制玩家每天备好珍稀材料，未选择时按原营业逻辑运行。

## 二、已有可用内容（当前源码事实）

- `src/data.js` 已有 Boss 掉落材料 `mushroom_heart`（菌王孢心）和 `ember_pepper`（熔心椒晶）；分别为 Boss 专属，不在随机市场销售。
- `mushroom_heart_wok` 菌心爆香 35 金币、`mushroom_heart_pot` 菌王吐息浓汤 36 金币、`ember_pepper_wok` 熔心喷火牛 46 金币、`ember_pepper_pot` 火山焖鸡 38 金币。这是现有基础菜价，**不是隐藏售价**。
- 三道日常菜目前在 `s.menu`，`canMenu` 固定 3 道，`selectArrivalDish` 只从常规三菜选择，`serviceDayPlan` 生成真实客流；`recipeCraftSnapshot` 保留玩家工艺/材料/价格，订单使用现有厨房与 `sale-orderId` 唯一交易。**目前没有隐藏槽、熟客身份或 VIP 消费能力。**

## 三、特殊顾客资格（推荐双通道，待确认）

资格与购买意愿分开，**有资格 ≠ 必定下单**：

1. **鉴味师通道**：现有幽灵鉴味师天然有查看隐藏菜的资格。这让玩家初期赢得 Boss 食材后也有高端经营出口。
2. **熟客通道**：新增真正跨天记忆的具名熟客（利用既有矮人、菌帽、史莱姆客群），建议达到至少两次真实满意用餐后可受邀查看隐藏菜；关系基于真实已消费并完成评价的订单，不能使用玩家全局声望自动捏造熟客。
3. 普通过路顾客没有资格；只因有钱或站在门口不解锁隐藏菜。满足资格还须依据风味、品质与精品支付意愿决定是否点单。
4. **到店机会保障（待确认）**：建议上架有料的隐藏菜后，玩家有可见的“可能来访的鉴味师/熟客”；为防稀有菜无限滞销，可从当天原定潜在顾客中保障最多一位具有资格的来客，**不保证他购买**，也不直接额外变出一位客人。这个保障是否开启还需用户决定。

## 四、今日供应和价格（提议值，尚未定案）

- 初版一个独立隐藏菜位，每日预计允许玩家设置 **1–2 份**；供应量不得超出真实持有材料可制作的份数。
- 初始试测隐藏售价为**基础价的约 1.6–1.9 倍**，而不是直接为所有菜涨价。须测算利润、食材稀缺与厨位产能。
- 现有 `customerFit` 将超出 `CUSTOMERS[segment].budget` 的差额乘 4 扣分，鉴味师预算 50；如果稀有菜卖 60–90 而直接走普通预算，可能无法接单。新机制需要合资格贵客特有的**精品消费能力 / 愿付价格**，不能改动所有普通客群预算。
- 材料与仓库共享。**避免一份 Boss 食材既被普通菜占用，又卖给限定订单**：设计实际可用数/配额保留，明确在预制或厨房实际开始生产时经原 `consume` 扣除，不可任意二次扣款。超出限量的客人自动回到日常三菜选择，而不是凭空增加库存。
- 现有 Boss 初遇有多份奖励，后续每次可得少量；保持探索稀缺与真实限量价值。未来稀有渠道应由食材 `acquisitionPolicy` 扩展，不限定“Boss 才算高级菜”。

## 五、和现有流程连接

- **菜单页**：在 3 道普通菜后另设一个低调“隐藏菜单”入口；内部允许选已研发稀有食谱、限定数量、查看售价与库存。原菜单页“今晚三道招牌菜”文案建议改成“今日菜单”，避免概念冲突。
- **营业准备**：沿用当前 v0.9.5 的食材估算，额外提示珍稀菜已承诺份数与对应库存风险；不得叠第二个大面板。合格来客预告可选，但不要不真实的“必有 VIP 下单”提示。
- **营业**：必须走 `createService` 生成的订单、真实占座和等位、`selectArrivalDish` 点单、WOK/POT 真实队列、员工/主角实际送餐和既有幂等 `sale-orderId`。
- **日结**：只显示实际售出的隐藏菜份数、真实收入、到访合格食客与评价；失败、超时、未成交不得计入销量和熟客好感。正常经济账不新增独立 VIP 钱包。
- **存档**：新增 `premiumMenu` / `guestRelationships` 等可迁移字段，老存档仍可读；保存与加载、当天续营业不会重复预留、扣料、付款、关系成长。
- **世界观与 UI**：复用现有程序像素食客。奇幻靠行为、食材与对白，内部场所命名**不要强加在界面上**。320px 窄屏、iPhone Safari 操作可达与色彩对比度需真机验收。

## 六、经营系统分层

**隐藏菜单**是高价值餐饮渠道，**熟客关系**是顾客长期资产，**口碑**是交易后的真实反馈。v0.10 优先证明珍稀菜能吸引和满足真实特别食客并带来利润，而不是给普通菜一个营销图标。

**v0.10 MVP 候选**：独立隐藏槽、现有四道 Boss 稀有食谱、每日限量、双通道顾客准入、必要的跨天熟客身份、同一订单与账本、简短日结与测试。
**后续版本**：熟客朋友推荐、特殊预约活动、神秘商人专供新材料、正式美术资源、多桌多厨位。无需把所有普通营销系统强塞进 v0.10。

## 七、尚需用户拍板（不要把提案写成定案）

1. **准入**：双通道（鉴味师天生可点 + 关系达标熟客可点）是否确认？
2. **机会**：每天设置有货隐藏菜单时，是否保障原有客流中至少有一位合格来客（但仍可能不买）？
3. **限量**：独立 1 槽、每日 1–2 份是否合适？
4. **定价**：建议 1.6–1.9 倍基础价，并给合格客人专属消费意愿，需数值回归。
5. **熟客阈值**：建议至少 2 次真实满意用餐；人物关系档案如何保持简洁？
6. **供货保护**：珍稀菜配料的份数承诺与普通菜共享食材时采用何种占用/预制规则？

**决策日志：** 2026-10-13，用户纠正此前 v0.10 “从三道菜挑一款普通招牌”的误解，定义为 Boss/其他稀有食材制作的**独立限量高价隐藏菜**；顾客解锁条件仍在讨论中。
