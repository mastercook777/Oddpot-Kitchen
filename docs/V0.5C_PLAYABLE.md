# v0.5C | 餐厅舞台与每日经营变化（可玩原型）

## 用户反馈对应
1. 主厨比其他人过大 → 餐厅全角色使用相同 `DINER_ACTOR_SCALE=1.13` 的原创小像素人。
2. 单人桌重叠 → 两桌各设左/右座，一晚可容纳最多四个同时活跃订单，独立选中与耐心计时。
3. 投菜中途桌上先有菜 → 飞行 1.12s，按 `served` 事件唯一触发；落点后绘制实体菜，无无限重复。
4. 跑堂穿过顾客 → 指定过道动线，跑堂仅到服务通道、客人绕开桌心入座。
5. 每天 7 客人、事件固定 → 夜间 6–11 位客人，依当天种子产生偏好主题和两波事件。可复现，不会读 UI 即重抽。
6. 经营目标模糊 → 每晚随机种子任务：上菜份数、平均满意、双人桌服务量、辣味销量；达标口碑 +2，交易唯一。

## 非范围
- 料理研发大规模重构留到 v0.6，雇员与厨房数值成长保持 v0.5B。
- 无正式装修/扩建、员工排班、顾客关系值或后端服务器。
- 未引入更多硬性强制等待，三波营业和第三日厨王沿用原结算规则。

## 质量门槛与待验证
- `npm test`: 75 项规则测试通过（67 旧版 + 8 v0.5C）。
- 关键不变量：一座一单、全队同尺寸、盘子飞行落桌同步、事件可复现、奖励不重复、第三日晚餐只有一次结算。
- 目前环境浏览器访问被限制，无法宣称真实浏览器端 HUD 或 iPhone Safari 已通过；必须真实手机检验双人座位遮挡、投菜动线、拥堵，以及客流目标是否真有决策价值。
