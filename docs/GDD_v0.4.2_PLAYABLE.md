# 《怪味食堂》v0.4.2｜玩法深化与稳定性修复

状态：2026-10-10 · 已实现开发切片，**未经过用户真机体验验收**。

## 用户反馈驱动的变更

1. v0.4.1 的像素小人方向被认可，继续使用程序绘制的小型像素角色，不引入正式素材；餐馆画面缩远以容纳角色与小 HUD。
2. 采集动作玩法基本成立，扩展到两个真实不同布局、敌人构成、生态特征与危险的地图：晨露森林与热泉峡谷；两地各提供安全采集线/高风险线。每日仍最多探索一次，地图之间可自由选择。
3. 背包从默认六格升到七格（45金币）、八格（75金币），永久保留；每格一种材料且最多三份。路线添加可选拾取点，以形成容量权衡；满包可主动丢弃一整格，绝不能动餐馆已有库存。
4. 备餐按钮因为层叠 hitmap/canvas 可能被遮挡，改为独立高层级触控卡；小屏面板内部滚动而非整页滚动。
5. 营业浮窗与角色遮挡：简化状态栏和餐桌订单标签、缩小场景主体、经营决策卡移到下方。
6. 修复入座/出餐循环播放：`arrivalProgress` 与 `servingProgress` 是无循环、单调变化且有明确终点的纯进度函数。视觉插值读取 `service.time`，暂停时不推进；Canvas 仍持续重绘，但静止画面像素保持一致。

## 保留的不变条件

- 研发炒锅、12 道菜、菜单三槽、独立 WOK/POT、三波营业、特殊第三晚均未改写。
- 探索只在 `settleField` 时结算一次库存；背包丢弃不应修改仓库；采购、备菜、升级按唯一事务扣款。
- 不用战斗升级替代研发/经营的策略循环。
- 老 v0.4/v0.4.1 存档按 `bagSlots ??= 6`、`field.capacity ??= bagSlots` 迁移，继续保留已研发菜与永久设施。

## 自动验收

- Node 47/47 tests PASS：两张布局差异、不同敌人配置、目标食材来源、容量升级价格/唯一交易/跨天保留、满包弃置无副作用、一次性动画的单调性、原先 39 项玩法回归。
- Chromium 390×844 / 375×667 / 320×568：每个备餐选项均实际点击成功、可开门营业，无脚本错误/整页滚动。
- 浏览器暂停 800ms Canvas 前后完全一致；升级 6→7→8 与背包丢弃实际操作通过。

## 后续真实验证和限制

- iPhone Safari 实际触控、性能和不同帧率下的事件手感等待用户验证。
- 新地图在首版仍是可重玩的地图模板，非完整开放世界；高风险事件、怪物种类与视觉特效还有扩展空间。
- 背包八格在当前八种材料池里主要提供“保留所有品类”的便利，数值平衡后续调整。
- 画面仍以程序像素美术为临时视觉资产，事件和餐厅空间可继续打磨。
