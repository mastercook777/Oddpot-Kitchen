## 视觉目标与结构

**定位**：「温和草绿作为舞台，暖金食材作为交互焦点，深轮廓像素人物/树石作为主体」；不追求更密的纹理，不将草地改成炫目的战斗背景。

| 层级 | 实际交付 | 关键要求 |
| --- | --- | --- |
| 地表 | 16px 草 Tile ×4 种变体，低饱和三段绿 | 原单 Tile 18 个散点改成 4–6 组最多，明暗减少；避免满屏盐胡椒噪点 |
| 道路 | BFS 安全主路 + 关键采集点/事件短支路 | 必须基于实际走通的碰撞地图，不画通往墙的伪道路；用同一土色色板与格边衔接 |
| 地貌 | 实体树×2、岩石×1、地面草簇与花 | 16×16/24×30 原生像素格，稀疏非碰撞装饰；碰撞仅取现有 `f.obstacles` |
| 信息 | 食材图标、目标框、旅人问号、危险标记 | 有真实资源才画拾取物；目标/旅人高对比，不把装饰草当作食材 |
| 生物 | 沿用既有动物像素轮廓，野外 HP/危险提示归整为方角像素标示 | 不改 HP、伤害、AI、掉落或敌人密度；B2 生态怪群属于单独后续任务 |
| 镜头与遮挡 | 沿用 `fieldCamera`，实装树冠前后遮挡 | 按实体纵向底边排序；主体可见，树冠有纵深；不动位置和碰撞坐标 |
| 特效 | 野外攻击提示和基础弹丸以实心像素块替代圆形装饰 | 命中判定、技能、实际 projectile 物理不变 |
| 性能 | Offscreen Canvas 精灵缓存 + 地表计划一次性缓存 | 不在每个动画帧重新 BFS 地图、生成 Tile，Safari DPR2 性能不回退 |

## 可测试的地图拓扑

- 保留 `expandFieldMap` 的 **12×16** 布局和物理障碍，不篡改种子、入口、Boss 通路、敌人出生点。
- `fieldTilePath` 是唯一判定标准，先画入口→当轮 target 主路，依种子选 ≤2 条从入口到真实采集点的支路，如果有一次性事件则事件方向优先。
- 所有可交互物/障碍基于实体节点绘制，无虚假可互动图标；路面不覆盖陷阱或树。
- 装饰点分布显著减少，靠近主要通路、交互物以及人物出生点保持干净。
- 旧 9×11 存档禁用新 renderer；非 `herb_path` 仍走原扩展场景渲染。

## 精确实施范围

**改动**：
1. `src/field_pixel_herb_v011c.js`：收敛色板、减少 grass noise、道路/小径分支、地表稀疏装饰和一次预计算、互动/UI sprites、岩石和树遮挡、战斗像素提示。
2. `src/scenes_v04.js`：只在 `isHerbPixelSlice` 成立时启用像素敌人/提示/弹丸与分层遮挡，其余剧情/地区老逻辑完全保持。
3. `art-preview.html`：可查看真实引擎画布的「采集、入口、原版对比」，不用依赖三方 HTML 代理来审美。
4. `tests/v011d_herb_map_art.test.js`：色板与纹理密度、装饰/路径和障碍隔离、节点/交互数据稳定、敌人可视化与旧图隔离，复用全套 v0.11 测试。
5. `scripts/build-standalone.py` + `standalone.html`：新代码在离线版可运行；Github Actions 全绿/浏览器产物检查。

**不会做**：地图怪物数量上限调整、新怪 AI、新食材经济、料理研发、餐馆美术替换。这些归 B2/C 与未来餐馆迭代，不能在此次“草地美术落地”偷渡进去。

## 本轮通过条件

1. 草地肉眼柔和、地表不再抢食材视觉焦点；四个 grass tile 的散点密度小于原版 1/2。
2. 从初始入口到目标至少一条真实安全路；关键支线可达；资源/旅人/敌人数量完全等于游戏状态；不会生成可拾取的假装饰。
3. 固定尺寸手机渲染和自包含离线包都可编译，**334+ 项自动回归绿灯**；新增针对种子、异常节点与本地绘制缓存的测试。
4. `main` 不变；Draft PR 限于上述独立分支。只有用户认可草地完整画面后才能决定是否合并。
5. iPhone 实际触摸/帧率是独立人工验收，不可用 CI 绿灯或浏览器截图代替。
