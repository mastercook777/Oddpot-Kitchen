## 意图与决策

玩家同意“生态地区决定食材来源”，认为任意选“今日目标食材”鸡肋，希望消除安全/危险即奖励高低的单轴提示。已确认方向：
- 对外叫 **采集路线 / 狩猎路线**（后台 `safe/risk` 枚举保持存档与兼容性）；这表示收益类型而非纯难易，也不遮蔽狩猎战斗、Boss 和晕倒风险。
- **采集路线**：蔬菜、菌类、调味原料是优点，少量弱怪；真实地图上的集中采集才有产出。**狩猎路线**：牛肉、鸡肉与食材怪掉落机会、Boss 稀有材料，需真实击败并靠近拾取；不提供免费假掉落，仍有风险和战斗成本。
- **两边各有重要的菜谱供应价值**：比较无战斗可得食材、全打完的潜在战利品、袋位限制下可带回材料构成（蔬菜/香辛菌类/肉类）。不要简单确保猎杀路线总数量总是最多、或把采集路线做成纯低级副本。普通材料在当前市场可偶然买到；定向探索填的是四款随机上架留下的结构缺口。
- **起始“点选任意一种食材→无论什么生态首图凭空生成×2”改为只看区域生态**。现行生成器仍保留每段可达的`key:'target'`核心采集点保证推进，但 `id` 由对应生态主产物决定，不再凭准备页面任意指定。旧在途 field snapshot 一律不重新生成/重抽。旧 selectedTarget 字段只供兼容，初始 UI 移除其选择。新的生态跑图不出现误导性的「今日目标」；保留旧档原提示。
- 保留**每次3张实体地图，段1固定、段2/3各二选一**。修复当前两地各1条“从未进入的 zoneId”（`forest_secret`/`spring_market`），并避免段2、段3使用完全相同的 Boss 地区；世界仍为森林/热泉两大区、8类生态与14个区域Id，不凭空造第九套地貌或新Boss。
- 分支卡展示生态特色的**主要产物/敌人/当前阶段的资源偏向**。有限但明确的采集/狩猎决策，不展示假的精确掉率，也不堆叠长版故事/多层浮窗。
- 不修改经济采购6–10、Boss单次奖励、商人/旅人一次性交易、菜单与星章，不调整角色/攻击手感。背包8格、3份一叠、统一掉落拾取/唯一 settleField ledger 均原样保留。

## 必须先算什么

- 根据实际 `generateBiomeMap`、`enterField/chooseFieldBranch`、`startActionField` 和战斗怪种类/实际死亡掉落映射，遍历固定多 seed，比较八生态正常采集点的数量、颜色分类、野生怪潜在掉落及各个可选分支的重复生态；区分“静态可采”、“击败全部普通敌人情况下可采”的上限和真实玩家有效获得的下界。
- 在相同种子和“尽量拾取”的收获政策下，使用正式 `addFieldBag` 检验保留一格稀有奖励、8格×3叠的背包压力；有合理的非支配选择：采集路径更多可采蔬菜、狩猎路径战斗潜在肉类更多，猎杀不必总是原料总量最高。
- 不把“怪物存在”当作已经击杀/获得战利品，也不把稀有掉落或探索积分直接加金币。经济端的21天结论作为需求权重；后续需要另跑真正手感与营业收入对照。

## 具体实现范围

1. 以生态权威`STYLE.resources`和`primary`生成采集点。调整资源分布与小地图采集密度，让采集植物/根茎有机会超过狩猎路线的无战斗资源量；战斗专属牛/鸡获取要通过真实死亡掉落，稀有仍来自Boss。
2. 前两段利用更多不同的区域与生态，并确保所有路由自然向第3段收束：森林采集可走菜圃或菌沼，热泉采集可走晶池或裂隙周边植物；森林狩猎主攻牛肉/菌怪，热泉狩猎主攻椒怪/蒸汽蟹/野牛。收尾为深层采集或Boss挑战二选一（做了战斗承诺者只能进入对应Boss终局）。
3. 前端路线/分支文字真实反映该 map 可能获得的资源与风险，移除“今日目标原料”滚动条；并给当前菜单短缺的**只读提醒**作为供给方向，不改变探索产出。
4. 对新生成地图做反复seed/3段/存档/采集/敌人战利/旧 schema4 在途兼容验证；不要因此改已开始的 run 图。
5. 更新版本号与 index/script cache/可离线 standalone；给 CI 一份可重跑多 seed 经济资源统计，不允许只靠纯 UI 文案验收。

## 安全与质量门槛

- 新`field.targetMode='ecology'`隔离原 `dailyTarget` 旧存档；`fieldHarvestTargetSuffix` 的旧逻辑不被破坏。不存在跨段无限补领食材和同天重复结算。
- “危险”一词允许用于**明确的生命受损/Boss警告**，不作为主路线的标签和判断哪边更好的一维轴。
- 任何场景路线都会在第三段完成并可撤退，怪物和资源点可达，存档恢复后的路线选项不重抽，前端玩法名称与后台枚举分离，专项Chrome 320/375/390和离线包再验收。
- CI通过≠玩家实际iPhone体验认可；报告必须列明模拟假设，不伪称真实战斗全部被玩家击杀。
