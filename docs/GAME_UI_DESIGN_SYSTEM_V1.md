# Oddpot Game UI Design System v1.0 · Z2e-A
2026-11-26。玩家批准重新审视整体网页感，要求文档+可交互工坊一起做。Z3暂停，Z2e先验证视觉语法，再迁移正式系统。基线Z2d3 PR145已合并17/17；Z2d3a缓存修复PR146仍独立复验。本规格覆盖未来设计，非已实装声明。

## 1. 产品原则
竖屏、单手、轻度经营+料理研发+外出探索。玩家在奇幻餐厅内行动，而不是填写表单。主空间是世界、UI是工具。借鉴昭和食堂的餐厅常驻、Food Truck Pup的图标与窗口、Cat Snack Bar的购买反馈、Postknight 2的角色装备槽、弓箭传说的结果仪式、洋果子店ROSE 2的料理收藏。前轮参考为公开截图与产品资料，非安装试玩结论；仅借交互结构，不复制素材或具体视觉。现有Hearthcraft与主角冻结，继续使用原生HTML/CSS/Canvas/Three，不更换引擎。

## 2. 分层与组件
L0 世界舞台：默认占完整游戏容器，非上半屏插图。HUD闭合时至少75%画面无遮挡；优先真实场景物件，非虚构系统列表。L1 HUD：金币、日数、星章、少量图标入口；浮在画面边缘；44px最小命中、8px间隔、安全区。L2 Hotspot：实际物件或新增物件所在坐标，箭头/提示标识当前可执行、金币不足但进度已达亦可查看价格；未到前置条件不显示；已满级移除。L3 Window：独立居中有厚边框、标题牌、关闭钮、有限内容、主操作，背景降亮但可识别；关闭回原场景；同层只一个，Tab隔离，Escape关闭非必选窗口。L4 Result：大图标、结果数字、里程碑、确认，结果与详细账本分层。Slot/Grid：物品格4列左右、图标数量、选中外框、点击才展属性；收藏可分页或内部滚动，核心操作禁止要求纵向滚动。
视觉tokens：墨绿#20382c、深边#523720、黄铜#c79b60、羊皮#efdbb0、墨色#473321、主按钮暖金、成功青绿、告警赤色。以厚薄不同的描边、下沿实体阴影、标题牌、切角/圆角6–12px形成可按的游戏控件；复用已有z2a2彩色图标和像素食材。禁用emoji当正式图标。正常说明>=12px、操作>=14px；非装饰SVG有替代文字；减少动态模式下不依赖动画。
交互：按下反馈、成功后真实金币变化与物件变化；失败解释不扣钱。窗口不修改模拟时间，保持正式暂停/订单规则；工坊无正式存档。正式接入需遵守原摇杆与触控契约。

## 3. 各模块迁移契约
|模块|默认交互|次级窗口|
|---|---|---|
|清晨|全屏餐厅热点与门口|库存、预报、员工|
|整备|地图/角色/厨具槽|路线详情|
|探索|保持现有实时场景|背包、奇遇|
|研发|真实灶台、投放槽|食材格与工艺|
|菜单|三张菜单槽，点格替换|已学菜谱网格|
|备餐|实际厨位热点、备餐图标|厨具切换与预制|
|营业|保持实时控制与订单|经营账本|
|结算|同餐厅上的Result窗口，核心数字|详细经营账本|
|成长|真实场景上可达升级热点|单项确认、当前近邻目标|
|库存/图鉴|图标格与选中详情|分类/分页|
|员工|角色槽位与当前职责|角色详情|
日程阶段仍由engine驱动。页面结构可以消失但玩法不能消失。先验证结算→星章→成长再迁移，不提前改变真实经济或阶段解锁条件。

## 4. 工坊交付
独立 game-ui-workshop.html，默认进入结算结果演示，背后复用现有餐厅真实3D渲染器，资源失败时使用真实2D fallback并标明。早期/首星/进阶三个测试档位显式标注为演示，重置仅重置内存，绝不读写正式localStorage。结果数字/获得星章为演示夹具，不冒充真实经营成绩；升级使用原engine购买函数与价格、真实桌位/厨位布局变化，热点随进度显示、满级消失。默认不显示未到条件的全部内容，至多一个近期目标；购买确认以窗口呈现。库存与菜单格支持点选详情/替换（仅演示）；账本是次级窗口。设置窗口切换样本与重置。主流程：确认结算→若样本有里程碑则领取展示（无重复收益）→场景热点→确认购买→真实变化→完成返回下一日示意。无正式存档、无新增正式资产/价格/玩法。
## 5. 验收
320×568、375×667、390×844：默认全屏场景、结算/星章/升级/菜单/库存窗口不滚动、不裁切，次级账本允许内部滚动。购买前后金币差/桌数/满级隐藏/未达条件隐藏；早期无远期锁卡；可退回场景，键盘Tab/Escape，触控44px。真实WebGL与2D fallback分别验证，正式游戏旧档及CI不受影响；视觉玩家验收单列。若工坊还像网页，修改设计系统而非直接迁移正式页。下一步Z2e-B正式验证切片，仅在玩家认可方向后推进；Z2e-C逐步迁移，Z3暂缓。
