# v0.6.2 · 料理动画可见性与搅拌残影修复（2026-10-11）

## 玩家报告
- v0.6.2 烹饪过程中看不清、甚至完全看不到锅内情况；
- 上一版 v0.6.1 搅拌操作出现重影，希望同样排查和修复。

## 本轮处理
- **v0.6.2**：重做锅体及食材的显示架构。锅体使用独立 CSS 渐变/轮廓图层；已投入的食材用持久的 DOM 图标节点表示，实时更新每个节点的位置、倾斜与短暂弹起，而不是依赖每帧 Canvas emoji 文本。
- **v0.6.1**：同样改成持久 DOM 食材节点，每帧只修改变换位置。搅拌和颠勺不会不断叠加半透明图层或复制 emoji 文本。
- 原 Canvas 保留为**透明的手势命中层**，使手机端向上划颠勺、画圈搅拌等操作入口和原有逻辑保持不变。
- 锅底固定可见，食材节点有足够的字号和深色阴影；炒锅/深锅使用不同锅底外观。
- **不变更**下料顺序、熟度/夹生、菜谱匹配、工艺词条、失败不可保存、独立实验存档、经营主线。

## 回归验证
- `tests/v062_visual.test.js`：从实际发布的两份 HTML 加载脚本，在 DOM 模拟层验证：
  - 有锅体图层与食材图层；
  - 首次投入两种食材后显示恰好两个食材；
  - 连续调用 45 帧绘制，不会重复创建节点；
  - 执行炒锅动作及旧版搅拌后仍只保留原来的两个节点；
  - 重开实验，旧食材会从图层清除；
  - 深锅执行轻搅、收汁后维持两种食材可见并切换深锅样式。
- 现有 `npm test` 在 GitHub Actions 中通过（修复提交 `d5090053`）。
- **限制**：目前的 Node 模拟和 GitHub Actions 不能证明真实 iPhone Safari 的视觉显示完全正常。需要玩家在真实手机上核验锅内食材是否显示、拖动操作有无残影，并特别看 320px 窄屏。
