# v0.13-D · 每日采购修复、二星双夜评鉴、蔬食新客 · 验证与开发合同（2026-10-15）

**状态：待实施，本稿先于代码提交。** 当前main v0.13.0-alpha.3；已获玩家确认站位修复与二星经营继续开发。基于已合并 [二星基础规格](V0.13C_SECOND_STAR_APPRAISAL_SPEC.md) 及 [ROADMAP](ROADMAP.md)。

## A. 真实问题审计（源码实证）
1. `src/data.js` 的 `SHOP_STAPLES` 实际只有鸡肉、蒜瓣、蘑菇、卷卷魔菜四项；`ensureDailyMarket` 每天从这四项抽3或4个。抽满4个后商品名单完全相同。默认种子20261009跨10个周期连续30天中16天四项完全相同。本质是候选池仅4、不是玩家感觉有误。
2. 八种初始普通食材为牛肉/鸡肉/喷火椒/蒜瓣/蘑菇/卷卷魔菜/洋葱/土豆；后四类的 `FIELD_ONLY` 只影响是否可以在店里采购，不妨碍它们是普通非稀有食材。玩家要求**每日随机挑4种普通食材并限量购买**，即应建立八种可采购轮换候选，但不改变探索原材料产出方式。Boss/商人/花蜜依旧永远不售。
3. 5类老食客口味：矮人辣肉；菌帽温和菌香；史莱姆清爽菌香鲜；幽灵辣香；星砂清爽甜香菌香。没有任何人特偏「蔬食」。已有丰收三拼、蔬菜炒菜等真实可用菜，缺的主要是明确的蔬食客群和获二星后菜单Build选择。

## B. 市场修复合同
- 从八种基本普通食材精确抽取 **4种**。每天`seed/cycle/day`决定四项，重进同一天或读档不得重抽；换天才重新抽。随机数须检验每日多样性，不可由于LCG低位周期而固定组合。保持结构 `market.goods`、唯一purchase ledger及每日数量耗尽逻辑。
- 保留探索定位：原四种 `SHOP_STAPLE` 上架 6–9 份；原四种 `FIELD_ONLY` 若被抽中也有有限采购，但每种只有 **2–4份**，单价更高（候选原估值×1.5–1.9倍），因此不能以每日市场替代探索稳定供料。保留全部`ING.acquisitionPolicy`：FIELD_ONLY依旧出现在探索中，`SHOP_STAPLES`仍表示原平价常驻类，新增明确的轮换基础池属性用于可售判断。
- 保留旧`schema2`**已生成的当天**供货名单/剩余量/价格，即使只有3种商品也不直接重抽；从下一天开始进入`schema3`轮换。无市场存档当天走新规则。资金/库存/ledger交易一律不重置。普通游戏`purchase`按今天已上架且属于8种白名单商品判断，稀有食材不能通过伪造价格购买。
- 不更改探索真实奖励、稀有获取、背包、餐厅利润公式或料理配方。

## C. 二星经营（承接既有规格）
- 获首星且四桌，累计第七个营业日后，在开门前自愿申请二星；跨两次**真实**营业，第1夜「繁忙之夜」评分订单上菜、门外等位流失和经营利润；第2夜「拿手之夜」评分真实满意/品质、上桌菜谱多样性与真实帮厨/跑堂参与。两夜可以间隔；失败仅重考当前阶段，不回滚首星/日常收入/经验。
- 第一夜建议权重45%实上菜覆盖、25%等位体验、30%盈利健康；第二夜40%满意、25%工艺、20%真实菜谱种数、15%真实团队服务。分数门槛初稿70/72，经首轮80种子双炉97%和三炉100%过关数据重新调到70/84，最低真实成交与上菜覆盖额外门槛，必须通过定量模拟检验至少多种人员/菜单可达。无排队时队列项不扣分；不雇工不自动阻断第二夜成功。
- `chapterProgress.secondAppraisal` 为老存档可选迁移子状态；原schema4保留。班次冻结 `secondStarStage`，日终使用原唯一事件/订单账本并用独立一次性 ledger 键 `chapter-hearth-star-2` 授星，旧正在营业不注入评鉴；工资/库存/订单不可重复结算。
- 二星奖励应当天即可玩：一项真实菜单定位宣传选项「田园品鉴」，需花真实金币才能在原同一订单系统增加少量蔬食客（新客第二星后可自然到店）；做对菜可能盈利，乱宣传可能亏。继承开门预付、唯一流水、真实厨房订单与等位系统。

## D. 蔬食食客
- 新客「芽角鹿客」解锁条件=二星已获，偏好「蔬食 / 清爽 / 温和」、预算中档、耐心中等；从**已有自然客位**中至少替换1个，避免一次无条件大幅增客。后续付费「田园品鉴」可增加2名真实访客，不可免费凭空加销量。
- 明确给包含`cabbage/potato/onion`且不含`beef/chicken`的非稀有料理附「蔬食」标签（生成食谱也一致）；不能只看名称是否含“蔬”或把蘑菇鸡误归类。餐厅原口味打分机制消费同一recipe.tags字段。
- 新客独立像素形象（鹿角/嫩叶辨识）、按真实订单阶段有少量短对白、差评和图鉴解锁；仍使用原程序绘制，不启用新资产管线，沿用原客单/点单/座位/预算/评价/单次出餐流水。
