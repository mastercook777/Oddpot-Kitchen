# v0.13-A · 第三厨位 × 第二帮厨：一个完整的经营产能升级

日期：2026-10-15。状态：**用户明确同意直接落地；开发设计先行**。基线 v0.12.0-alpha.5。目标 v0.13.0-alpha.1。

## 决策变更
**第三厨位和新员工必须同时提供，不发布没有人干活的空设备。** 再开发烤架、烤叉前，先做第三个**独立物理工位**（中央封印炉）+ 第二名帮厨「小炭」的可购买**单次扩建套餐**。第3台暂配 WOK 或 POT，不引入第三种烹饪法、武器、食材或配方。烤架=下一阶段独立切片；水吧=更后期前厅设施且不必变成武器。不要丢弃第二星章规划，但先用此真实经营升级切片做数值验证，再定下一枚星章的阈值，避免直接强推更多客流。

## 可玩功能契约
- 第四桌和首枚星章均已获得才解锁「第三厨位＋小炭入职」同一购买动作（仅 upgrade 阶段，固定一次唯一账本交易；暂定**260金币**，价格以受控模拟为依据审查）；旧存档回填`kitchen.slots[2]`只在真实买下套餐后进行，不能免费长出设备、员工或工资。绝不删除已有双锅、工作餐、XP、存档账本和工作状态。
- 套餐购入当场：中央封印灶变真实炉，`kitchen.slots[2]={type:'WOK',level:1}`，`crew.helper2.hired=true`且`onDuty=true`，派往中厨位（index2）。由于升级阶段之后是开店前准备，必须从下一次开业开始生效；已经开始的营业保持`v.kitchenSnapshot`、`v.crew`的冻结数据。
- 第三条生产队列ID **CENTER**；左仍**WOK**、右仍**POT**（物理ID与类型分离，保持历史事件/报表兼容）；真实`v.stations.CENTER`与`stationStats.CENTER`可独立接单，按实际锅具类型处理相应菜单料理，可与原 WOK 并行处理，不能一次订单多次扣食材或多次销售。
- 小炭作为第二名真正帮厨：单独排班/工资/8与30实际工单XP晋升/员工餐/正常工位分配、独立头像与Live像素角色（既有helper像素语言的差异化服装）。预估薪资12/16/22；可在三厨位中分配阿火、小炭但同一厨位只能派一名帮厨（移动分配时显示阻止冲突或通过有效交换；初次默认阿火左、小炭中）。并且小炭在做实际料理时才获得相应XP，不能给闲置员工虚假成长。
- 没有主厨或帮厨在某炉值守时该炉**不推进制作**。玩家可接近中厨位临时接手；小炭与阿火分别操作其分配工位，不凭“解锁厨位”全场自动加速。烹饪消耗、出餐台、跑堂小芽和订单评价仍使用唯一现有链路。
- 原有`WOK`/`POT`升级、改装与探索武器仍可用；index2也有锅具选择和强化（价格可以暂与右厨位同级）。探索中的WOK/POT只有装备**类型**而非「每个物理工位各一个武器」，中央厨位不会自动多一把武器。
- UI：备餐可直观看到第三厨位当前配置、三处实际厨房负载；在升级页显示套餐价格及解锁状态。员工界面显示小炭并可配置排班/晋升/食物/中厨位，但没有未雇佣时单独付费招聘按钮（只有绑定套餐）。Lv1–3外观继续同源；Canvas人物小而清晰、不加大遮挡；320×568保持整页可滚。
- 真实日报：第三炉单数与工作秒、阿火/小炭各自真实工单、工资、XP；与旧日报统一账本。场景中央封印图形只在无第三炉时显示。
- 兼容：旧schema4无新增状态者保留历史两厨位；正在营业中的旧shift继续只按`v.kitchenSnapshot`长度执行；防止重新读取`s.kitchen`导致途中升级；存档迁移不改变既有字段、日内交易、经济；每家店最多一个套餐。
