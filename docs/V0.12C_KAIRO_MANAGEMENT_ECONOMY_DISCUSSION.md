# 《怪味食堂》v0.12-C · 开罗式经营成长：人工、培养、揽客与财务
**状态：研究与设计草案（待玩家讨论确认）；未开发、未调平衡、未发布。**
**撰写：2026-10-15；权威游戏基线：main v0.12.0-alpha.1 + 已合并的 v0.12-B 数值审计。**

## 0. 本轮玩家反馈

- 现在除了进货，餐厅缺少实际营业成本；希望增加**员工工资**并考虑随熟练度上涨。
- 玩家几乎感受不到已有员工的熟练度成长；应先核实效果再设计培养。
- 希望开门前增加市场策略，例如**发传单宣传→真实新增客流**。
- 经营成就感与成长节奏倾向开罗系；借鉴但不照搬。应共同审阅参照、数值和适配 H5 的复杂度。

**设计中心命题：不是靠扣钱遏制滚雪球，而是“投入资源 → 看见能力增长 → 承接新需求 → 赚到有用途的回报”。** 探索/料理仍驱动餐厅，不能转成纯放置开罗克隆。

## 1. main 代码事实（需与正式版本区分）

`src/engine.js` 的 `CREW_ROLES` 只提供阿火40金币入职、小芽35金币入职，一次性支出。当前**不存在周期工资、店铺房租、日常设备维护、开门前宣传购买**，只有采购、员工餐材料、事件临时费等。
- `crew.helper.meals` 和 `crew.waiter.meals` 上限3，来自**实际投喂员工餐**，并不是订单完成XP。达到3次：阿火基础工时节省1→2秒；小芽额外耐心3→4秒；未实行3级以上培养、解锁专长/工资晋级。员工餐当天仍可额外加成，总计阿火至多4秒、小芽至多12秒。视需求、同工位与双锅分工，这些正向加成可能压缩后期挑战。
- `serviceDayPlan` 当前第二轮起客流增加、声望10以上增加，但仍总上限14，**完全不依赖真实桌位数或宣传决策**；首星后新增客群主要替换原客位。
- `closeService` 中日报 `profit` 为收入-材料消耗估值-现有事件与员工餐成本；`purchase` 已经在采购时扣金币，因此该利润并非当天现金变化。未来薪资在现金账本实际扣款时，报告不能再次扣现金。
- `transact` 的幂等键防止重复营业或重复发钱；新工资、宣传必须用当日唯一键。旧 schema4、已开业的 `service` 快照、评分不变。
- v0.12-B 数值审计的成熟餐馆均衡Build在四桌/双员工固定操作模型中，平均11.28单、完成约10.32单、收入239.2、材料耗用估值91、贡献约148.2；但第四桌不增计划客流。连续21晚的40种子情境有大量缺料夜，现金仍显著上涨，强调**有钱≠经营更好**。这是受控模型/外生供给，不可当玩家真实平均表现。

## 3. 员工工资：增加真实长期成本，保留培养成就

### 3.1 建议改为“工作经验 → 可晋升 → 能力质变 + 阶梯工资”
- 玩家实际送出的订单产生跑堂经验；实际完成的厨位工单产生帮厨经验。**不得凭空按一晚/开店动作加XP**。员工餐继续提供当天特效与互动，但不直接重复堆“永久熟练度”。
- 经验槽满后出现**晋升建议/培养提示**，玩家可选择晋升，晋升时工资按固定台阶上调；不得每次经验+1就涨薪。
- 推荐优先3级（见下方候选值），一场营业最多弹出1个成长提示；升级结果必须在员工角色、能力对比和当晚日报可见。
- 随机新员工的技能流派候选以后加入，不要首版就大量属性/雇员抽卡。

| 员工 | Lv1（日工资/能力） | Lv2候选（日工资/能力） | Lv3候选（日工资/能力） |
|---|---|---|---|
| 阿火·帮厨 | 10金币 / 所在锅基础 -1s | 14金币 / -2s，见习→熟练 | 19金币 / -2s **+可指派一次高峰抢锅技法**，与已有主厨加速、员工餐需设总减时上限 |
| 小芽·跑堂 | 9金币 / 顾客耐心 +3s | 13金币 / +5s | 18金币 / +6s **+晚高峰一次优先快速递送**，真实缩短一次延迟而非伪造上菜 |

候选经验阈值：Lv2 8个有效工单，Lv3累计30个有效工单；若有熟练员工提前太快达标，调整阈值或“需要在特殊客群实际达成服务目标”作为职称考核。数值为**设计假设，须经过真实模拟**。
- 旧存档 `meals` 不能被擦除：映射为员工餐关系/临时培养亲密度；新 `xp` 字段默认0，也可在首版发一次性适度经验抵扣，但需明确用户旧培养成果处理策略。不能将3次员工餐直接解释成30份真实工单。
- 工资按**实际上岗当夜快照**在正常营业日结扣一次，薪水单独列账。不能通过开业前反复换岗位或重新加载规避工资；无营业时不计新工资，避免无操作的空日惩罚。
- 保底：工资不足不可导致无法继续经营。首两天可有店铺开张补贴，后期优先提示“选择不宣传、员工暂缓晋升、基础采购、探险获取食材”等玩家有行动空间；若设计欠薪机制须另外审定上限和规则，不在此草案假装已经实现。

### 3.2 工资不能取代真正的数值平衡

以 v0.12-B 的控制实验中“四桌双员工·均衡菜单”单晚理论经营贡献约148金币为参考：Lv1双人工资19，若引入小额基础店务费6，静态贡献仍约123。仅新增工资**不足以解决金币滚雪球**，真正突破是宣传、员工培养、扩建和评级把钱变成可选择的生产力与挑战。追加维护费应从第二轮考虑；首批不把新玩家强制推入亏损。

## 4. 开店前市场策略：花钱购买特定真实客流，而不是无条件营业收入

### 4.1 三档小型计划（初步待校准）

| 营业准备卡 | 费用假设 | 客流/风险 | 经营选择 |
|---|---:|---|---|
| 不宣传（保守营业） | 0 | 现有客流不变 | 储蓄、准备研发/囤料，零新订单压力 |
| **街头传单** | 18 | 当晚 +2 名真实可入座的附近家庭/街坊客，安排在已有波次 | 需要温和/清爽菜单和足够原料；若已很拥堵，传单可能亏 |
| **冒险公会告示** | 35 | 当晚 +3 名真实冒险者，偏高峰进场，有库存和短耐心压力 | 辣/肉/饱腹菜与炒锅产能必须匹配 |
| **品鉴邀请**（首星后候选） | 45 | 额外1位高期待评论家/特殊食客，可有更高的成交机会但不承诺必下高价单 | 需要合适的工艺、声望/关系条件与贵客资格 |

同一营业日只能选择一个宣传方案；效果在开业创建 `service` 前冻结，客人必须真实走门、找座、下单、烹饪、吃饭、付款、评价；**不增虚构销售、不直接送声望**。须先修改当前全局14客硬上限：允许显式“基础客流+获客活动增量”的可预告上限，检查最长100s营业结束以及三波节奏和真实座位数。不要直接把客流上限整体改为20后不做产能测试。

与现有解锁衔接：两桌可先试少量传单；四桌扩建真正提高对宣传额外访客的接待能力；VIP邀请晚于首星，避免首星被随机稀有食材卡住；可从客人图鉴/关系解锁某种活动，使“熟客关系”成为新宣传内容。

### 4.2 投资回报的设计教学

一份额外卖出的基础菜，大致带来**13–18**金币的单位材料估值价差（视菜和工艺而变，并非一定卖出）。18金币的传单，需要2名新客中的大部分真实完成订单才有正向贡献；一旦没有材料/座位/能力，广告就可能亏。

示例（仅说明机制，不是模拟结果）：取前次受控模型148贡献，Lv1双工资19、示例店务费6：
- 不宣传：约123；
- 发传单成本18，若额外真实卖出2份、平均每份材料估值差价14：约133；
- 仅多卖出1份：约119；
- 没能卖出任何增量：约105。
**注意：** 上表全是假设增量，并非代码中已有的广告模拟；真实成交、排队和食材短缺必须用同一个 `engine.js` 验证。

### 4.3 手机UI（减少弹窗）
在目前开门前的**备餐页**已有“菜单/市场/员工”附近，增加一条小型 `今晚揽客` 区块：一个默认“自然客流”，点按后出现三卡简选；展示“费用、预测新增顾客、可能偏好、预计最高客流、供货风险”，最后回到正常开始营业。不要重建经营大厅大弹窗。
日报分为“营业额 → 原料耗用估值 → 工资 → 宣传费 → 店务成本 → 理论营业利润”与“当日现金净变化（含市场购买）”两个分区。显示计划新增客人、实际到店/服务/付款，以及宣传回本情况；对工艺与岗位的成效给可追溯量化数值。

## 5. 学开罗最核心的成长结构：多轴里程碑，而不是无限点数

让玩家同时看见四种进步，每个维度最多1个近期目标，避免小屏HUD塞满进度：
1. **料理**：研发特定客群适配的菜与标准工艺；菜谱不是纯图鉴数量。
2. **员工**：真实服务/烹饪→经验→晋升→岗位/技术改变，员工会“成为某个店的老伙计”。
3. **餐馆**：第3、4桌从装饰变成承接真实新增客流的资产；升级之后才有必要考虑第三厨位/新员工。
4. **客人/评鉴**：熟客带来委托、活动计划与新客型；第二星章要求不同经营挑战，且可由不同Build达成。

一种可能的三日体验（待讨论）：
- 第4天：花18金币发传单，请来2个新客。厨房一下忙不过来；日报清楚写“传单+2、成功接待1、宣传差额-4”；阿火累积工单临近Lv2。
- 第5天：优先备餐/换成双工位菜单，阿火完成工单达到晋升申请资格，选择涨薪换取工效；第二天再宣传时能够多接1份。
- 第6天：完成“老顾客带新朋友”的公开预约与第二星章专项目标；赢来的是可购买的第三厨位资格与独特订单机会，而非直接送钱。

## 6. 开发分期与验证门槛（此版仅讨论，不直接改玩法）

**C0：先做数值数据与设计确认**（本稿）
- 在 v0.12-B 的确定性模拟上比较 **无工资/固定工资/等级工资**，区分真实市场现金和理论耗料利润；20–30夜回归；低绩效与高绩效各跑一组，必须在后续可恢复。
- 宣传增加有条件的客流时，分别在2/3/4桌、单人/双员工、三类菜单、缺料/不缺料等测试供给和服务上限。并验证本体100秒营业结束不会造成无可控失败。
- 约束：宣传按当日唯一交易、工资按班次唯一交易，复盘与保存/恢复都幂等。

**C1：人工与日报**
- 先只加入**固定工资**（按当前员工已雇佣状态；晋升未实现时不涨薪）与收入/成本/现金差异的清晰日结；如新建店务费先作为可关闭试验参数，不要一下加所有费用。旧存档兼容、已有开业快照冻结。
- 真机验证新日报不会把玩家推成记账负担。

**C2：真实成长**
- 工作订单XP/晋升/明确角色反馈/员工餐新定位，再开放阶梯工资；通过阿火、小芽的真实岗位展示效果。
- 现有`crewEffects`是单一能力权威，改动需避免“旧meal升级＋新Lv升级＋新技能”三层同时堆满效率导致更严重滚雪球。

**C3：一次宣传玩法**
- 先实装“自然客流/街头传单/冒险公会”三择一，需引入 `serviceDayPlan` 同源新增订单和真实四桌路径，以及对应小屏预告/日结增量。
- 价格与新增数按实测调优；确认“认真备餐可赚钱、乱宣传可能亏，且没有固定最优选项”。

**C4：第二星章与员工岗位扩张**
- 依据营销引入的真实高峰，实施第二星章双主题与第三厨位/新员工资格；无需另起一套营业模拟。
- 非当前C1/C2/C3实现范围。

## 7. 决策待确认（供玩家下一轮反馈）

- 成长路线建议采纳：真实工作XP、**晋升时涨薪（而不是经验每加一点就涨）**、员工餐为日Buff/培养关系。
- 开店前宣传先小三选一、按真实订单带来额外客流；不增加第二层货币、不做抽卡活动。
