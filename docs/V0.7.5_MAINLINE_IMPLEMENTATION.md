## 这次已经落地

**版本显示**：浏览器标题、游戏内左上角 ODDPOT · v0.7.5、package.json 全部同步；index.html 的 app.js 缓存参数升级为 v0.7.5-release，避免玩家因旧文件缓存误以为版本没更新。

**完整重绘厨房与餐厅**：src/restaurant_scene_v075.js 的 DINER_FLOOR 为厨房、柜台、桌椅、服务热点、碰撞区和员工路径的唯一权威。src/scenes_v04.js 通过 drawRestaurantV075 在新经营中只绘制一张 Canvas 地面、灶台、出餐台、双人桌及人物，不重复渲染老版 DOM 家具、透明 hit-map 和固定主厨。新预报/准备静态场景也使用同套餐厅。人员均使用 DINER_ACTOR_SCALE=1.13，不能额外放大主角；头顶工作状态为单个图标，无文字气泡。

**营业 UI 减法**：src/app.js 里新的 service() 与旧的 serviceLegacy() 严格互斥。新移动营业不显示「选择顾客、优先出餐、金币招待、经营事件与继续迎客」底部按钮，不再输出大型 Dock。只有顶部紧凑的波次、已上菜、精力、暂停与一个小目标显示，特殊精力技能仍必须玩家主动点按钮。旧版代码保留用于老存档正在进行的自动营业。

**流程事件**：开门直接开始营业。第 1、2 波结束时自动冻结并弹出可选事件，选择一次方案后自动执行旧 chooseServiceEvent 唯一事务并 resumeBreak；不可支付选项灰显，不重复收费，不需要再点一次继续；旧临时换菜单/备餐管理菜单不再挤进移动经营。

**时间与动作**：原先每 750ms 的自动 tick 只保留给非移动的旧营业；新营业通过 requestAnimationFrame 同一个真实 delta 同时驱动人物物理移动、持续取菜/上菜读条及每一秒的经济/厨位 tick。advanceWalkableInteraction 用真实到位后约 0.36 秒取菜、0.48 秒送到正确餐桌，直接改变既有 orderId，不另外开销售系统；收入仍在菜真正落桌后由原 sale-orderId 记账一次。主厨普通工作/端盘/上菜不花精力，额外加速与紧急安抚必须主动点击。

**员工与客人**：阿火守住被指派的厨位，小芽沿 PASS→中线→目标桌→PASS 实体来回送餐。新桌位状态识别 pickup、carried、delivering，不能把等待服务的顾客显示为空桌。主角移动、锅体、服务位置共享 DINER_FLOOR，端错桌无法送达。取盘和端菜时唯一食材、唯一订单、唯一营业收入。

**存档**：旧非移动营业保存状态不硬切，结束当前夜晚后下次开业使用新场景；v0.7.4 进行中的移动营业首次恢复时将主角放入新场景安全入口并记录 sceneVersion=0.7.5，只迁移一次。后台恢复自动暂停，不补算后台时间。旧菜谱工艺、真实库存、员工餐、探索便当、研发结果和日报均保留。

**离线版**：scripts/build-standalone.py 现在包含 restaurant_scene_v075.js 与 CSS；standalone.html 已同步，并修复从上一版拼接中残留两套 HERO_STATIONS 的重复声明问题。
