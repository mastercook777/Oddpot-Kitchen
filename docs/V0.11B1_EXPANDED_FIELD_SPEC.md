# 《怪味食堂》v0.11-B1 · 扩展生态地图、跟随镜头、空间层次
**状态：已确认实施 / 功能分支开发中** · 基于 main v0.11.0-alpha.2 · 2026-10-13
**输入**：[10月13日用户反馈和2.0重规划](V0.11_PLAYER_FEEDBACK_REBASE.md)

## 核心玩家体验与这次边界

玩家进入新探索段不再看见固定 9×11 全图：以**约 8×10 单位的镜头视野**在**12×16 世界**中移动、寻找目标和旅人；不同生态的可通行路径、地面装饰、资源聚落和大型可辨认障碍组成不同场景。环境与障碍必须能对应上，不凭贴图挡路。现有 3 段、WOK/POT、HP、Boss、背包、便当、一次旅人均原样保留，餐厅研发不动。

- **B1 第一批本次开发**：地图 9×11→12×16；已有资源/陷阱/障碍变换到全新世界坐标；基于种子附加物理障碍形成不同有效路网；出生/目标/掉落/Boss/旅人保持可达；摄像机以人物为中心、贴边时夹住，单位尺寸不随地图扩大而缩水；新增生态专属可视地形与丰富世界道具、双层前后景。
- **B1 后续和 B2 尚未开发**：每生态高质量专业像素资产、具有玩法影响的捷径/采集路线、多行为原生怪群和数量梯度；这些不能因本次地图扩容而被宣称完成。
- **B/C 后续**：真实商人/旅人多类型、专供材料、四道稀有菜与餐厅商业闭环。这次不能增加伪奖励。

## 可测试方案

1. `src/field_world_v011b1.js` 的 `expandFieldMap` 把旧基础生态资源位置映射到 12×16 网格，设置 worldVersion `0.11-B1`，世界地图仍保存坐标和障碍；按稳定 `seed+zone+day` 生成附加障碍和纯装饰 `scenery`；每次插入障碍必须用 `fieldTilePath` 检查所有采集点与 Boss，从玩家出生保持通达，并避免打掉至少一条避开静态危险区的通路。
2. **只有新生成的地图会扩容**，旧存档已生成中的 field 坐标保留 9×11；旧地图依然按旧渲染投影，避免角色或怪瞬移。换段会使用新版大地图。新版字段均可选，存档 schema `version:4` 不升级。
3. `src/field_camera_v011b1.js` 是纯摄像机计算，Canvas 根据真实场景大小约 7.6×10 的视口单位缩放，始终裁剪到世界边缘；`drawField` 中世界层施加相同变换，实体像素大小不缩水，旧图保持固定全图视角；小屏/横屏均不能出现无内容露底。
4. `src/field_world_render_v011b1.js` 按生态 style 区分地貌：森林草甸足迹与草簇、菌沼发光圈与孢柱、古树根系、菜圃畦垄；热泉池岸、蒸汽裂缝、熔岩焦土、晶池纹理。同时放置不会挡住目标/危险符号的装饰；所有物理障碍由 `map.obstacles` 唯一生成、画面与判定同坐标。
5. 新地图的 `startActionField` 改用地图几何动态计算敌人位置（大场景）；不提高总敌人数上限，不改变战斗平衡、血量或弹幕。固定老怪起点只用于旧图。

## UI/视觉约束

维持 9:16 竖屏、HUD/摇杆/技能按钮 DOM 叠层位置。目标轮廓、奇遇旅人标识、陷阱状态、可通行路径优先于装饰。B1 只使用自绘 Canvas 美术占位，不声称已经完成正式高品质美术；装饰没有碰撞，不应看起来像一堵挡路的墙。两大地区轮廓识别是重点，不靠添加背景故事字幕。

## 安全与验收

- 8 个生态 × 64 个 seed × 安全/危险路线：世界为 12×16，新障碍不压资源、陷阱、出生、Boss，主线所有节点和 Boss、旅人节点 `fieldTilePath` 可达，且存在显著布局变化；
- 摄像机函数 320px 手机、不同 Canvas 长宽、边缘以及旧 9×11 地图上无越界/空白露底；世界精灵屏幕大小与地图扩张解耦；
- 真机玩家完成森林+热泉两区，各三段，观察走位和地形“不是旧图缩小”，体验是否仍保持紧凑；**CI 通过不等于 iPhone 通过**；
- 执行 npm tests、独立离线构建与网页构建，均绿灯后合并；更新 PROJECT_STATE / ROADMAP，禁止把 B2/C 标成完成。
