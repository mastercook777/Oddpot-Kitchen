
# 《怪味食堂》v0.8 · 三段式探索、Mini Boss 与库存供给（设计规格 v0.1）

日期：2026-10-12。状态：设计确认，尚未实装。起点：v0.7.8 正式主线；保留 v0.6.3 实时研发、v0.7.5 可移动餐厅与 v0.7.8 角色对话。

## 1. 核心体验和不可变规则

一次出发最多三个连续探索区段（初始段+最多两次继续前进）。每完成一区暂停区段进程，显示两张不同的下一站卡片，以及独立的「带着收获回饭店」。两张卡片分别承诺不同掉落、危险和事件；已生成后本轮不得重抽。第三段完成直接结算，不出现第四次继续前进。

危险路线的最终第三段固定发生该地区 Mini Boss，覆盖先前「40% 出现」的候选随机规则；两个危险终点卡可以改变进入方式、敌人与地形，但不得让已承诺的 Boss 消失。普通路线的第三段提供高级采集或事件，不强制战斗。每次仍只消耗当日一次探索机会；区段间沿用同一角色 HP、背包、一次性便当、所得线索、同一 seed。

可以随时撤离保留已经拾取的本次背包物品。生命归零按现有探索失败规则损失本次部分收获，但绝不回滚餐馆旧仓库。材料只在全程结束时经 src/engine.js 的 settleField() 一次性写入账本；不得区段间提前入仓。区段选择中暂停游戏时钟/敌方攻击。退出重进不得重抽卡或重复领奖。

## 2. 地区内容

晨露森林：香草小径（安全：蒜瓣/卷心菜/洋葱）；幽光菌地（中等：蘑菇/鸡肉/孢子事件）；古树孢巢（危险：菌王孢心/孢冠菇王）。
热泉峡谷：热泉浅滩（安全：火椒/蒜瓣/土豆）；蒸汽裂隙（中等：火椒/野牛肉/间歇喷泉）；赤焰断坡（危险：熔心椒晶/熔壳椒王）。

示例森林三段：
- 初始香草小径清除后，两卡：A 幽光菌地（常规素材）/ B 古树外缘（危险承诺，第三段孢冠菇王）。
- 选 A 后第二次两卡是不同常规终点，如林地菜圃/菌光秘径。
- 选 B 后第二次两卡是孢巢正门（更多小怪）/枯根侧道（更多地形危险）。两者第三段均必须打孢冠菇王。
热泉峡谷同理，危险线路第三段为熔壳椒王。若允许最初直接进入危险小区，也要从出发时明确第三段 Boss 承诺。

每卡显示名称、风险、稳定产出、可能产出、特殊地形和是否固定 Boss；不得虚构精确掉率。区段完成必须达成公开的采集/遭遇目标或到达出口，而不能站立等待计时自动领奖。单段建议 20–30 秒，危险终点额外 Boss 约 15–25 秒，最长一次出发约 75–115 秒；该时长仍需实测，早退一段保持短局便利。

## 3. 技术状态与幂等

推荐探索状态：PREPARE → SEGMENT_1_ACTIVE → SEGMENT_1_CLEAR → BRANCH_1_CHOICE → SEGMENT_2_ACTIVE → SEGMENT_2_CLEAR → BRANCH_2_CHOICE → SEGMENT_3_ACTIVE → RESULTS → RESEARCH；任意 ACTIVE 或 CLEAR 都可 RETREAT → RESULTS，死亡 FAINT → RESULTS。

ExplorationRun 字段建议：runId、dayKey、seed、regionId、segmentIndex(0..2)、segments[]、branchChoices[]、selectedBranchIds[]、dangerCommitment、hp、bagStacks[]、bento、claimedSourceKeys[]、defeatedBossIds[]、pendingPickup、settled、exitReason。每个节点领奖键关联 runId+segmentIndex+sourceId；整日 settlement 仍使用唯一 field-cycle-day 事务。中途进出区段同一背包，不赠送额外材料，不清空状态。

区域配置独立于实时运动代码，建立 RegionDefinition / ZoneDefinition / BranchDefinition / EncounterDefinition / IngredientSource。保留 safe/risk/spring_safe/spring_risk 旧 routeId 的迁移映射。展示 Canvas 不直接写库存；最终金币与道具均通过 engine 域结算。

## 4. Boss、珍贵食材和料理

首批 Boss：古树孢巢「孢冠菇王」，扩散孢雾和短冲锋；赤焰断坡「熔壳椒王」，直线喷火和蓄力冲刺。保留当前摇杆、自动攻击和锅铲技能，不引入装备树，攻击预警足够规避。首胜稀有材料×2，此后重复击败×1；材料首先生成地面拾取，实际装包后才能在撤离结算入库。背包满时必须允许玩家选择交换原物，禁止静默丢弃新稀有物。

菌王孢心 mushroom_heart：菌香/鲜/浓郁，估值13，field_only，只从菇王奖励获取。
熔心椒晶 ember_pepper：辣/香/爆香，估值16，field_only，只从椒王奖励获取。

新增共鸣：古林珍馐（菌王料理+不同菌香菜，高品质评论家口碑奖励每晚一次）；熔心热宴（熔心料理+不同温和 POT 菜，冒险者相关 Fit +8）。沿用每晚仅一个主共鸣的上限，不能重算同一订单收入。以上价格、战斗时长、Fit 均为待验证样例，不能直接写死进场景。

重要：现有 src/data.js 已自动从 8 种普通食材生成 167 个唯一菜谱 ID。新增两种 rare 时先使用精选配方白名单，仅上线本段四道；不能把稀有食材无条件加入自动组合枚举，避免产生大量未设计/未平衡菜谱。完善 src/cooking_v063.js 的热度、熟度和下料特性，确保上述料理真实可售、不会永远夹生。

## 5. 野外背包空间优化

当前 f.bag 是 ingredientId → quantity 对象，一种材料最多 3 份占一键、旧版背包 6/7/8 格；三段循环会暴露「同种材料满堆无法再捡」的瓶颈。

v0.8 推荐改为 bagStacks[]，每槽具有 stackId / ingredientId / quantity（每槽最多 3 份）；同种材料允许自动分配第二堆叠槽。野外初始 8 格，成长升 10/12 格（示例 60/110 金币）。旧存档 bagSlots=6、7、8 根据已购买次数迁移为 8、10、12；迁移不再扣金币、不丢旧包内容。不引入强制掉落替换：满包只允许用户显式选择腾出哪个槽，或立即撤离。

探索 UI 显示 xx/8 格、总份数、稀有/目标来源和一键查看每堆；卡片选择时携带资源在原 run 中。大背包只扩大容错与多样性，不免费提升战斗力或掉率。

## 6. Stock 仓库采购缩减与保障

当前 src/engine.js 的 purchase() 允许购买 chicken、garlic、mushroom、cabbage、chili、onion、potato 共七种；beef 不允许。仓库列表独立渲染采购按钮，可能出现前端许可和领域许可不同步。永久仓库当前并没有真正硬容量上限。

v0.8 可补货四种：林地鸡肉 chicken、蒜瓣 garlic、幽光蘑菇 mushroom、卷心菜 cabbage。其余六种只能探索：火椒 chili、野牛肉 beef、琥珀洋葱 onion、地精土豆 potato、菌王孢心 mushroom_heart、熔心椒晶 ember_pepper。保持安全热泉段能够稳定采到火椒，保证初代厨王无需 Boss 掉落也有基础辣味可用；常规基础菜仍可经营，避免缺料软锁。

将食材统一配置 acquisitionPolicy=SHOP_STAPLE 或 FIELD_ONLY；purchase()、可购买列表和购买按钮均以此源数据判断。STOCK 分两个分类「基础补货（4）」和「野外专属（6）」；后者显示库存、来源和灰态说明，但不出现可点击的采购按钮。暂不引入永久仓库的硬总格数上限，以免老存档累计库存被无声截断；先改善分类、素材来源/售价可读性与野外背包空间。

## 8. Codex 任务与验收

A 数据/采购/旧存档：地区区段/卡片定义、双来源政策、旧背包迁移、库存 UI，两区地图和已有餐馆正常。
B 三段循环：第一段可撤离或二选一、第二段同理、第三段结束自动回店，卡片在同 runSeed 下稳定；一天只有一次入库事件。
C Boss/掉落：危险第三段固定 Boss，非危险终点可不战斗；胜利拾取两种 rare，满包交互，失败/撤离有解释性结算。
D 四道真实特色菜：研究→已选工艺→菜单 Build→实际出餐/库存消耗→评价/日报，精品与基础菜都有价值。
E NPC 气泡热修、经济平衡、真机触控、离线包与 Pages 版本统一，npm test 绿灯。

测试必须覆盖：恰好最多两个前进选择；每次两张不同卡和回店；危险第三段 Boss 必现且只给一次；非危险不强制；中途撤离携带真实已得物；HP 和 bento 跨段持续；每段不能入仓或重新抽奖励；刷新和重复点击都不会复制稀有材料；旧存档各档位包完整升级；同材料多个堆叠/满包选择；四种可购、另六种不可购；初代厨王安全火椒来源；四道新品能实际售卖并改变菜单；三种手机视口无气泡和控件重叠。

## 9. 新增设计决策（2026-10-12）：厨具与探索武器绑定

新增正式配套设计规格：[v0.8 厨具 × 探索武器双用途系统](V0.8_COOKWARE_WEAPON_BINDING_SPEC_v0.1.md)。玩家出发前从目前左右已配置的实体厨位选一套带到野外，WOK = 剑盾风格的近战横扫/锅盖格挡，POT = 洋葱炸弹的远程范围输出。自动普攻+一个主动技能、同一局三段不换武器；普通投弹只属于视觉弹药，不消耗真实洋葱。现有厨位 Lv2 的单次经营升级同时获得有限的战斗强化，不新增独立武器升级币种。当前 level 绑定厨位而非锅种，必须用 slotIndex/type/level 快照实现，兼容旧存档；未来新增锅具再共用同一注册模板。两款 Lv1 都必须可以击败两地 Mini Boss，探索仍为料理与营业提供材料。开发顺序调整为 A→B→C0(武器适配)→C(Boss)→D(稀有料理)→E(气泡/打磨)，正式任务与验收以配套规格为准。
