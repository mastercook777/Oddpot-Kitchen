## 1. 玩家体验
玩家已经有什么、缺少什么、现在能做什么；以一段实际营业日示例说明新系统在菜单→准备→营业→日结→次日中产生何种变化。**必须有经营意义，不仅更高难度**。

## 2. 新规则与已有系统关系
数据来源与状态；具体触发条件、消耗/收益及上限；菜单/食材/订单/服务/声望/扩建之间真实关系；算法示意。区分 **玩家可选操作** / **自动后台效果**，禁止未说清的新货币、新订单、新 Boss 独占资源。

## 3. UI 与奇幻表现
在哪个现有页面出现、区域空间占用、按钮与操作、显示字段、缺失状态、老存档迁移；320px 窄屏/短屏/安全区/触控遮挡；奇幻靠 NPC 身份、环境、反馈实现，**禁止仅用功能区名字堆界面**。没有正式美术资源时只使用现有素材或程序绘制。

## 4. 数据、代码位置、依赖
需要新增的数据字段与身份键，兼容旧存档，消费、结算与防重复交易规则，源文件/可复用函数，前置改动和不改动部分。

## 5. 最小可玩范围与分期
必须完成 / 可延后 / 明确不做。优先最小闭环，避免无关功能堆叠。

## 6. 数值建议（尚未确认与已确认分列）
用明确数字或范围标出“提议值，不是现有事实”，并解释测试方式，不要无依据声称已经平衡。

## 7. 验收与风险
功能测试、经济守恒、旧存档、移动端视觉、玩家真正能感受到的成就感。列明“CI 通过”与“真机验收”是不同状态。
