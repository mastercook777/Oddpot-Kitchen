# 《怪味食堂》v0.7.8 · 食客性格、员工闲聊、负面反馈与日报标题修复

**2026-10-12 · 已实装正式主线 main。**  
**玩家需求：** v0.7.7 的 chitchat 获得认可，希望各类型食客对话更多、有真实缺料/久等/愤怒离店反馈、员工之间也有简单对话，并修复每日结算页 title UI 框显示问题。  
**正式地址：** https://mastercook777.github.io/Oddpot-Kitchen/  
**注意：** 自动回归不能替代 iPhone Safari 视觉验收；本版主要打磨餐馆氛围，不能破坏已经成立的移动经营 UX。

## 1. 四种食客角色的个性化对白

真实 customer segment 仍来自 \`src/data.js/CUSTOMERS\`：

- **冒险者 adventurer**：焦急、爽快、吃饱赶路；例如「这一餐得吃饱！」「快上菜！我还要赶路！」「不等了，冒险要紧！」
- **家庭食客 family**：温和、照顾孩子、重视家常饭；例如「看看有什么家常菜。」「孩子都等饿了…」「抱歉，我们先走了。」
- **街坊客人 regular**：熟悉店铺、随意且能评价老主顾体验；例如「老样子，来一份！」「老板，别忘了我啊！」「今天这服务不太行！」
- **美食评论家 critic**：火候、工艺、服务都算在评价里；例如「期待工艺上的巧思。」「出餐效率需要改进。」「服务失序，测评结束。」

\`src/diner_ambience_v077.js\` 的 \`DINER_VOICES\`：每种客人对**看菜单、点菜、烹饪、出锅、送餐、用餐、等待警告、愤怒离场、缺料、菜单不合适**均有 3 条备选短句。

随机感来自真实 \`order.id + segment + 话题\` 的稳定哈希，**不按 RAF 每帧重抽**。同一单在读档和重复绘制时不会乱跳文字；只读，没有金币/好感/产能改动。点菜文字**优先展示真实菜谱名**，再附一句类型化补充；图标与实际需求仍保留。

## 2. 负面反馈必须有真实经营因果

\`src/engine.js\` 在原有订单状态与事件中补充小字段，仍沿用原本订单，不新建平行经济系统：

- 排队太久：\`status:'left'\` + \`leftReason:'等待超时'\`，在真实离场动画的前 2.5 秒显示角色专属愤怒文字和轻微不满动作。耐心剩约 11 秒以及 5 秒时会短暂催单，但不会无限刷消息。
- 食材不足：\`status:'rejected'\` + \`rejectReason:'食材不足'\` + \`missingIngredients:[ingredientId,...]\`。若真实缺少可识别食材，气泡会直接说出 **「火椒都没了？」** 等真实品名，而不是与菜单不匹配混为一谈。缺料由原库存规则决定，UI 不凭空制造。
- 菜单不匹配：\`rejectReason:'菜单不匹配'\`，顾客抱怨店里没有合适的菜，与库存不足分开。
- 做菜失败、营业结束：分别 \`leftReason:'制作失败'\` 和 \`leftReason:'营业结束'\`，避免所有离场都被渲染为“等太久了”。

**重要渲染修复：** v0.7.7 的 speechActors 只包括 \`!a.walk\`，会导致离场顾客虽然有负面台词却被过滤。本版显式允许真实 \`left/rejected\` 行走人物短时间挂气泡；所有气泡仍锚定唯一实际 NPC，不创建额外固定演员。

## 3. 阿火、小芽的简短协作

\`selectStaffSpeech(s,t,visibleCustomerCues)\` 只在有雇员、真实工作场景且营业未暂停时可显示：

- 阿火负责的厨位真正开始工作或对应菜品出锅后：「这锅我看着！」「新鲜出锅！」
- 小芽真正从出餐台取菜、送达返回：「这盘交给我！」「我继续招呼客人。」
- 有真实食材不足且客人抱怨结束后，阿火才会补一句「得赶紧补补库存！」，不抢过顾客的负面反馈。
- **两人同时雇佣时**，每隔约 24 个游戏秒出现一段简单轮流对白，例如阿火「我看火，你看客人！」，小芽随后「放心，桌边我照顾！」。同一时间最多**一名员工**发言，避免对话刷屏。

特殊约束：顾客正在紧急等待、愤怒离场或真实评价时，优先顾客对白，工作人员对话让位；原有「一桌最多一条、全厅最多两条」规则不变。员工气泡仍在 Canvas 中，**不会增加拦截摇杆的 HTML 控件**。人员正常比例 \`DINER_ACTOR_SCALE=1.13\` 不变。

## 4. 日终日报 title 显示 Bug 修复

此前 \`src/style.css\` 的 \`.report-scene\` 与 \`.menu-scene\` 共用 \`justify-content:space-evenly\`，而移动端又令长日报整个容器 \`justify-content:center\` 且 \`overflow-y:auto\`。长日报在矮屏可能从中间堆积，**顶部标题被裁切或显示得像挤坏的 UI 框**。

修复：
- \`src/app.js/report()\` 使用语义化 \`<h2 class="report-header">...</h2>\`，原中文胜负文案不丢。
- 新独立 \`src/diner_polish_v078.css\` 明确只限定 \`.stage.report\`：报告内容从**顶部对齐**，在场景内部纵向滚动，不挤压标题/统计卡；标题透明、无边框阴影、允许自动换行，以一条小分隔线结束。
- 320～390px 手机宽度及较矮屏幕压缩标题与卡片留白，不要突然用绝对定位或固定高度覆盖正文。
- 这只是 UI 修复，原日报利润、工艺销售、员工贡献、任务、食客评价、升级入口没有改变。

## 6. 玩家验收最重要的三件事

1. **短对白真的听得出身份**：连续来访的冒险者、家庭、街坊、评论家不同；说的料理名跟点单一致。重复读档文字不变。
2. **犯错之后餐厅会有情绪**：若缺料，顾客先失望走开，员工在适当时刻自言自语；若久等，先抱怨、再愤怒离场。两桌和员工同时互动时不至于全屏对话。
3. **日报首行正常显示**：结束三天任意一天，普通/挑战、0 员工/2 员工、长料理工艺表现的日报，顶部标题都完整显示，向下可滚，底部升级按钮保持可点。

**发布 Gate：** GitHub Actions 完整通过和 Pages 部署成功只是代码 Gate；小屏布局与频率必须等待玩家实际试玩验收。
