# Oddpot Game UI Architecture v2.0 · Z2e-B / Z2e-C
2026-11-26。玩家已实际认可工坊1.0基本摆脱网页感，确认先做五大场景架构文档与可交互全流程工坊2.0，不立即迁移正式游戏。基线 PR147 / main 9f8232e，18/18 CI、664/664 核心，方向已验收；PR146缓存修复17/17。延续 [Game UI Design System v1](GAME_UI_DESIGN_SYSTEM_V1.md)，本稿优先于其旧迁移路线。Z3暂停。

## 1. 设计原则与边界
- 从八个规则phase到五个视觉/操作场景；保留真实规则phase、引擎与数据，不把状态机重写为开放世界。餐厅是玩家的家，清晨/开业准备/营业/收工/成长是同一空间不同状态；营业是特殊交互模式，算五大场景之一。关闭窗口回到原场景，不触发阶段推进。
- L0全屏世界；L1常驻少量状态（非营业金币/日期/星章，探索生命/背包/技能，研发火候，营业波次/上菜/精力）；L2物件热点/状态气泡/槽位；L3单一游戏窗口；L4结果演出。沿用1.0黄铜、墨绿、羊皮、实体边框、图标、44px最小操作目标。默认无页面级滚动；只在大量资料窗口内部允许。320×568、375×667、390×844、安全区。关键动作固定下缘，状态在上缘，非必要信息按需。
- 不新增正式素材、游戏规则、数值或存档迁移。工坊新独立入口 game-ui-workshop-v2.html，1.0保留。示例档只存在内存，不读写正式存档。真实渲染与可操作引擎尽可能复用；示例起始条件与快速验证节奏明确标注，不能作为经营平衡样本。正式内容仍以主站为准。

## 3. 一日流转与窗口契约
清晨→门口→整备（可以返回清晨）→确认路线→野外（真实地图生成/输入/收获，随时返回）→收获窗口→研发（或跳过）→料理结果→同餐厅备餐→开业→实时营业（同一canvas与镜头，不销毁餐厅舞台）→打烊结果→星章（若真实获得）→成长→次日。探索和研发之间只做简短环境淡入/淡出；餐厅模式间不黑屏、不重新加载文档，以招牌、HUD和暖色光晕变化。工坊2.0只验证轻量转场节奏；正式Z3声音/精细演出后置。场景切换由显式动作触发，结果窗口不可误关闭跳过必要确认；普通窗口关闭恢复原焦点与状态，原生dialog隔离背景，禁止堆叠；详情返回上一个窗口。减弱动态偏好取消转场动画。切换场景释放不用的3D实例；餐厅模式保持实例。3D失败继续真实2D或明确的简化工作台/地图示意，核心操作仍可走通。

## 4. 工坊最小验证范围
起始为接近首星阶段的独立内存样本（从现有labFixture复用，可明确预置首星、金币与桌位；不模拟虚假星章获得）。复用 enterField/startActionField/stepActionField/useFieldSkill/settleField，真实研发 beginLiveResearch/dropLiveIngredient/performLiveAction/stepLiveResearch/finishLiveResearch，真实 createService/tick/resumeBreak/closeService，labOffers/labBuy/advanceDay。实际结果来自引擎；若无获星不展示获得演出。为快速体验提供显式“快进营业”而非伪造成绩，原规则处理失败/成功。正式游戏深度功能（所有路线分支、全部工艺/营销/招聘/员工调度等）不要求在工坊全部重做，但正式迁移绝不能丢失。保留现有工坊1.0作为首星/成长的确定性展示。

## 5. 验收矩阵
三手机尺寸从清晨经整备、真实野外、研发、备餐、营业、结算、成长、次日，一次文档加载走完整流程；共用窗体与HUD、核心路径无全页滚动；截图各场景与重要窗口；核对实际结果/金币/升级、重复点击不重复结算、窗口关闭回原模式、无正式存档读写；验证真实WebGL与资源失败后的降级；旧游戏全CI不受影响。玩家需重点验收场景空间连续感、窗口视觉一致性、主要操作手感、是否还有网页感。Z2e-D正式迁移按场景分切片，先营业→收工→成长真实链路再扩展，必须保留正式全部功能；Z3继续暂停。
