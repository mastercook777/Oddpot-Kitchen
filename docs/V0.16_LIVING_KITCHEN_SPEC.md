# v0.16 · A Living Kitchen / 一间活着的食堂
状态：用户确认，分期实施；2026-11-24。基线 main 0.15.0-alpha.11。
## 1. 目标与玩家体验
现有功能 App 感来自页面优先、场景缩小、交互脱离物体、演出缺乏。以餐厅为持续存在的世界；一日从店内备料、门口出发、回店研发、菜单开业、真实营业到打烊。核心仍是探索×料理×经营，不增加重复跑腿。先冻结第三世界、新厨具及新菜谱，已有云港问题留档。
## 2. 阶段
A：边境食堂视觉/空间切片。真实餐厅 Canvas 成为首屏主体；保留 DINER_FLOOR 物理布局、座位和工位。重绘墙地、窗口、木材与照明，白天与营业夜色区别；不以新增功能卡片替代场景。A1 首批先实现首页场景优先及空间入口，验证手机再做完整素材雕琢。
B：场景实体交互：厨房、菜板、储物/商人、门口、员工、图鉴等映射既有动作，点击即可，不强制跑腿；保留可达快捷入口。阶段约束、实际库存与现有动作保持。
C：真实已雇员工、真实客人与订单驱动动作/反应；装饰演出不可产生交易。清晨/营业/打烊可感知。
D：锅具特写、实物下料、翻炒与火候、成品演出。保留现有实时研发规则，逐锅具验证。
E：开店/评星/晋升/传送门演出、声音、HUD 一致性；尊重静音和 reduced-motion。
F：验收边境后推广云港，必须保留地域差异；不迁移引擎，除非后续单独验证必要性。
## 3. A1 实施边界
首屏不再以大目标卡和九宫格为主体：边境 forecast 场景占主要空间，简洁提示与快捷入口保留。利用当前 Canvas 真实演员、天气、厨位、桌椅，不造虚假顾客。空间入口须通过既有 data-act/事件处理，不直接改变 game；不可用操作仍由原规则限制。云港、营业操控、研发及数据逻辑不重写。新样式只作用于边境首页；场景绘制如扩展应限定边境、保持物理坐标和视图比例。优先已有素材和程序绘制，不声称正式手绘资源。
## 4. 工程与兼容
基线 src/app.js、src/scenes_v04.js、src/restaurant_scene_v075.js、src/forecast_home_v076.css、src/full_game_ui_v014.css。无 schema、经济、订单、食材、星章、员工数值变动；旧档无需迁移。确保正式入口及离线生成链一致，不能手改生成包造成漂移。保留原操作和无障碍按钮语义，缩小屏幕也能操作。
## 5. 验收
320×568、375×667、390×844：场景占首页可用高度目标≥60%（极短屏允许例外），无遮挡/滚动陷阱；所有原快捷操作和主按钮可用，场景入口触发同一动作；云港原样；真实角色/桌位/工位与旧档对应；npm test、npm run build、离线生成及浏览器烟测分别记录。真机玩家主观验收：静止画面有世界感、10 秒录像不似管理 App，场景入口比卡片自然；未通过不全面推广。对比截图/录屏须实际获取，不以描述代替。
## 6. 风险与决策
触控命中区重叠、短屏、Canvas 过度重绘、装饰与真实可交互对象不一致；优先稳定保留原路径。设计不是把所有界面移到 Canvas，也不是强制移动。A1 为体验验证切片，不能声称 B–F 已完成。
