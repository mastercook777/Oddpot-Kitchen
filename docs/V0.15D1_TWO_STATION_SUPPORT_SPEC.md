**状态：已由 v0.15-D 审计确认的 P0 修复，尚未实装。**  
**依赖：** [实际数据](V0.15D_CLOUD_OPERATIONS_RESULTS.md) 来自 12 配对 seed ×6服务组，其中主厨与帮厨重叠时 1.33 成单/6.25 超时，站右锅时 5.50/2.08。原控制组无缺料且菜谱口味匹配高，首要原因是没人工照看另一口锅时零生产速率。

## 目标与范围
- **仅云港**：双厨位、开业中、存在一名本地已雇已排班帮厨，当前炉位空闲且无本厨具待做单，而另一厨位有真实制作中或待做订单，且玩家不在该厨位时，帮厨才在原房间行走路线从左到右或右到左跨位支援。
- 真实位移耗时（两厨位不相邻，建议 3 秒；中厨位相邻沿用已有 2 秒），路上无生产速率。到位后只能服务新岗位，原岗位不会凭空保留复制员工。若玩家已经覆盖另炉，不需要多此一举跨位。
- 已占位的厨房有工作，不允许员工凭空放弃正在做的锅；跨位最短4秒间隔/现有 cooldown 保留，不能左右每帧弹跳。没有第二厨师时无法双锅并行；如果玩家不动而两炉各有单，依然会排队，只是不会整晚完全死锁。
- 旧世界两厨位、任何世界三星会宴/评星配锅、三厨位现有自动支援、已开工订单的厨具快照、普通菜谱/好感/客群耐心、工资、库存、分账、存档 schema 均不改；只增强云港物理帮厨实际工作。
- 正式游戏用既有 `crew_move/crew_arrived` 动画路径/事件，不另加假 NPC；必要的站位提示后置 UI 切片。旧存档正在营业的快照保留（若下次 tick 具备两厨位条件可临时启用，同一笔订单不重算）。
- 测试：同 seed 12组 left/pass 真实上菜/超时改善，right 不应显著降低；工作时不能跳跃/复制帮厨，员工抵达后实际持续生产，旧世界双厨位不受影响，三星挑战不变；`npm test`、构建、离线/手机 Chrome 和玩家真机逐项另报。
- **明确不做**：延长23/31秒顾客耐心、提高菜品好感、给云港免费资源、改变工作台数目、自动从旧店拿货。
