# 《怪味食堂》GDD v0.3 — 核心循环重构与原型验证

版本：v0.3 · 2026-10-09 · **原型假设 / 尚未玩家验收**

## 一、为什么调整

v0.2 用户试玩反馈：
1. 炒锅研发有趣，但菜单可发现内容太少；数学 Puzzle 性质并非必然问题。
2. 食材探索只靠列表点击，不产生获得材料的参与感。
3. 餐厅经营的独立乐趣不明显；让营业继续手工做菜会与研发重复。
4. 页面的纵向滚动/大量菜单像普通网页，而不是 H5 游戏。

v0.3 保留「研发 → 菜单 → 营业反馈」的核心因果，重分工：**研发 = 创造**、**森林 = 探索收获**、**经营 = 观察顾客并在关键点选择**。

## 二、改变的设计契约

> 本节是明确覆盖 v0.2 MVP 数量边界和默认操作的新设计实验，其余经济账本、第三晚唯一营业、库存真实扣除、手动料理占用制作时间等不冲突规则仍遵守 v0.2。

- v0.2 的 6 食材 / 4 基础 + 1 隐藏是旧垂直切片锁定；v0.3 **新增琥珀洋葱、地精土豆共 8 食材，菜谱总数 12（11 基础 + 1 隐藏）**。
- v0.3 的正常营业**不再需要手工重复制作料理**。已学标准工艺由独立的双工位订单队列真实自动完成。玩家仍可在研发阶段操作炒锅盘，未来特殊评委手做是候选而不是必须交互。
- v0.3 探索需在 9×11 森林地图上通过手动方向键或点击目标逐格移动，接触采集节点拿到背包；选择撤离后才将收获一次性入食堂库存，且每天最多一次。
- v0.3 游戏主视图固定于手机 viewport，不允许依靠全页纵向滚动查找操作入口；细节信息可以抽屉式滚动。

## 三、已实现的垂直切片及实现阶段

| 系统 | 原型交互 | P0 验证问题 |
|---|---|---|
| 料理研发 | 8 食材、3×3、移动/颠锅/火力、3拍、12道图鉴线索 | 玩家是否主动再尝试另一道菜？ |
| 森林探索 | 2路线、地图行走、目标采集、危险节点、背包、主动撤离 | 玩家是否因菜单目标而探索，而非为了刷怪？ |
| 餐厅经营 | 餐厅场景、2桌、WOK/POT、3波真实订单、自动做饭、优先/招待/备餐 | 不手动做饭，玩家是否仍愿意调整菜单和操作？ |
| 报表反馈 | 满意度、销量、贡献利润、拥堵、基于未解锁配方的灵感 | 经营是否推动下一个食材与菜谱目标？ |
| 长期循环 | 三天厨王、永久菜谱/仓库/设施/技法、轮次重复 | 下一轮是否愿意测试不同菜单？ |

## 四、必须如实记录的不足

- 12道菜只是足以测试探索的第一批内容，暂不证明足够耐玩。没有锅具形状或实时操作深度扩展。
- 真实经营反馈仍是二维的顾客等待与菜谱适配，并非自由布置餐厅。店长操作频率和力量待评估。
- 地图使用位置触发节点与离散移动，危险没有 AI；不应称为已完成 Roguelite 探索战斗。
- 当前没有全程实测时长、平衡曲线或用户长期留存数据。测试通过≠核心乐趣已被验证。

## 五、下一轮真实试玩问题

1. 没有正确答案提示时，玩家能否通过图鉴线索做出至少两道新菜？
2. 能否自然说出为什么需要走哪条探索路线？是否像探索而不是代替菜单点击？
3. 玩家更喜欢 ① 开店前菜单决策，② 看客人反应，还是 ③ 插队 / 招待客人的操作？是否有经营张力？
4. 本次新菜真正影响了哪位客人的选择、哪个工位的负载、哪条日报建议？
5. 固定手机场景下，是否出现遮挡、过小的触控目标或页面滑动？

**暂停内容扩展条件**：如果玩家仅想刷研发拼图、不愿看店里的客人，优先修正餐馆反馈机制，暂不增加更多菜谱或复杂战斗。
