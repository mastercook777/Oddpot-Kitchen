## 核心闭环
1. **固定工资＋可选上班。** 雇佣员工可在开店前上岗/休息。上班提供真实 `crewEffects` 并有固定日工资；休息不给Buff、不收本班工资。按已创建营业班次的冻结快照日结仅一次，重入/恢复/旧档无重复扣款；工资资金不足计入待支付账款且金币不低于0，未来营业结清（没有无路可走的破产锁）。
2. **订单经验与晋升。** 阿火仅实际完成帮厨工单获得经验；小芽仅真实完成跑堂送餐并成交的订单获得经验；日报记录今日XP＋累计进度。Lv1→2累计8XP、Lv2→3累计30XP，晋升需玩家在准备或成长页手动确认，等级奖金投入及日工资台阶；食物原有最多三次熟悉度不丢弃。新晋升不会让锅的最大提速/客人耐心突破既有封顶。Lv3强调晚高峰实际工作专长并可由记录验证。
3. **开门前付费营销（四选一，含默认免费）。** 自然客流0；街头传单18/2名家庭街坊客；公会告示35/3名冒险者；首星品鉴邀请45/1名鉴味师。明确在准备页选择，开业才冻结并付费。实际 `serviceDayPlan` 增加真实有顾客ID、到店、占座、厨房工单、消费、反馈的访客，不自动增加收入；场地扩建自然改善拥堵下宣传收益可能性。队列保持三波且不会让原有客单错位；上限只为实际宣发额外几单开放，天然基础客流仍原上限14。可真实失败、自然营业保持安全路线。
4. **两种经济视图。** 日报利润=实收-原料消耗估值-员工餐-招待/事件-广告-当班工资（含欠薪），每日实际现金变化单列，包括市场支出与晋升、锅位扩建；现金购买只扣一次，防止双扣。
5. **兼容与真值。** v4旧档迁移；已开业快照不重新派员工/营销；重启与重复关门、事件恢复幂等。UI紧凑，320×568可读，所有按钮有真实响应。C1-C3只改变餐馆经营，不更改探索掉落或第2星章（另做）。
6. **开发验收。** Node全量自动回归、真实引擎固定种子模拟宣传新增到店/成交/供应压力、20+天金币进度（库存不足单独计量）；GitHub Chrome浏览器检查交互与控制台，并通过已配置 Pages 部署。真机仍需玩家反馈，不得凭CI声称真机通过。
