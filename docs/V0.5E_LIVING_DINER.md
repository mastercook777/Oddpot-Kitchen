# 《怪味食堂》v0.5E · 餐厅生命感与真实评价

## 本轮目标（根据 v0.5D 试玩反馈）
玩家不再看四个抽象座位 Indicator，也不再看订单状态的事后动画；让顾客一生动、可观察的餐厅行为形成经营因果。

## 已实现
- **去掉四个座位 Indicator**。仍保留透明的两座位触控热区，点击具体座位可查看对应客人，不再显示四个绿色方块。
- **真实时间线**：预定客人 `waiting` → 从入口走到桌子 `entering`（2s）→ 坐下看菜单 `ordering`（1s）→ 生成点单 `queued` → 工位自动制作 `cooking` → 按独立订单发起飞菜 `flying`（2s）→ 菜落桌、一次性记销售收入 `eating`（3s）→ 按真实风味匹配、菜品质量及等待时长评分 `review`（2s）→ `served` → 沿走廊离店。厨房不会对刚进门尚未落座的客人提前制作。
- **因果分离**：`throw` 表示出锅不代表记账；`landed` 触发一笔销售；`reviewed` 触发评分/口碑；`served` 作为已评价完成的最终可结算订单。避免飞菜未落桌就显示菜品和记收入。
- **客人气泡**：入座短暂说“我看看菜单…”，点单后在头顶显示已选菜，品尝有简绘餐具动作；最后基于品质、偏好与等待说“太好吃了！还想再来！”“好吃！下次还来！”“嗯，还不错。”“一般般，有点失望。”“这个味道不太合我口味。”“等太久啦”等，坏评优先解释真实原因。双人座位气泡错层降低遮挡。
- **员工行为**：跑堂根据入座、点单、收桌（服务结束）事件建立不重叠的往返行程，固定服务通道，每次从固定工位出发并回位；厨房忙时员工有动作，闲时有少量低频环境动作。
- **日报**：记录每份菜的实际点评及其对应评分，挑选前三条给玩家看；和菜谱质量、员工餐强化、厨房吞吐建立可观察关系。
- **暂停**：人物、飞盘、等待、评价、巡逻均只取营业模拟时间，不取 `Date.now` 或随机动画，不会在暂停时重新进入桌子或循环扔菜。

## 测试与边界
- 原 82 项回归用例，升级早期测试以匹配**真实入座后点单**的语义；新增 10 项端到端状态/时序/事务/双人座位/行为数据/路径回归，共计 92 项。
- 390×844、375×667、320×568 移动浏览器：页面没有整体滚动、脚本错误，四个可见占位符已消失，保留四个透明可触控座位区域。
- 旧版 v0.5D 存档安全加载；已完成的旧订单沿原 served 路径离席，不会被强行重新计费；原菜单、锅具、员工和仓库升级不变。
- 仍需要真实 iPhone Safari 长时间试运营验证：文字气泡阅读性、进出路线、玩家观察到的评价密度和经营目标感。
- **不包含**料理研发系统 v0.6 重新设计、新雇员/正式像素美术/更多菜谱。

## 可能的下一步
