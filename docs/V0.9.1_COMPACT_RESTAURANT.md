# v0.9.1 餐厅布局、角色文本和验收

## 目标和边界

本轮是**可玩系统布局重构**，不是单独换一个美术外形。两人桌仍然各有两席，两口锅仍使用原有 WOK/POT 服务 ID，第三个炉台只做可见、不可操作的程序场景物件。保留 v0.9 的扩建权限、账本、销售、真实顾客和存档机制。本轮不增加永久厨具、员工、VIP、额外菜品或正式美术素材。

**世界观包装准则：** 内部可以使用 `RESTAURANT_LORE` 配置「咕噜门廊、热锅正厅、菌灯角落、喷火灶台、待启用怪火灶」的语义 ID，开发与叙事策划可查。**正式 UI 不直接展示这些区域名称**；用户看到的是明确的桌号、座位、锅具状态、待客数、扩建条件以及基于角色身份的对白。禁止为体现奇幻感而额外浮出地名、功能区名或说明牌。

## 坐标契约

权威数据是 `src/restaurant_scene_v075.js`。绝对值是 Canvas 画面宽度/高度的分数；**不能**将新的桌、炉、主厨、顾客、送餐单独写另一套坐标。

| 功能 | 内部坐标 (x,y) | 说明 |
| --- | --- | --- |
| 左厨位 | (0.245,0.240) 炉具 / (0.245,0.325) 站位 | 炉灶最大约 62×51 像素 |
| 预留第三厨位 | (0.500,0.240) | 封闭空灶台，无标签、操作与产线 |
| 右厨位 | (0.755,0.240) 炉具 / (0.755,0.325) 站位 | 与左厨位一致 |
| 出餐口 | (0.500,0.448) | 中央通道及送餐台 |
| 第 1/2 桌 | (0.255,0.745) / (0.745,0.745) | 两人小方桌、服务点靠中央通道 |
| 第 3 桌 | (0.255,0.555) | 仅扩店后出现的左后方位置 |
| 入口 / 等位 | (0.500,0.930) | 座位拥挤时保留排队顾客、没有额外 UI 弹窗 |

双人桌实际方形桌面边长随屏幕宽度压缩，约 39–51 像素；每桌双人座位分居左右。顾客路线：入口 → 中央纵向通道 → 餐桌侧方 → 座位；送餐路线同样连接到 `tableWork`。玩家不能穿越炉具、封闭炉台、柜台和桌面。

## 程序化奇幻感

- 干净的小方木桌、淡色木纹、浅刻纹、左右双人椅，第三张桌旁有一盏小菌灯；不在桌面印入“赶路桌/街坊桌/菌灯包角”等设定文字。
- 厨房左右是明显收窄的两口炉具，中央是一处封闭空炉台，墙上有食材罐及自然灯具。未来开放第三厨位时必须新建独立工位经济/生产逻辑；不能直接把目前的空置绘制当作可用设备。
- 四类顾客的文本和好评/差评现在分别符合铁甲矮人、菌帽一家、史莱姆街坊、幽灵鉴味师的表达方式；文本只解释真实游戏状态。**不允许额外生成虚假的好评或客源收益。**
