# v0.15-F · 跨地区研发快捷入口、烤架美术减噪与云港双跑堂

**日期**：2026-10-21 · **基线**：main / 0.15.0-alpha.5 · **状态**：先行规格，开发实施之前提交

## 玩家证据 / 根因

1. 图鉴「点击配方→快速研发」出现退化：现行 `data-book` 只尝试设置 `selectedIngredients` / `selectedMethod`，不检查真实物料与阶段，跨章节数据只报旧世界无法上架；图鉴按厨具分类但无地区和库存状态。用户要求可按地区查看，当前有料则直接点击进入**真实研发操作**。
2. 截图左上炉台多根彩色立柱妨碍识别。现行场景在两章共享烤架炭架/食材绘制，高竖向装饰像可操作机关，应重绘为低矮水平炭架与串料；如查实是旧墙面非功能柱，同样清理。不能隐藏真实厨位或可用状态。
3. 云港仍像原店以一名跑堂为限。应将「当地前厅繁忙、两人分头送餐」变成可以投资的当地组织配置，不能只给一个静态增益或复制第二帮厨。

## 1. 图鉴：地区与库存双轴

- 保留当前炒锅/深锅/蒸笼/烤架分类，并增加 `当前地区 / 边境 / 云港 / 全部` 筛选，默认当前地区；按每道配方的**本章有效可供应食材**确定唯一地区。跨地区已知菜谱可以查看，不得带到异界非法研发／上架。
- 每道菜展示完整名字（**已学过**的配方；未知仍只提示原线索）、材料余量、厨具是否拥有、当前阶段是否能做；状态 `立即研发`、`缺少XX×N`、`未购入XX`、`仅限另一地区`、`请在研发阶段使用`。旧存档未知菜仍不可泄露隐藏名称。
- 玩家在 **research 阶段**、未在做菜、拥有对应厨具和实际剩余库存足够时，点击 `立即研发` 一键调用原有 `beginLiveResearch`（不跳过真实下料/工艺/消耗）；记录同原交互。若不符合则看得到材料状态且点击不消耗原料，不把异界菜带进研发。
- 状态和按钮每次根据游戏库存/地区重新计算；原 recipeVariants 点击选默认工艺与图鉴客人页不破坏。

## 2. 烤架场景美术

- 将两世界共享的旧烤架炉面改为可辨识的**矩形低矮炭床/平放的双排穿串**，去掉令玩家误以为可点击的四根彩色竖柱/悬高食物块。
- 别误删有功能的物理厨位、工作进度、Lv2 提示或员工交互圈；玩家截图中可操作的炉台仍同位置，两个地区无垃圾装饰。原店暖铜木、云港金属玻璃可以有不同材质，但**轮廓一致作为烤架**。
- 手机视口避让右上炉位订单与角色，不额外制造看似可碰撞的栏杆。

## 3. 云港两名跑堂：独立人员+真实双路送餐

- 保留边境店原有 `waiter` 小芽一人配置；云港保留小羽（`waiter`），新建 **`waiter2`「小澜」**（新制服/头像），**仅云港首枚当地星章后**允许在 `prep/upgrade` 花 **55 当地金币** 单次招募。两跑堂均可按独立 `onDuty` 排班，适用原晋升/员工餐/XP 体系；二号基本工资 **11/15/20**，独立于原店/第一跑堂（不能靠切换世界复制资产）。
- 云港不因新增 waiter2 免费增加厨房生产力/第三厨位，第二帮厨仍保留为独立后厨角色并负责后续第三炉。双跑堂有实际职责差异：小羽优先最近已可取盘订单、小澜优先另一份可取盘订单，并行配送最多各一份；两人忙时取盘等待，不能两人同时拿同一份，亦不能制造第二笔销售。
- 服务每秒 tick 的一条权威 `pickup→delivering→flying→eating→review→served` 状态链继续使用；各跑堂独立忙碌与 2 秒返程冷却，保留原队列公平性和玩家自己拿盘权；记录 `waiter_pickup`/`waiter_return` 的 `role`，送达前不可重抢；按真实 `waiter_pickup` 且最终 `served` 的订单分别计 XP。
- 兼容旧 `deliveryRole` 缺失的在途订单视为一号跑堂，旧 `waiterBusyUntil` 保留兼容，新增 `waiterBusyUntilByRole` 保存于营业快照。若二号不上岗/未雇佣，则旧单跑堂规则保持；二号在场仅获得**较小、独立、真实**顾客耐心基础加成+2s（与一号合计上限仍受已有 cap），核心收益是第二并行配送线路。
- UI 面板显示两名跑堂与实际职能、工资、晋升、排班、喂饭；云港普通服务与休息场景同时绘制两名当地跑堂，第三厨位扩编与帮厨逻辑不破。游戏报告显示二号工资/XP/订单统计。
- 已开始营业/已有旧档的 crew/service 迁移必须默认二号未雇佣，不能追改历史订单、工资/收入/顾客或自动补发经验；原店无二号入口/可聘条件。

## 4. 交付测试矩阵

1. 原店/云港可知和未知食材组合，图鉴地区筛选、物料耗尽/不足、厨具缺失、跨章只读、非 research / 正在研究、原正常下料与变体设置。
2. 两世界烤架去竖柱后的静态 Canvas 路径、三尺寸 Chrome 320/375/390 视觉；原炉台工位等级/进度/碰撞和菜单覆盖不变。
3. 新/旧云港档、同账号跨章返回、购入二号一次/金币55/工资/班次/成长/XP 唯一记录；原世界不能聘二号。
4. 一名跑堂、两名跑堂、二号休息、两盘同时 pickup、超时订单释放、玩家抢先取盘、存档恢复旧在途订单；每单最多一次 `sale-` 事务，二号自己配送才记自己的 XP。
5. `npm test`、`npm run build`、GitHub Actions、离线包、Pages 和玩家真机验收均分别记录，不能冒填。

## 5. 非目标、约束和开放问题

- 不改变研究结果计算、菜谱经济售价、员工角色的历史工资、云港现有星章目标、三炉购买条件、原世界存档 schema 4 或虚构到店订单。
- 不做「第二跑堂自动接待/点餐/清桌」额外提速：现有引擎点餐、清桌在统一时钟状态机中，擅自加速会改变经济与星章难度。此轮真实可量化收益仅并行上菜、可控排班、额外 2 秒耐心；后续考虑接待专精应先跑双章节经济数据。
- 玩家真机视觉、跑堂交互是否有足够差异仍需其亲自验收。
