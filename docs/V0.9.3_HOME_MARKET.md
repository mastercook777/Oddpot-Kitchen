# v0.9.3 · 主页面减法 / 每日进货次数

## 用户实际反馈

主页面餐厅下方两个“厨房配置 / 桌数座位”的悬浮说明条已经与可见场景重复，会遮挡实际的门口窗口。食材采购有经营价值，但当天上架的普通食材仅提供 3–7 份，经过六座扩店后偏紧。

**明确不做：** 不取消随机缺货，不保证四种食材每天齐全，不开放探索/Boss 独占材料的购买，不增加正式美术资产，也不让奇幻内部区位名称溢出到 UI。

## 本轮规则

1. 保持 **4 种可采购基础食材中随机上架 3–4 种**（仍有每日缺货；同一个游戏种子和日期结果可重现）。
2. 每种当天**上架**的材料，可采购的数量从原 **3–7 份**提高到 **6–9 份**。因此至少支持六次「买 1 份」操作。用户可选择一次购买 1 份或 3 份；“买 3 份”消耗相应三份额度，不额外制造库存。
3. 当天已经买过的数量依然严格计入当天库存。迁移旧存档时，先算此前已买数量，再提高单品初始限额，保留当天定价和已经买过的账本；同日刷新不会重开采购。
4. 保持价格原先 ± 浮动以及次日随机刷新；当日缺货行以“今日缺货 · 可探索补充”表达。
5. 首页取消漂在餐厅预览下方的两项“厨位数 / 桌位数”状态条。顶部已有真实座位数字，直接观察布局即可，门外天气和等位窗不再被遮住。
6. 仓库采购页显示当前数量、今日余量、单价以及买1/买3按钮；较窄 iPhone 屏幕为按钮独立保留一行。

## 回归

- 保留 3–4 种的随机缺货事实，而非随机全部上架；
- 被上架的每个材料 `initialStock` 至少 6、最多 9；
- 同一天可对一项食材连续购买 6 次（足够金币），实际物资和资金一致；
- 三份批量采购扣三份额度，不会突破上限；
- 当日已有采购的旧 `market` 存档升级时，不重复赠送物品，不改历史金币和 ledger；
- 首页仍用实时 Canvas `restaurantView(false)`，不再生成冗余小浮层；
- 全量 `npm test`、Vite 构建以及离线 standalone 重打包。

## 未来经营扩展

本改动只是缓解扩店后基础材料偏紧的问题，不是替代神秘商人、特色供应商或口碑经营系统。后续 v0.10 重点仍然是招牌菜、熟客与口碑传播。
