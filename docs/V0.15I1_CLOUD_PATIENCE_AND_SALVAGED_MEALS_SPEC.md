# v0.15-I.1 · 云港等待好感与离店熟菜回收修复

**状态：设计先行，待代码、自动测试和玩家验证**。基线：v0.15-I 开发 PR #92（`main` 仍 alpha.8）；此改动属于正在开发的 alpha.9，不宣称已发布。

## 1. 源码根因
- `CUSTOMERS.cloud_docker.patience=23`，`cloud_weaver.patience=31`；云港实际大部分客群是本地搬运客和云织旅人。用餐满意度 `0.5*fit+0.3*quality+0.2*serviceScore`，等待含门外排队压缩剩余耐心；等待超时直接扣一次当地 `reputation`。不是单纯菜品少自动降满意。
- `tick` 的后厨任务在开工时已经 `consume` 原料并计入 `v.cost`。如果订单 `cooking` 时客人先离开，现有成品在 `job.left<=0` 时仅记 `waste`；如果成品处于 `pickup/carried/delivering` 而客人走掉也不进入预制池。已制作成品浪费使供货有限的云港压力进一步变大。
- 预制机制已经有 `s.prep[recipeId]` + `s.prepVariants[recipeId]`，而下一单会检查匹配 `variantId` 的预制品并免再次扣原料。日终清空预制，不存在跨日冷藏。

## 2. 本轮规则（P0）
1. **只回收已实际完成的普通订单**：客人离开后还在炉上烹饪，等实际完成才进入同营业日预制；菜已完成但未落桌，被客人超时取消，在 `pickup/carried/delivering` 状态当场回收。正在制作但未完成，不得直接变熟菜；未扣食材的 queued/未点单订单不能回收；已交付/飞向桌面/已经吃的盘子不可回收。
2. 回收保存 **真实 recipeId、variantId、ingredientIds、quality** 和原材料对应的出锅品质；后续只有同一 recipe + variant 的实际下一位顾客可领取，不再扣材料和成本；不能跨世界、跨日、跨菜、跨工艺复用。完整精准配对失败时只能重新烹饪。菜单不需要保留在三个栏位外：同营业日新订单仍必须正常上架后才会用。
3. 重复调用、存读档、重复 tick、制作完成的边界时刻都只能回收一次；未完成菜保留原 cooked job，原 station 和 waiter/hero 送餐状态不可卡死。半成品/失败菜、隐藏限量高级菜（premium）、已被食客触及的菜不进入公共预制。无额外 `transact` 收入，`v.cost` 原先已计并且未来复用不再计；日报显示回收、复用、过夜报损的真实份数，避免声称“挽回已成交金额”。
4. **尽量减少被动浪费**：后厨从待做订单选取时先看真正剩余耐心，在同厨具同等可做订单中优先快到期者；不凭空更改菜谱、厨具速度或客人耐心。已进行中的任务和员工走位不强制中断。Cloud 搬运客耐心是否需要从23上调，待计量后调整，不做无证据全局宽松化。
5. **避免无差别“提高好感”**：原客群 `fit` 与 `quality` 原值、实际排队等待、不满/弃单经济、星章真实上菜评分保留；专项经济模拟比较云港流失及库存收益再决定是否加专属外卖/加速设施。
6. **体验反馈**：出锅转入预制池记录 `salvaged_ready` 事件，下一单复用记录 `salvage_used`；日报显示“本晚离席熟菜回收 A 份、再用 B 份、日终丢弃 C 份”，与原预制数量的剩余区分。

## 3. 玩家与技术边界
- 入口不新增管理弹窗、货物或额外币种；现有菜单→备餐→营业→日报显示回收数据，真正工作台产出沿用现有物理工位。
- 复用时保持 `o.craft` 及冻住的顾客评分/价格，熟菜真实品质来自之前那一锅的 `job.quality`；严禁把先前更高工艺售价套到下一位不具有此工艺快照的顾客。
- `s.prepVariants` 必须保持与 `s.prep` 数字同步，不能把损耗后的订单原价算作新销售；回收品有适配字段 `salvaged: true` 和 `cookedQuality`，老 `prepVariants` 继续兼容。
- 旧存档加载中进行的 `service` 若无本轮统计对象，需惰性初始化；不要强制 schema 升级或重置局部进度。
- 在线/离线同源、缓存键及版本统一；PR #92 原有点单、云港本地客与经营事件仍需全套回归。

## 4. 验收矩阵
- 人离店后锅还没煮完：完成后准确回收一次，不发生销售，不退还食材；另一客同菜同工艺能一次性消费预制并实际卖出一次。
- 菜已经在 counter/跑堂手上，原客中途离店：立即回收且不会再从废弃的跑堂状态二次交付/结算；下一客可复用。
- 被取消还没制作的 queued 无回收，失败 cook 无回收，premium 限量无回收；错菜/错 variant 无复用；无第二位顾客时日终按真实余量报损。
- `closeService`/新营业日/switch world/存读档可安全，原交易账本无双扣/双卖。
- 对比相同云港种子、菜谱与客流的真实在引擎中的等待离店数量、有效销售与成本；不把模拟外生添加物资解释成游戏自发产生。
- `npm test`/构建/16组移动CI/离线单文件、320/375/390 各自据实记录，Pages、玩家手机单列。
