## 0. 设计决策摘要

### 玩家已明确确认的方向

1. **不要再重复设计路线取舍**：三段地图、分支选择、安全/危险路线、Boss 及背包取舍已有。下一轮重点是 **区域玩法差异与地图结构差异**，而不是新做路线系统。
2. **全面升级随机奇遇**：神秘商人、神秘 NPC、一次性交易，可能用金币或物资换取真正专供的稀有食材。奇遇必须不止是原有“蘑菇换火椒”。
3. **珍稀食材与食谱一并交付**：拿到专属食材能进行研发，至少有精选专属料理，并能借用现有高价限量隐藏菜单售卖。
4. **地图视觉全面改进**：当前采集物与陷阱容易看混；必须升级生态地形的空间/轮廓辨识，并建立资源、危险、NPC、障碍物的视觉语言。不是换调色盘就完成。
5. **保持三条主循环平衡**：探索的惊喜与风险最终落到研发、菜单选择和真实经营，不把游戏做成纯战斗 Roguelite。
6. **延续“螺旋式打磨”**：本轮探索为主，已有料理/经营底层尽量复用，下一轮再回经营的特殊营业日与新食客。

### 本稿的建议，尚非用户逐项拍板

- **沿用两大区域与八种生态样式**，先强化布局、事件与可读性；不增加第三大地图。
- **首发 2 种新专供食材、4 道精选稀有料理、2 类有交易能力的 NPC 奇遇，加 1 类生态奇遇**；数量可依试玩减法。
- 每次三段探索最多发生 **1 个特殊 NPC 交易奇遇**，不保证每次出现；需要一个避免长期不出的轻度机会保障。
- 新专供食材不能与现有 Boss 材料「菌王孢心」「熔心椒晶」混用来源，也不能被普通每日市场随机上架。

## 2. 成功定义：一段新的探索应给玩家什么记忆点？

设计三种典型体验（均为目标示例，并非已开发）：

**森林采集局**：地面道路清楚，普通采集簇容易看见；远处有一位行为古怪的行脚食客。靠近后出现一次性物资交换，玩家选择把普通材料换成用于高端料理的新食材。回店后研发出新菜，准备下一天的隐藏菜单。

**热泉风险局**：蒸汽裂隙与可采火椒在轮廓上绝不会混为一谈；危险区喷发前能读懂明显的警示期。玩家可选更近但有危险的采集位，或绕开并继续找资源；区域本身改变了走位方式。

**稀有机会局**：玩家途中遇见特定商人并有真实金币预算/背包空格选择。专属商品只在此时购买一次，若没买或买不起，无法靠当天普通市场“补单”。回店后它确实影响研发、利润与稀有菜售卖。

### v0.11 验收的三道问题

- **读图**：不阅读提示文字，玩家能否迅速区分哪种对象能采、哪种会伤人、哪种可对话？
- **差异化**：同样“找食材”的目标，在森林草甸、古树孢巢、蒸汽裂隙与赤焰断坡，移动路线与避险判断是否明显不同？
- **跨系统收益**：至少一次神秘 NPC 交易能否完成 **获得新材料 → 成功结算入仓 → 实时研发 → 新配方入菜谱图鉴 → 作为隐藏菜单候选 → 真正可能售出** 的完整链条？

## 3. 地图差异化 2.0：强化既有八种生态，而不是新增八张皮肤

保留世界单位规模 9×11 和现有三段移动与敌人密度框架；地形结构和生态地标使用相同 data profile 驱动生成与绘制。下面是**建议的设计意图**，不是所有子区都新增一套独立规则：

| 既有子区域 | 读图主体 | 推荐的空间/玩法差异 | 现有来源基础 |
| --- | --- | --- | --- |
| meadow 林地草甸 | 亮色开阔地、弯曲小径 | 低遮挡、视野开阔、资源沿岔路成小簇；适合稳定补货 | meadow 资源分布、路径绘制 |
| glow 幽光菌沼 | 冷色菌冠群、柔和荧光 | 小块安全岛 / 曲折菌丛；可采菌菇必须与危险孢子特效不同形 | glow 菌丛地标、资源点 |
| roots 古树孢巢 | 巨根墙、紫色孢气 | 明确狭道与孢子脉冲的侧向躲避点，奖励在危险边缘但不压在危险圈中心 | roots 障碍 + hazards |
| garden 野蔬采集圃 | 成行菜圃、整齐低植被 | 低风险、密集采集簇和可绕行田垄，让“丰收”体现在采集效率 | garden 丰富资源 |
| spring 热泉浅滩 | 温泉池、浅水环路 | 易观察的泉眼与稳定通道，给初到热泉的玩家学习喷发信号 | spring hazards |
| steam 蒸汽裂隙 | 石板/狭长断裂 | 连续但不同步的喷口与安全间隙，移动时根据预警选择过路时机 | steam 密集 hazards |
| ember 赤焰断坡 | 深红熔岩岩台、尖锐裂边 | 高价值资源靠危险带，开放一条明显的绕行路而非强制受伤 | ember 危险点与敌群 |
| oasis 矿泉晶池 | 冷绿晶簇、池岸阶地 | 安全采集岛与稀疏喷口对照，作为热泉区的节奏缓冲 | oasis 水晶地貌 |

**关键原则**：
- 子区域之间要有 **轮廓 / 路网 / 障碍组合 / 资源簇形态 / 危险规律** 的差异，不能只改 floor/grain/accent 或背景装饰。
- 安全路线依然是可预测补货，危险路线仍然通向现有首领；**不要重新规划已存在的线路抉择**。
- 同一生态的不同种子至少提供两种可辨的资源簇/障碍布局变化，而不是只左右镜像；结构多样性仍需保证可通行。
- \`generateBiomeMap\` 的资源产量、目标节点、敌群、出生位置、Boss 走廊保持同一数据真相，**视觉不可展示实则碰撞的地形，也不能展示能通过却实际被挡住的路**。
- 无障碍路径：玩家出生点到目标采集点、至少一条撤离/终点路径必须可达。地图生成后的碰撞通达检查和安全缓冲是验收硬门槛。
- 玩法要以真实采集/风险取舍为重，不显著延长一段探索的平均耗时，也不在每张地图都增加新的强制战斗。

## 4. 地图视觉语言：采集点、陷阱、障碍物、奇遇对象必须不同

本轮最优先的视觉 bug：**可采食材点与陷阱都像发光圆点，形状和配色容易重叠**。

| 对象类别 | 统一轮廓语言（必须） | 动态/接近表现 | 不应使用 |
| --- | --- | --- | --- |
| 可采普通食材 | 清晰的**食材小像素形状 + 小型椭圆底座/浅色柔光**；外轮廓偏圆润 | 玩家进入既有采集半径后给环形读条/轻微亮边；颜色偏绿、浅金，**形状先于颜色** | 与陷阱相同的三层发光圆点 |
| 高价值/稀有可采物 | 本体形状更独特，外加低调的星点/亮角，不等同于陷阱的脉冲 | 距离接近才有轻微提示；老板可判断背包是否值得留位 | 用巨大闪光遮挡碰撞和敌人 |
| 危险陷阱 | **断裂轮廓、锯齿、开裂纹、警戒斜纹**；平时也明显“危险” | 进入既有真实危险爆发窗口前沿着**真实命中范围**显示明显环形警示；喷发期形状跳动、喷流向上 | 靠“亮度高”冒充危险；只在触发伤害后才告知 |
| 固定障碍 | 厚重、封闭的轮廓与阴影；不闪烁不呼吸 | 仅移动碰撞反馈，造型必须与真实 \`blocked()\` 一致 | 像食材可采物一样发光 |
| 奇遇 NPC/商人 | **可识别的移动角色剪影或摊位轮廓**，不是地上的“？”道具球 | 靠近显示一次性互动图标和可理解的身份提示 | 直接占据陷阱/采集点的底座语言 |

- **统一基础可读性**：即使关闭颜色，仅看轮廓与动画节奏，也要能区分“采集 / 伤害 / 对话 / 障碍”四类。图标中不能只靠红绿区分，应增加符号与形状。
- **表现和伤害状态共源**：抽取 \`hazardPhase(hazard,elapsed,biome)\` 之类的纯函数，供 \`stepActionField\` 的命中判定和 \`drawField\` 的预警/爆发同用，避免“画面显示安全但实际扣血”。沿用既有春泉与 roots 的不同实际爆发阈值，禁止重设计数值只为动画好看。
- **碰撞与层级**：底纹 → 可通行地标 → 陷阱警戒底纹 → 障碍 → 可采物/NPC → 敌人/主角 → 战斗与伤害特效；若警戒圈遮挡材料，则按接近玩家、正在爆发优先。约定 draw order 与 gameplay 坐标一致。
- **视图占用**：所有必要信息尽量画入 Canvas，不用在右侧/底部添加大型文字浮窗；与摇杆、技能键和已有野外背包提示不冲突。
- **美术范围**：优先延用现有 Canvas/程序像素角色；不依赖正式 spritesheet。需要正式美术替换时再单独交接。

## 5. 奇遇 2.0：从一个固定游商按钮，升级为类型化、一次性且可重复游玩

### 5.1 事件契约（通用规则）

\`encounter\` 不等于新的“路线选择”。它是三段探索中的**场内可见实体**，玩家走近后才触发；进入选择对话时继续复用现有 \`f.activeEvent\` 暂停机制。每次奇遇需要：

| 字段 | 规则 |
| --- | --- |
| \`eventId\` | 由当日 cycle/day、段落、zone、种子和局内节点序号确定且稳定；防止重开页面重复刷新 |
| \`kind\` | \`merchant\` / \`traveler\` / \`ecology\` 等显式事件类型 |
| \`offer\` | 本次独有库存、价钱/物资成本、可购买上限；进入后不得刷新内容 |
| \`choices\` | 每个选项要显示真正支付内容、可得材料、占用的背包格或风险 |
| \`status\` | \`available\` → \`resolved\`，选择离开也要消费本次事件；不能退出弹窗无限刷事件 |
| \`result\` | 实际金币/野外背包变化、真实日志和可重现结算；无材料或背包满要明确失败，不得已扣款却得不到货 |

**交易原则**：交易一次即结束，但“可拒绝”不应被视为 Bug；不能通过多次靠近 NPC、切换场景、读档重开无限拿到同一份食材。

### 5.2 首版三类奇遇

#### A. 神秘商人 · 金币换专供食材（首发主角）

- NPC 轮廓为小型行商/奇特背包角色，走近出现“神秘商人”短标题和一张紧凑报价卡。
- **出售本轮独有的一份专供食材**；可以随机展示两款商品中的一款，但**每次只能成功交易一次**。首版不实现完整商城与每天无限采购。
- 必须显示 **金币价格 + 背包占位**；玩家要同时支付金额和留下一个合理背包位置。若买不起或装不下可以离开，但不会在同一场景重新刷货。
- 可试验价：专供材料 1 份约 **16–22 金币**；属于待调优参数，需对照真实隐藏菜收益，不能假设稳赚。
- 商人的商品**不进入现有每日基础市场**，随机缺货规则保持原样。

#### B. 神秘旅人/食客 · 一次性物资交换（首版主角）

- 与行商在外观和对话上明显不同：不是“另一个有折扣的货架”。可能是一位嗜好古怪的食客/草药旅人。
- 提供一次**明确等价信息与风险**的交换，比如“用若干普通野外材料换 1 份专供花蜜”，也可以拒绝。交换在野外背包里扣去普通材料，再把稀有材料放入背包。
- 不能把仓库物品直接拿来交换（当前探索中资源在 \`f.bag\`，不是仓库）；如果要从仓库预带交易品，必须另立未来设计，不偷偷开放。
- 首版一个可复用模板，允许根据生态替换交易材料、文本与商品；不做漫长剧情任务。

#### C. 生态奇遇 · 地图上的一次性发现（轻量补充）

- 示例：森林深处奇异花丛、热泉边的异常晶体，提供**观察后选择**而非“主动踩陷阱”；玩家可安全放弃，或付出清楚的风险换额外资源/食谱线索。
- 先复用 \`type:'event'\` 和既有交互面板，但视觉与商人/NPC 必须不同；具体可奖励普通物资或**新稀有菜的研发提示**，不直接凭空解锁菜谱。
- 不创造独立的第三套“抽卡事件”货币。

### 5.3 出现率与稀缺性：建议试测，不是固定承诺

- **每次完整三段 run 最多 1 次特殊 NPC 交易机会**（商人/旅人二选一），生态奇遇可另有少量机会。避免三段连着出现“同一个神秘商人”。
- 安全区域偏旅人与采集奇遇，危险深区可提高商人/稀有机会权重，但**不能保证进危险线就一定有商人**。
- 首轮建议在 3 次完整探索以内能遇到至少一次值得交易的 NPC 机会；可考虑轻度保底，但必须记录次数并保证种子确定性，且不强制消费。
- **建议调优范围**（仅作为测试参数）：完整 run 出现 NPC 特别奇遇机会约 **35–50%**，生态奇遇约 **20–30%**，不把每局都塞满。
- 不允许固定每日开局立刻必出现；让路线和探索有发现感，而不是变成日常采购操作。

## 6. 新专供食材与菜谱：必须与现有 Boss 产物形成差异

**明确禁止复用命名逻辑**：\`ember_pepper\` 熔心椒晶已经由熔壳椒王掉落，\`mushroom_heart\` 菌王孢心已经由孢冠菇王掉落。本轮**不把它们假装成神秘商人限定商品**。

以下为首版**候选名及数据，待玩家认可与研发试玩**。重点是两种新味觉方向：酸香、花蜜甜香；不继续重复“菌香+辣味”。

| 建议食材 ID / 名称 | 首发获得方式 | 风味差异 | 候选交易 |
| --- | --- | --- | --- |
| \`tide_sour_pulp\` · 逆潮酸浆 | 神秘商人限量交易（\`MERCHANT_ONLY\`） | **酸 / 清爽 / 开胃**，提供现有食材不明显具备的酸味方向 | 约 18 金币购买 1 份 |

- **从研发到售卖必须是真菜谱**：\`ING\` 定义新材料，\`RECIPES\` 手工登记以上四道（\`rare:true\`），\`RECIPE_INDEX\` 正确识别，\`cooking_v063.js\` 的 \`REQUIRE\`、\`AROMATICS\`、\`MAIN_PRIORITY\` 和熟化反馈同步处理新 ID；\`recipe_profiles_v063.js\` 添加必要工艺性格、适配与提示，不能只写名称而忘记烹饪判定。
- **研发解锁**：实际拿到材料后，玩家通过正常 2–3 食材实时研发第一次产出菜谱；不能购买素材就自动解锁四道菜。研发成功后图鉴可查看，并且现有隐藏菜过滤 \`RECIPES[id].rare && s.recipes[id]\` 能纳入这些菜。
- **交易与配方的搭桥**：可通过 NPC 台词/简短研发线索告诉玩家“逆潮酸浆适合鸡肉的爆香”“花蜜适合温和炖煮”，不把配方直接弹出全部答案，更不加长期教程浮窗。
- **普通菜平衡**：现有普通菜和 Boss 菜不被替换；新珍稀菜的初始标价可测试 **约 40–52 金币**，隐藏菜单继续使用现有工艺价格乘 1.7，**不在本版改全局倍率或贵客资格**。综合利润必须扣除商人金币和探索所承担的机会成本。
- **客群承接**：当前客群喜欢 \`清爽\`、\`甜香\`、\`温和\` 等标签；两种新材料的稀有菜至少要命中真实已存在的口味偏好。新增 \`酸\` / \`花香\` 标签可增强特色，但在没有顾客喜欢它们之前**不能单靠新标签虚构额外适配收益**。
- **重点技术陷阱**：现在自动组合生成器是“除了 \`BOSS_ONLY\` 之外所有食材都能生成常规两/三料菜”。引入 \`MERCHANT_ONLY\` / \`ENCOUNTER_ONLY\` 后必须修改过滤器，只对**8 种普通食材**生成海量组合；稀有材料只能走明确策划的精选菜谱，避免一次增加上百道无意义配方。
- 珍稀材料原则上仍**不可从基础市场购买**。若未来加更多来源，用 \`acquisitionPolicy\` 的枚举描述供应，不要依赖“不是 BOSS_ONLY 就可以商店买”的反向推断。

## 7. 奇遇交易的经济完整性和存档安全：优先解决的工程细节

当前 \`f.bag\` 属于探索临时战利品，\`transact()\` 直接影响**永久仓库/金币**。这两者不能随便相互调用。

### 金币购货

1. **先检查**：本次事件仍可购买、金币足够、野外背包有足够格数，专供 ID 已注册。
2. **唯一提交**：使用当天 + run/段落 + \`eventId\` 生成唯一账本 transaction ID；扣金币**一次**，专供材料进入 **\`f.bag\`**，不直接写入仓库。
3. **完成事件**：在同一个决策处理动作中设置 resolved，写入持久 field 状态。退出弹窗、切换场景或刷新后不得再购买。
4. **撤离结算**：仍遵守 \`settleField\`：只把幸存收获按既有 \`field-dayKey\` 唯一交易合并进仓库。探索晕倒时按既有减损规则处理，**商人的金币已经支付，不因撤退自动退款**，页面提前清楚告知“交易品仍在探索背包中”。
5. **不可有半笔账**：库存塞不下时绝不能扣金币。实现必须以完整 preflight + 原子结果写入为准，禁止先付钱后发现背包不足才用易失败的补救事务。刷新恢复不能造成已扣款却没货。

### 物资易物

- 所有换出的基础材料从 **\`f.bag\`** 扣，换入新材料也加入 **\`f.bag\`**；**必须原子交换**并保持每三份一格的背包规则。
- 如果换出物品释放一格后才腾出换入位置，要以**交换后的总堆叠占格**验证，不可用“操作前背包已满”错误拒绝可行交易。
- 处理 \`fieldBagSlotsUsed\` / \`bagStacks\` 同步，旧档 \`load\` 中正常重建，不创建负数、超额、重复堆叠。
- 离开 NPC 不扣金币、不扣材料、不授予奖励；事后不能再次领取该 offer。

### 断线/重载/相同日重复运行

- 事件身份稳定，\`claimed/resolved\` 必须保持；交易价格、商品不会因刷新改变。
- 每个 \`eventId\` 一个实际成功交易 ID，按已有 \`ledger\` 去重。
- 不改变 \`version:4\` 的旧存档键；新增字段可选并在 \`load()\` 温和迁移。
- 现有 Boss 首次/后续奖励不变；专供交易和 Boss 战利品不互相替代。

## 8. 移动端交互与怪味奇幻表达

- **地图中**：奇遇 NPC 有自己的轮廓/小姿势；靠近后暂停野外移动，复用当前事件选择 UI。上半部分一幅简短 NPC 表情/物件提示，下面最多三个可理解的动作：购买/交换、拒绝/离开、查看条件（若必要）。
- **报价可见性**：清楚写“需要 18 金币 → 得到逆潮酸浆×1（放入野外背包）”“当前金币 X”“背包占用 Y/Z”；按钮因无钱/无空间 disabled，并给原因。只显示与该次交易有关的信息。
- **视觉布局**：在 320px 宽、短屏、iPhone 安全区中，不遮挡玩家当前最重要的交互；事件面板让人能确定这次机会会在离开后消失。关闭/拒绝按当前事件生命周期处理，不产生幽灵残留。
- **NPC 与世界观**：NPC 可以怪异、幽默、可辨认，但**不在地图上给每块草地和角落贴奇幻命名标签**。让特殊身份由造型、报价、对话行为体现。
- **语言**：人物语气要符合《怪味食堂》轻松古怪的气质，但一条对话不应取代“多少钱、换什么、怎么放进包”的功能信息。
- **没有正式美术资产**：用现有像素演员结构或 Canvas 临时造型做 MVP，正式立绘待后续专门设计。

## 11. 明确不做什么

- 不重建安全/风险三段线路，不删除现有路线分支与 Boss；不加第三大区或第九种生态作为凑数量。
- 不扩展成传统任务 RPG、等级制战斗、永久地图大世界或独立货币/商人声望系统。
- 不把 Boss 专属材料降级为普通商人的每日供货，不取消基础市场随机缺货。
- 不为引入两个稀有食材生成海量自动组合菜谱，避免破坏已经维护好的研发/图鉴结构。
- 不增加正式像素美术资产需求；UI/图形可通过程序绘制原型达成，正式资源由后续独立任务处理。
- 不在此次把 v0.11 原计划的贵客预约、两种新食客或特殊营业日全部混进探索迭代；它们留给**探索之后下一轮经营主导版本**。
- 不让稀有交易直接生成“已出售”的订单/金币；收入仍须客人真的到店、点餐、出餐、消费。
