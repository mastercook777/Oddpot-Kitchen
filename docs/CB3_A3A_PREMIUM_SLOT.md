# CB3-A3a · 特供占槽与预算一致性
状态：开发中，未开放正式玩家启用。基线 main 2a72cd3f7e7672bd6b143bc2ecf56a9e18bb8ce0（PR166 的20/20 Actions，合并树与测试树相同）。依据 Cooking & Menu Build V2 GDD 第6节；CB3-A2b R2已合入。
## 玩家体验与规则
玩家在真实正式菜单里先选择一个稀有菜收藏工艺，再将其标为当日特供（1或2份）。占用既有Deck槽、完整稀有度Cost；不产生第4/5个免费槽，仍需3道不同菜总数、厨房预算及章节/厨具合格。特供不参与常规客人选择、普通备餐、应急备餐及普通风味共鸣；限定顾客/溢价/库存预留沿用原机制。仍不保证售出。未售不扣食材。撤下特供模式恢复该槽为普通菜，不删除工艺。设置期间若需要变更Deck，先撤下特供再改；波次可换其他槽，不能替换已冻结特供槽，不改既有订单。
## 数据、接口、UI
继续使用premiumMenu（dayKey/recipeId/limit，正式新增variantId）；服务开始冻结特供工艺完整快照。选项只来自当前合法Deck且rare，按真实材料计算库存，禁止未上架/伪造variantId。普通菜池排除当日特供；众星捧月不计其他特供白菜，独门绝技仍计算实际占用厨具的槽；清晨复位普通菜单工艺。正式菜单窗口提供特供入口、槽位标记与限量选项，显示真实配方和Cost，不展示隐藏料理分数；旧模式原隐藏菜单仍保持。使用现有engine、app、cb_build_rules及离线构建，不添加货币/美术资产。保留未激活旧存档和在途旧订单，旧规则不强制迁移。
