# v0.15-C.1 · 云汽蒸笼研发复盘工艺反馈修复

**日期**：2026-10-20  
**性质**：真机截图反馈的研发结果显示 Bug 修复；不新增玩法、不改变配方、经济、库存、星章、工位或存档 schema。  
**基线**：main / v0.15.0-alpha.3；云港返工已合并，[上游规格](V0.15C_CLOUD_HARBOR_REWORK_SPEC.md)。

## 1. 玩家证据与根因

玩家在 iPhone 上制作「雷羽浮苔蒸羹」，截图记录 `0.9s seal`、`4.9s vent`、`7.5s 起锅`，结果显示「云汽匀蒸 · 适合 · 品质 80」，但复盘把 `seal` / `vent` 都标黄并写「未产生对应工艺加成」。这是矛盾的玩家反馈。

源码 `src/cooking_v063.js` 的 `readCookFacts` 已计算 `steamEven`（先封笼、至少 2 秒后排汽且全部材料同锅），`evaluateLiveCook` 将其映射至 `steam_even`、品质 +8。与此同时 `reviewLiveCook` 的操作分支仅认 `flip/toss/gentle/reduce`，其余全部默认标黄并打印英文类型，**遗漏 `seal/vent` 是根因**。`STEAM` 复盘理论上限还错误套用 `POT` 的 86 分，未体现现有蒸笼工艺可及上限。

## 2. 修复规格

1. `seal` 复盘显示 **封笼**，绿色：明确解释对成熟速率和食材熟化的实际帮助，不虚构独立的品质 +8。
2. `vent` 复盘显示 **排汽**；若匹配现有 `readCookFacts` `steamEven` 规则，则绿色并标注「云汽匀蒸 · 品质 +8」；若提前不足 2 秒或缺少必要工艺，则黄色并指出原因（现有 `steam_dry` 对品质 -7），不作假阳性。不要重写真实研发判定算法。
3. STEAM 复盘达到现有真正可及的满分时应提示已达上限，不再错误继承深锅 86 分；有可能凭真实提前底香额外 +4 的配方需保留上限空间。
4. `WOK` / `POT` / `GRILL` 的既有判定和评分不改，保留已研发配方的品质和工艺效果。
5. 线上版更新缓存查询版本，离线包同步；不改旧存档、不追改已记录的销量/订单/财务。历史 `lastCook` 记录在重新打开复盘时也可正确显示。

## 3. 回归验收

- 使用玩家同款 `sky_moss+storm_egg / STEAM`，两料先投、`seal@0.9`、`vent@4.9`、`finish@7.5`：出锅实际品质/工艺保持 `80/steam_even`（材料熟透时），复盘两操作为绿色/中文且解释与加成一致。
- `vent` 距离 `seal` 不足 2 秒：结算 `steam_dry`、品质扣 7、排汽复盘黄色，不伪报 +8。
- 仅 `seal` 不 `vent`：没有云汽匀蒸 +8；封笼仅显示熟化帮助；`STEAM` 最高分可达判断正确。
- 抽样 `WOK` 和 `POT` 旧动作、烤架分支与真实可售状态，不影响原先 UI 或结算。
- `npm test`、`npm run build`、离线打包及浏览器/Pages 实际验证分别记录；未经 iPhone 重新体验不得称玩家验收。
