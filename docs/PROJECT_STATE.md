## 游戏定位

一款移动优先、9:16 H5 奇幻美食经营游戏。三个互相支撑的循环：

- **餐馆经营**：真实顾客进店→厨房制作→玩家/员工送餐→就餐评价→营业收入和声望→扩店/升级。
- **料理研发**：自由选 2–3 种食材 + 炒锅/深锅，实时投料与对应动作；成品品质、工艺、所用食材和菜谱配对可影响经营、员工餐与探索便当。
- **食材探索**：三阶段场景与 Boss，WOK/POT 不同武器姿态、采集与背包、撤离结算，珍稀食材进入料理循环。

## 约束与技术债

- 老存档的键 `oddpot-prototype-v04`、存档 schema `version:4` 沿用；新内容需向后兼容，幂等交易与快照一致。
- 顾客只在其真实订单完成/实际上桌时产生相应销量、满意度和口碑；**不得创造虚构客流、虚假交易、隐藏库存或瞬移出餐**。
- 竖屏窄尺寸 iPhone 优先；UI 精简、可滚动、不挡摇杆、重要按钮和气泡；内部区域设定名称不得在界面硬展示。
- 没有正式坐姿美术动作时，当前就座效果以位置覆盖和椅沿遮挡呈现。自动测试通过不等于真机视觉验收。
- 已实现的智能库存检查**只是需求估计**，不能宣称预测了真实具体顾客的菜品选择。
- 现有 3 日 `cycle/day` 用于存档兼容，UI 显示累积营业天数；后续系统应兼容该机制，不随意重置玩家已运营多天的餐馆。

## v0.10.0 版本说明与体验边界

- [设计确认记录](V0.10_SIGNATURE_REGULARS_DESIGN.md) / [功能 PR #31](https://github.com/mastercook777/Oddpot-Kitchen/pull/31)。自动回归包括稀有供货保护、顾客准入、隐藏菜从厨位到真实收款的端到端交易、日报统计和 320px 样式结构；**自动测试通过不等于 iPhone 实机 UI 已验收**。
- 只有当日有限量且库存足够才会确保计划里至少一名合资格食客；这名客人依然可能因口味不符、等位/出餐失败而不购买。
- 当日 1–2 份是最大接受订购数，而不是已经卖出的菜；日报显示接单数与真实售出数，避免混同。未成交不会假记收入。
- 具名常客每个客群只在真实访问/用餐后积累关系，不能自动把旧存档第20天的声望换成熟客等级；旧版本存档 schema=4 不变。
