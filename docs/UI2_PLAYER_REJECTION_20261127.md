# UI2 玩家真机拒收 · 2026-11-27
对象：Pages `ui2-preview/`，快照 cedaf32，用户 iPhone 六张截图 IMG_4609/4610/4611/4612/4613/4614。PR163 CI 最近已结束 7/20 通过、13失败，禁止作为正式版本合并。用户明确：不但未比全流程UI工坊2.0更精细，连概念都没达成。将本次判为拒收，不能以架构代码或测试代替真实视觉验收。
## 逐项验收缺陷
1. 野外：盾状态压血量、回店底栏压固定摇杆/技能，操作区域不成立。必须分别保留上方HUD、底部动作、左右移动/技能专属区域，命中不重叠。
2. 菜单：实际进入2D，顶部版本覆盖阶段，底部提示叠字、主按钮占宽失衡。3D y2Eligible 不含 menu 已确认；menu/prep/forecast 同一餐厅应保留3D，无故降级禁止。首次引导与瞬时提示、常驻提示互斥。
3. 营业：靠近厨位提示纵贯场景；旧bottom+新top同时生效导致高度拉伸。真实交互提示必须短小单行/双行，位于独立锚点，不遮玩家/炉/桌；四状态+设置/账册等HUD不得重叠。
4. 打烊：全屏羊皮纸导致餐厅不可见，营业HUD仍显示，和工坊紧凑结算卡矛盾。只用单一实体结果卡，在同一餐厅显示，禁背景按钮，隐藏重复HUD；不要重复今日打烊→日报两次结果。
5. 日报：长报表几乎占满屏，标题被HUD挡。主结果以工坊result-hero大数值+3个指标+简明反馈为基准；完整账本和评鉴/晋升等细节进独立窗口或主动展开，必须保留真实数据，不减功能。窗口默认高度不超过可用视口约65%，极短屏内部滚动，头脚固定。
6. 成长：桌位统计压金币，提示压行囊/总览。统计并入HUD或单独空间；热点图标化、44px触控，不把金色标签大面积盖场景；固定底栏和提示分区。买前确认，实际引擎几何更新。
## 根因与修复方法
旧 app.js 的phase页面、全局旧CSS位置规则和新增formal_ui_v2.css共用选择器，局部覆盖而未定义各层独立布局契约；例如 v4d-service-guide 同时 top/bottom。y2Eligible 正式3D未覆盖menu。旧 toast/guide/HUD与结果窗在不同叠层，inert不等于视觉隐藏。工坊使用明确 #world/#hud/#dock/#hint/#play-controls 和原生dialog顶层；实际迁移应以这些边界/视觉比例为准，不再仅换颜色、叠选择器。
## 发布门槛
先建立并落实实际UI层的尺寸/层级契约，再逐场景迁移；以工坊实际截图/代码为参考，正式版进一步雕琢，不复制实验夹具、快进、临时玩法。研发排除。正式引擎和存档冻结。必须在320×568/375×667/390×844及Safari/WKWebView实际可用区域截取前后对照，至少验证六张拒收场景；3D菜单真实canvas、提示条高度、HUD/底栏/操作区交集、结果默认高度与真实值、旧功能及2D降级。无真实浏览器截图不宣称视觉验证。玩家亲自测试前只更新独立预览，正式main不受影响；正式合并仍需全部CI通过。
