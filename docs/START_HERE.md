## 每轮固定工作法：规划先入仓，开发后动手

- 先检查 `main` 当前代码、存档结构和已有交接文档，判断是否已经实现类似能力。
- **任何新经营内容/玩法、重要 UI 重构或经济规则变更**，必须先在 `docs/` 中创建/更新版本化设计稿，明确玩家体验、现有系统衔接、UI 占用、数据/数值、安全边界、测试、验收和未定问题。设计应先提交到 GitHub 可供新对话读取。小型纯 bug 修复可以在同一 PR 写精简修复记录，不必扩写 GDD。
- 在文档用状态显式区分：`草案（待讨论）` → `已确认待实现` → `开发中` → `已实装待真机验收` → `已验收`；**合并成功/CI 绿灯 ≠ iPhone 体验验收通过**。
- 真正实施时，代码 PR 应引用设计文档，并把实际发生的偏差回写；合并后刷新 PROJECT_STATE 和 ROADMAP 的状态。
- 玩家提出新方向优先更新规划文档，**不能只在聊天中描述计划**；新对话时以 GitHub 计划为衔接依据。
- 需要 Codex 的情形按用户当次要求处理；**不涉及正式美术资产的功能，优先直接实现**，不自动转交 Codex。

## 明确的体验原则

《怪味食堂》是**餐馆经营成长 × 料理研发 × 奇幻取材探索**，不是刷更高参数的纯战斗 Roguelite。经营成果必须在真实顾客、实际客流、利润、店面与员工协作中可感知。奇幻感来自 NPC、器物、口吻和行为，**内部空间设定名不要因为强调世界观而出现在玩家 UI**。尽量少浮窗，保持手机竖屏阅读清晰。

**当前开发优先级**：E.2 非像素特效先于全生态重绘；F 按森林、水域、危险地貌分批，再做完整两区三段复验。B2 怪群与 C 商人/专供料理仍保留在 v0.11 后续路线，不能混入本次纯美术对照。详细交付、旧档与验收见 [V0.11E2_F_EXPLORATION_ART_STYLE_AND_ROLLOUT.md](V0.11E2_F_EXPLORATION_ART_STYLE_AND_ROLLOUT.md)。B1 空间/镜头已实现，旧 9×11 进程保留原几何；E.1 目前只覆盖香草小径。
