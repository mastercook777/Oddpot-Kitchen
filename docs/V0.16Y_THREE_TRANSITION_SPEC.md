# v0.16-Y · Three.js 视觉转向
2026-11-24 · 玩家在 X.3 实机后决定停止像素人物尝试、转向 Three.js。X1/X2/X3 与 A2.1 保留历史，不再推广像素资产、Canvas HD 或像素化 3D。正式游戏尚不迁移。
## 目标
原生平滑风格化 3D：温暖的微缩奇幻餐馆、清晰轮廓、圆润有性格的角色、细致的木石金属材质。不要 voxel 方块拼接，也不追求写实。以固定正交斜俯视为默认，保留触控、空间可读性。
## Y1 可玩美术样板
独立 visual-lab 默认进入 Three.js，保留旧 Canvas 对照；改善相机斜俯视和构图、圆润木质家具与灯具、真实程序模型的主厨（帽、蓝衣、红领巾、围裙、脸、手臂、脚），角色方向、步态与轻微待机；昼夜、火光、共享实验布局和点击移动保留。新增独立 model helper，不直接修改正式引擎。依赖固定版本 Three.js CDN，联网/WebGL 失败提示并回退。未承诺首轮即达到商业美术品质。
## Y2–Y5
Y2 资产生产规范与真实餐馆运行切片（桌位/锅位/顾客/员工/扩建/服务），建立 renderer adapter，从现有状态映射 x,z，不复制经营逻辑。Y3 晨露森林 3D 切片，保留原二维逻辑、战斗判定和地图生成，验证遮挡、相机、掉落、性能。Y4 料理研发/菜单世界化、成长反馈及 UI；Y5 双世界迁移与低端性能/离线交付，保留旧 2D renderer 作为可回退路径直至验收。正式保存/经济不迁移，不改玩法；分阶段确认。
## 验收
Y1 优先看人物不是机器人、场景非积木拼装、相机清楚、移动/昼夜可用。320/375/390，iPhone/Android 实机 FPS 与触控；无外部图像资产；可回退 Canvas，不读写正式存档。实际测试、发布与主观验收分别标记。Y1 未验收前不批量迁移正式游戏。
