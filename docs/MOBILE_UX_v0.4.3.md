# 《怪味食堂》v0.4.3 · 手机 UX 全面检查与修复

**基线**：v0.4.2。**性质**：仅布局、文字、信息层级、移动端操作可读性与滚动状态；玩法不改，沿用存档 `oddpot-prototype-v04`。

## 用户发现的问题

- 实际 375px 手机上探索出发页出现目标食材横条、地区 Tabs、路线卡重叠，地图装饰在文字背后；导航阶段层级重复。
- 部分系统依靠 9–11px 小字和窄按钮区分操作；和固定一屏手机游戏的体验相悖。

## 本版实施

1. **探索出发页**：重建线性结构「① 目标食材、② 地图、③ 路线」，删除旧绝对定位内容；顶部只保留一句说明，安全/高风险卡有明确危险标签、路线标题及资源预期。背景森林装饰降低亮度，不遮文字。
2. **所有屏幕信息层级**：固定 HUD 显示金币、声望、当前日和阶段；文字从强调到描述明确分级（标题约 18–21px、主控与重要标签 13–15px，次级说明原则上不低于 12px）；主要操作区域与长内容区域区分。
3. **菜单/研发/备餐**：重新分配小屏高度；双工位与套餐共鸣无需滑动整页即可看见；备餐项字号、可点击热区和前后库存信息更清楚。
4. **营业与事件**：短屏波次决策用 2×2 按钮格替换四个小按钮；事件卡可完整呈现所有选项；事件选择、继续迎客保留原行为。
5. **弹层**：图鉴、仓库、换菜与设置统一标题与可点击列表密度；超出屏幕只允许弹层内部滚动。
6. **连续点选体验**：保存目标食材横向条的滚动位置；长表单/图鉴重新渲染后保留当前滚动。

## 手工浏览器验证

- 在 Chromium 使用 Playwright `set_content` 加载独立单文件版，模拟 **390×844、375×667、320×568**。
- 从今日情报进入探索准备，选择不同目标、地区，跳过探索进入研发、菜单、备餐、开店；检查按钮实际点击和 JavaScript 异常。
- 额外检查 320px 菜单的套餐共鸣没有被底栏遮住，事件卡的全部 3 个解决方案可见，横向食材筛选重绘保持滚动位置。
- 全程 `documentElement.scrollHeight === innerHeight`；无顶层滚动与页面脚本错误。
- `npm test` 原有 **47 项**纯规则测试仍通过。

## 不覆盖的范围

- 游戏主体配色与像素人物美术仍为原型；不是完整 UX 设计系统或正式视觉资源。
- 不改动探索碰撞、菜谱、经济账本、事件决定结果和当轮挑战规则。
- 真机 iPhone Safari 的字体细节、点击误触和较旧设备帧率仍以玩家体验为准。
