# v0.10.2 · 图鉴拆分为「菜谱 / 客人」及熟客关系可视化

**状态：v0.10.2 代码已实现、GitHub 自动回归通过；iPhone 真机视觉与触摸待用户验收。**  
**基线：main v0.10.0 / v0.10.1 完成后再重新检查源码。**

## 玩家目标
v0.10 已实现熟客身份，但玩家无法查看见过谁、喜欢什么、真实高分消费进度和是否可看到隐藏菜单。图鉴应该成为**经营成果陈列与下次选菜单依据**，而不只是身份插画列表。**本功能属于 v0.10 的完善，不占用 v0.11 版本号**。

## 信息架构
- 原有「图鉴」入口保持不变，复用现有 `overlay='book'`，顶部显示两个**切换页签**：「菜谱」与「客人」；默认菜谱，保留原有菜谱配方、工艺变体的所有选择行为。
- 「客人」首先按现有四个客群提供**短卡片**：铁甲矮人、菌帽一家、史莱姆街坊、幽灵鉴味师。使用现有像素人物系统的身份逻辑、已有图标/emoji；不生成正式美术资源，不随便编造新增身份。
- 真实见过的客群可显示名称、口味偏好（直接来自 `CUSTOMERS[segment].likes`）、基本介绍、可否天然点隐藏菜。未遇见显示“未遇见”轮廓/锁定概要，避免所有图鉴开局全亮；满足一次真实入场后显示资料，不要求已成功成交。
- 与客群分离的**具名代表进度**：现有 `REGULAR_GUESTS` 三名稳定 id，首次真实来访登记已见，之后每次真实满意消费记录 `visits`、`happyMeals`；只展示真实数据。达到 2 次满意 ≥80 后显示“隐藏菜单资格已解锁”，未达标显示例如“满意用餐 1/2”。
- 幽灵鉴味师直接显示“天然有资格”，不虚构其 `guestId` 或熟客好感数据。没有出现过的具名熟客状态显示未结识。
- 可加 1–2 句角色性格描述以增加怪味奇幻感，但不能把内部区位命名当 UI 装饰。不得引入多层收藏玩法、礼物/社交树或虚构“传闻销量”。

## 真实数据来源
- **客群相遇记录**：新增可迁移 `guestDex.seenSegments`（字典）或等价状态，**只在真实顾客到达/入场时**按稳定 segment 记录，不靠随机渲染或访问图鉴登记。
- **具名身份**：现有 `s.guestRelationships` 只在真实结算写入；客群“见过”与具体人“成功消费”是两种不同事实。保留 v0.10 现有关系结构、阈值、唯一交易 id，无须清空旧档。
- **老存档**：若已存在 `guestRelationships` 中有真实 visit，则反推该客群已结识；既有历史 `s.history` 不够精确时绝不凭空伪造曾经见过的客人。
- 不改变现实顾客选择、定价、等待、收入与厨房规则。菜单、图鉴、员工/商店继续使用原 overlay 生命周期。

## UI/验收
- 320px 竖屏：两页签置于弹窗标题下方，高度约 40px，不再新增第二个主页面入口。卡片纵向滚动，客群标题一行、偏好与关系用 1–2 行，不出现横向溢出与低对比度说明。
- 选择菜谱既有 `data-book`、`data-choose-variant` 事件不变；切换页签不改变菜谱、游戏阶段和存档。
- 真实客人入场一次才解锁客群；未见客人默认隐藏；关系进度只因真实满意用餐增长，重复结算/刷新不增长。
- 自动测试字段迁移、未入场/已入场和老档关系回填、UI 页签、长姓名、手机尺寸 CSS；完成后单独提供真机试玩验收。
