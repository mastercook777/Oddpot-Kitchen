## 动效实现

| 厨具 | 触发动作 | 真实视觉反馈 |
|---|---|---|
| 炒锅 WOK | `flip` 翻炒 | 食材在炒锅里绕锅沿均匀翻动，锅体轻摇 |
| 炒锅 WOK | `toss` 颠勺 | 锅体倾斜抬起，食材抛起并回落，模拟抛物线 |
| 深锅 POT | `gentle` 轻搅 | 食材缓慢环绕，汤面短暂荡起水纹 |
| 深锅 POT | `reduce` 收汁 | 汤面逐渐缩小，蒸汽增强；**收汁结束后汤面保持收缩** |

现有每份食材下锅仍是一个 `span.v063-food-icon[data-live-icon]`，没有克隆、残影贴图或离屏 Canvas 辅助层；整锅只保留一份静态的锅体、汤水、光效、水纹与动作文字。所有动作和食材位移由 `src/cook_motion_v063.js` 的纯函数 `livePanMotion(cook, dimensions)` 根据 `s.cook.elapsed` 和真实事件计算，再在 `src/app.js` 的原有 `requestAnimationFrame` 中映射回 DOM。**CSS 禁止食材节点自身叠加变换动画或过渡**，避免之前试验版的 transform 冲突/重影；蒸汽 CSS 动画只改变透明度，位移由 JS 统一负责。

- `src/cook_motion_v063.js`：动作时长/姿态/食材弧线/收汁状态；每次返回的 `items` 数量等于 `c.dropped.length`，且每项唯一。
- `src/app.js`：锅体视觉元素、动效同步和动作提示。只渲染当前下锅食材，未下锅的菜不会出现在锅里。
- `src/cooking_v063.css`：锅面汤汁层、水纹层、光晕层、动作提示层、图片防重影约束。
- `tests/v063c_motion.test.js`：验证四种动作姿态显著不同、确定性重放、食材数无复制、收汁液面不反弹、无旧的第二套逐帧变换。
- `index.html`：使用 v0.6.3-C 页面与资源缓存键；`scripts/build-standalone.py` 及 `standalone.html` 同步包含新模块。

## 不改动的玩法与兼容边界

- 厨具动作时机、研发计分、熟度、失败、真实原料扣除与工艺词条规则完全沿用 v0.6.3-B；**动画反馈不偷偷给额外品质/价格 Buff**。
- 图鉴、经营订单快照、员工餐、探索便当和旧存档完全保留。
- 每份食材只在物理上一个 DOM 节点里改变 `transform`，不通过在帧循环里 `appendChild` 复制素材。
- 页面被重新渲染、用户快速点击动作、自动起锅、切入后台恢复时，动作姿态由模拟时钟推导，结束后自动回归正常慢速翻滚。
- 动作演出约 0.9–1.55 秒，但可以与下料、真实烹制时钟并行，不引入回合制或精确 QTE。

## 待用户真机验收

1. iPhone 390×844、375×667、320×568 下四种操作均看得清锅体和食材，动作提示不会挡住主按钮。
2. 快速连续按不同动作、不停投入食材或切后台再返回时，不出现重复食材、叠影、食材凭空消失。
3. 深锅收汁后汤液不会自行恢复原高度；新下的菜不会参与它入锅前发生的颠勺。
4. 研发可正常起锅与进入成果结算页，营业与图鉴正常运行。

> 自动测试与构建不能完全替代 iPhone Safari 的真实动画流畅度和触屏性能验收。
