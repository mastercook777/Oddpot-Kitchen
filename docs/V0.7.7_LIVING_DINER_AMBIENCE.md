# 《怪味食堂》v0.7.7 · 会说话的餐厅（轻量环境氛围）开发交接

**开发日期：2026-10-12**  
**状态：** 已接入正式 \`main\`，体验仍需 iPhone Safari 真机检验。新版不改经营计时、任务、交易、库存、顾客耐心和存档数据结构。  
**正式 H5：** https://mastercook777.github.io/Oddpot-Kitchen/

## 背景与目标

用户反馈 v0.7.6 的整体操作比旧版有趣，走位经营方向成立，但 v0.7.5 厨房全 Canvas 重绘时**原本的顾客对话气泡被遗漏**，餐厅显得缺少生活气息。要求继续改善氛围，同时必须遵守“**UI 不妨碍 UX**”。

根因：\`src/scenes_v04.js\` 已有旧版的 \`guestSceneBubble\`、\`dinerBubbleLayout\`、\`drawReviewBubble\`，但 \`drawDiner()\` 在 \`walkable\` 分支直接使用全新的 \`drawRestaurantV075()\`，没有使用旧的气泡渲染流程。直接将旧的 2–4 个大气泡放回新场景会压住现实走位、餐桌与快捷键，因此采用**新经营专用的克制版**，旧自动模式代码不动。

## 真实实施

### 1. 顾客真实状态对话（只读）

\`src/diner_ambience_v077.js\` 的 \`diningSpeechCue(order,t)\` 由**真实的订单字段**派生短暂对话，不随机创造情绪或新订单：

| 已有真实状态 | 候选短对话 |
|---|---|
| \`ordering\` / \`seatedAt\` | 看看今天吃什么… |
| \`queued\` / \`orderedAt\` | 来一份 **真实点中的菜名**！ |
| \`cooking\` / \`started\` | 厨房好香呀！ |
| \`pickup\` / \`pickupAt\` | 闻着好香呀！ |
| \`carried\` / \`pickupAt\` | 是我的那份吗？ |
| \`delivering\` / \`deliveryAt\` | 我的菜来啦！ |
| \`eating\` / \`landedAt\` | 我开动啦！ |
| \`review\` / \`reviewAt\` | 使用真实 \`order.reviewText\`（已有品质、等待、客群适配评价），不捏造好评 |
| \`left/rejected\` / \`leftAt\` | 等太久了… / 没有想吃的… |
| 低耐心 | 根据真实 \`patience - (time - arrival)\`，临近放弃时才说“等得有点久啦…” |

这些短句只在相应的 1–2 秒窗口出现，时间来自**和营业相同的模拟时钟**；暂停/后台不推进，不另外引入持续跑的对话 timer。

### 2. 画面约束：对话让位给操作

- **一张桌最多一个气泡，全厅同时最多两个**。两张桌只有都发生有意义事件时才同时说话，一般闲聊只显示一个。
- **最多两行、16 个字符**，长实际评价末尾省略号，不能变成遮盖整张桌的大阅读面板。
- 气泡**只绘制在现有 Canvas**，没有创建新 HTML 元素、悬浮 DOM 命中层、点击事件、指针拦截或需要关闭的弹窗；动态摇杆和主厨技能保持正常。
- 坐标跟随真实顾客的 \`actor.x/actor.y\`，限在对应的左右半区；优先在已坐稳的位置出现，不在餐厅中央行走时铺大气泡。轻微淡入淡出，不闪烁/滚动。
- 说话的顾客**暂时不重复显示头顶订单 emoji / 评价 emoji**；桌面当前需求和耐心圈始终保留，不损失实时经营信息。
- 差评使用克制的暖红色，其余奶油白，无霓虹装饰。角色仍使用原 \`DINER_ACTOR_SCALE=1.13\`，不放大主角或 NPC。

### 3. 不加 UI 的场景生命力

\`src/scenes_v04.js\`：顾客 \`eating\` 时加入极轻微吃饭身体浮动和餐具手势；订单实际进入 \`eating\` / \`review\` 才在桌上出现相应的食物盘，刚刚真正送达时只有不超过 0.8 秒的两点小亮光。**不加常驻 UI、任务条、金币加成或第二套订单进度**。原有厨位蒸汽/送餐人员动作继续保留。

### 4. 版本与打包

- **游戏内** \`ODDPOT · v0.7.7\`、设置内版本、\`package.json\`、\`index.html\` 里的标题与入口脚本查询 \`v0.7.7-ambience\` 同步。
- \`src/app.js\` 对场景渲染器的 import 查询升级为 \`scenes_v04.js?v=0.7.7\`，避免 iPhone Safari 虽然加载新 app，却继续用旧场景 JS 而看不到任何气泡。
- \`scripts/build-standalone.py\` 和 \`standalone.html\` 已纳入新的 \`diner_ambience_v077.js\` 代码，离线可玩包与 Pages 一致。
- \`tests/v077_diner_ambience.test.js\` 增加真实菜名、催单耐心、真实评价与差评、同桌仲裁、屏幕密度、短时淡出、纯只读以及入口版本/缓存等回归；旧 \`v075/v076\` 版本断言已同步。

## 注意与下一步人工体验验证

- 需要 iPhone Safari 连续营业一晚观察是否真的能看到点单/端盘/吃饭/评价短句，**且不能遮挡灶台进度、出餐台或摇杆**；重点测试双人桌两个顾客、两桌一起点餐、长评价文字与低耐心。
- 需要确认小尺寸 320×568 的实际屏幕边界；Canvas 渲染与检查值通过不代表布局经真机验收。
- **气泡不是常驻 UI**：为了让餐厅“活”起来可以增加意义明确的微演出，但不能再堆叠大气泡、常驻新闻横幅或虚假的情绪数值。
- 保持不变：真实经营 \`sale-orderId\` 唯一账本、菜单/料理工艺效果、顾客真实心情、主角移动与精力主动技能、员工配送路径、原有 save key。
