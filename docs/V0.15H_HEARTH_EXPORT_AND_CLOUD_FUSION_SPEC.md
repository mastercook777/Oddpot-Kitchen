# v0.15-H · 旧餐厅航运委托改为边境食材出口 + 云港融合料理

**状态：已确认待实现（用户 2026-10-22 直接纠偏）**  
**基线：main / 0.15.0-alpha.7**  
**前置：** [v0.15-G](V0.15G_FERRY_CARGO_AND_SCENE_PROP_FIX.md) 的四柱修复、八份/次、三个可选货箱、一日一兑、真实销售获券均保留。

## 1. 玩家指出的问题与设计原则
旧食堂通过真实营业取得的航运委托，在云港却兑换当地本就容易探索采集的云谷米、浮苔叶、酸铃果和雷羽蛋。仓库源头和产出不符，也稀释新世界野外探索价值。

**修复目标：** 航运委托只兑换旧世界的常规食材；云港当地材料继续通过本地探索/市场获得。旧菜图鉴可以查看，但旧菜不能跨章直接上架。进口旧料必须与云港新料形成**真正能研发、上架、生产、销售**的融合菜，让返回旧食堂营业提供独特价值。

## 2. 货箱：旧世界三选一，每箱八份
| 套餐 ID | 名称 | 进口旧世界材料 | 本章料理价值 |
| --- | --- | --- | --- |
| `spice` | 边境香辛箱 | 喷火椒 ×4、跳跳蒜瓣 ×2、琥珀洋葱 ×2 | 火椒云谷饭、蒜香雷羽蒸蛋；洋葱原有云港料理可用 |
| `forest` | 林地菌香箱 | 幽光蘑菇 ×4、咕咕鸡肉 ×2、琥珀洋葱 ×2 | 浮苔菌香浓汤；鸡肉/洋葱可用于原云港料理 |
| `hunt` | 荒野野味箱 | 铁角野牛肉 ×4、地精土豆 ×2、咕咕鸡肉 ×2 | 酸铃炙牛、云米薯煲；鸡肉用于原云港料理 |

只有旧世界八种常规材料可出现；Boss、稀有奇遇、金币、云港当地材料不在货箱中。暂继续原“真实成交一晚生成一张委托→云港当日兑现一箱”的合同。**委托代表边境供货商的调拨权，而不是从原食堂已结存的仓库自动扣除八份**：因此保持两地本地库存隔离、旧档不丢失库存。后续双章审计必须检验此八份供给是否过量，再决定需要采购成本或原库存真实转运。不得将当前券兑换当作二次现金购买，也不得复制既有老店库存记录。

旧 `staple/steamer/tangy` 方案只存在于历史账本；旧版已兑换当天不能重新领，未兑换的老券可选新货箱。对旧外部调用 `redeemFerrySupply(s)` 使用新的 `spice` 默认，失效旧 ID 不得产生副作用。

## 3. 云港融合料理：只研发新菜，不复活旧菜单

价格、时长、顾客适配需实际试玩/经济审计验证，本轮数值是**初始配置而不是已平衡结论**。所有新菜都至少包含一项本地材料；现有旧世界纯材料菜即使全部进口也不能在云港上架、制作员工餐、藏入限量菜单。新菜须经真实研发/耗料/解锁后上架，结算同一营业账本。不会在云港生成通用两三食材笛卡尔积配方，也不让本地探索直接掉出旧世界特色材料。

## 4. 玩家操作与 UI
原店真正成交 → 日报获一张边境航运委托 → 经传送门到云港 → 打开现有采购抽屉选旧料货箱（显示“旧世界进口”、库存和每箱真实八份）→ 从云港当地探索获取另一半材料 → 在真实料理研发中解锁融合菜 → 当地菜单选择、配置对应厨具、真实接单扣料销售 → 日报复盘。旧菜图鉴仍只读。云港初期开局和不兑换货箱时原先八道当地菜可照常研发，不能软锁。

现有货箱布局与触控命中不新增弹层，320×568/375×667/390×844 核验；旧店日报文案要强调“供货委托/边境食材”，不是凭空给云港材料。

- `src/engine.js` 修改 `FERRY_SUPPLY_PACKS`、云港材料允许集合；菜谱边界仍要求“至少一个云港原生材料+全部材料获准”。`transact` 使用既有单日 ID `ferry-supply-${cycle}-${day}`，一次入货、扣一券，不改存档 schema、不修改旧店另一本账。
- `src/app.js` 改三箱说明、结算提示；实际旧料进云港库存后出现在研究材料选项；图鉴按“云港”分类五道融合菜。
- `standalone.html` 必须和主线一致，按 `scripts/build-standalone.py` 的模块拼装结果维护；版本号、缓存键、源码和离线一致。
- 不增加跨章材料任意交易入口、员工搬迁、旧菜重新可售、强制教程或第二扇门。

## 6. 可复现验收矩阵
1. 三箱精确八份、全部来自旧世界常规池；不存在云港材料、Boss、金币，错误 ID 与无券拒绝且零副作用。
2. 一次真实旧店营业销售仅生成一张券；无销售不生成；云港一日最多一券，重复点击/刷新/跨章不重复兑；旧档已领旧三份不能二次领取，未兑换老券可兑换新箱。
3. 五道融合菜 `liveRecipeId` 指向正确配方，均是“至少一项旧料 + 一项本地料”，旧菜在云港不可菜单/备餐/员工餐；回原店云港融合菜也不可上架。
4. 至少一例旧店获券→云港进口→本地采购或探索→真实研发（耗料）→三菜上架→实际订单卖出并纳入唯一账本；两种不同厨具菜单可操作；没有进口也有正常当地营业。
5. 老存档章节金币/仓库/员工仍隔离，两个章节的换乘不会复制进口库存；新店不凭空取得旧料；新材料不进入云港本地常规探索表。
6. `npm test`、`npm run build`、离线资源、Chrome 三尺寸与 GitHub CI 分别据实记录；Pages 线上版本与用户手机观感单列，不冒充自动通过。
7. 本轮实测不足以确定八份回本，v0.15-D 双章多日经济审计继续保留最高优先级，必要时按数据调参。

## 7. 不做、风险与后续
不让原店仓库自动减少八份，不加双货币、不把旧食谱改成云港可用；这避免破坏旧章永久库存与既有旧档。风险：一种菜对特定厨具有更强吸引力、一次货箱八份偏富、老券积累成为长期库存注入。后续 P1 记录来自真实旧店销售的券取得成本、使用率、融合菜销量与两章库存/现金变化。
