# v0.15-G · 餐厅四彩色立柱精准清理、原店航运补给价值回调

**日期**：2026-10-22 · **先行规格** · 当前基线 `main / 0.15.0-alpha.6`。
**用户直接反馈**：放大的局部截图中，左上炉台以外的一组彩色立柱没有用途，两章均存在；返回原店完成一天营业，只能在云港换三份食材，跨章游玩的反馈不足。

## 现状 / 可定位根因

- 截图对象是 `src/scenes_v04.js::drawRestaurantV075` 中**独立场景装饰**：
  `for(let i=0;i<4;i++){rr(x(.15+i*.055)-5,y(.185),10,15+(i%2)*4,...)}`；位于 y=.185 的上部厨房墙边，对两世界绘制都运行；不是 `type==='GRILL'` 炭架，也无玩法语义。前版 v0.15-F 误把这组物件定位成烤架/旧壁柱，实际没有删掉此循环。应精准删掉**这段共享装饰循环**，两世界不再出现这四个彩色竖块；不删云港有功能辨识意义的悬索、港货、蒸笼或炉台本体。
- `src/engine.js::closeService` 只有旧店实际 `served.length>0` 才按旧店营业日唯一账本取得 `ferryCredits +=1`；云港 `redeemFerrySupply` 过去每张只发 `{cloud_rice:2,sky_moss:1}`，仅 **3 份、2 种普通食材**，且固定组合；每云港营业日最多兑换一笔、仅当前库存真实入账。回原店完整营业的机会成本远高于收益，因此有动力缺口。

## 设计：每张委托三选一、各 8 份云港普通食材

将原固定补给改为有策略的 3 种**等数量套餐**，全部只含云港当地四种普通食材，不含风暴晶核/Boss 料、金币或原店库存。兑换界面显示包名、数量、缺料用途、当前库存与真实材料，玩家可选择最需要的一包。

| 方案 ID | 名称 | 实际入库 | 玩法目的 |
| --- | --- | --- | --- |
| `staple` | 航路主食箱 | 云谷米×4、浮苔叶×2、酸铃果×2 | 连续营业消耗型主食/酸香菜 |
| `steamer` | 云汽蒸羹箱 | 浮苔叶×3、雷羽蛋×3、云谷米×2 | 解决蒸笼研发/蒸羹的雷羽蛋与苔叶缺口 |
| `tangy` | 酸铃调味箱 | 酸铃果×4、云谷米×2、雷羽蛋×2 | 酸铃爆炒的可持续上架与跨厨具选择 |

**相对旧版**：每张从 3 份提升为 8 份，约 2.67 倍；选择不同组合与菜单、厨具研发真正关联，不因缺某一项被迫拿固定补给。旧版的“至少售出1份才能有一张、同旧店营业日唯一、同云港营业日一笔”全部保留；避免空转刷货、跨章金币/旧菜搬运、Boss 资源通货膨胀，确保探索和当地市场依然有意义。

## 必须遵守的执行契约

- 兑换仅允许云港 `forecast/field/research/menu/prep` 的安全时机；仍不可在**未结算**的探索中兑换；玩家传入未知套餐必须拒绝且没有扣券/增库；没有券、已经兑换过、非云港、错误阶段全部拒绝。
- 一张委托**一张入库交易**：在云港本日唯一 `ferry-supply-${cycle}-${day}` ledger 下同时写真实套餐 `items` 和标识，成功后才减 `ferryCredits`；重复点击、读档、切世界不得复制物资、券或单日额度。
- 旧档已有 `ferryCredits`、旧领取账本仍有效；**不补发**已消费旧券，也不重置当天额度；旧档未来可兑换新 8 份套餐。
- HUD/原店营业报告说明“真实成交→委托”；云港市场明确展示“三选一、每张8份、每日一次”，订单/历史资产独立保留。
- 不改探索产出、日常市场规则、菜谱价格、星章目标、当地初始库存或人物工资；仍需专门做未来双章节多日经济实证，不声称本轮已平衡长期补给。
