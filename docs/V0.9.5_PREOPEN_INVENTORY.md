# 怪味食堂 v0.9.5 · 开业前库存检查

## 本轮目标

在不额外堆叠面板的情况下，给玩家一个真正有意义的“开门前库存风险提示”。进货仍共用当天的随机限量市场；并且库存不足**不能**阻止开门，玩家仍然能选择承担风险。

## 计算规则（只是估算，不是假造的订单）

- 使用已实现的 `serviceDayPlan(s).count` 获取今晚**预计**到店人数；不是已经下单的人数。
- 将预计人数尽量均匀地分配到三道上架菜（例如预计13人：5/4/4）。这个分配仅作为提醒模型，**实际客人会根据偏好和价格独立选菜**，因此不能当成真实订单保证。
- 对每道菜使用玩家当前激活工艺的真实 `recipeCraftSnapshot(...).ingredientIds`，同种原料按重复数量累加，多道菜共享同一种材料也合并计算。
- 已提前预制的料理记为已供应份数，计算待加工需求时扣除，不会再次估算它们的原料。
- 余料与预计用量逐项比较，存在短缺才提示。最多显示两个最值得留意的食材及现有/预计份数；不足三种以上时显示“等N种”。
- 玩家购买、预制或给员工做餐后，重新进入当前准备 UI 即时重算；不引入持久的风险标记，也不修改真实原料余额、已有客单和日志。

## UI 规范（优先级最高）

原本的厨房准备卡已经有厨位、伙伴、客流与三道预制按钮。新功能位于**客流提示下方、预制按钮上方**，只有一条背景轻微变化的紧凑状态条，不能扩展为另一张大型面板：

- 有风险：一行主提示“预计X种原料偏紧”，下方最多两种材料库存/预计需求，并显示一颗“采购 ›”按钮。只有市场不能直接供应任何缺料时，按钮改成“查看 ›”，避免暗示一定能补齐。
- 无风险：“按今晚客流估算，备货较充足”，下方“预计X位客人 · 已预制N份”，右侧仍可进入采购。
- 补货按钮复用当前 `stock` 弹窗。单日仍只随机上架3–4种基础食材，每种6–9份额度；不重置今日采购、不增加隐藏临时供应、不出售Boss专属原料。
- 手机窄屏 (<=350px) 收紧间距与文字；屏幕低于650px时缩紧高度并保持原厨房卡滚动。按钮最低点击高度34–38px，正文与采购页分别采用对应深色/浅色主题，不能再次出现低对比度文字。
- 若原料不足，照样可以开业（只受厨位覆盖限制）。玩家可以选择承担风险、减少某道预制或按当天市场补货。

## 回归

- 估算覆盖重复菜单、共享食材、激活工艺、已预制数量、实际金钱/库存不变。
- 仅有特殊/野外原料不足时，不能谎称可直接进货。
- 购买后库存/风险变化与当天market一致，不允许重复采购。
- UI 中仅增加一行内嵌状态，不创建第二弹窗或浮层，不挡住餐厅画面和已存在的动作按钮。
- GitHub CI: `npm test` + `npm run build` + `python scripts/build-standalone.py`。
- 最后仍需 iPhone Safari 真机验收：三道料理名称较长、最高六座、厨位与伙伴都已解锁时，检查卡内滚动、主按钮是否可触达，以及 320px 视窗提示是否完整。自动测试不能替代实际触摸验收。
