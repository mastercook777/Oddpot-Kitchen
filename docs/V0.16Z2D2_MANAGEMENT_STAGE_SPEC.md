# Z2d2 · 经营三页同源3D舞台
2026-11-26；基线 main d070ad9（Z2d1 PR143 17/17 CI通过并合并）。玩家提供实际 Z2c14 开店准备截图，认可其后厨近景比例，要求结算、扩建与其对齐，并明确先文档后落地。
## 目标与范围
准备页原镜头保持不变；日报新增真实同一餐厅近景，账单与明日线索放在下方独立滚动区。扩建默认同一后厨近景，而非旧远景；因同一近景不能同时容纳前排桌椅，提供同俯角同尺度的「后厨 / 餐桌」切换，餐桌视角只平移中心，不用全景缩小家具；实际扩桌成功后切到餐桌，厨房升级后切回后厨。顶层舞台共享准备页43%（短屏也保持相同规则）、135px最小高度、金边与上下分区。底部操作始终可用，账页/扩建内容滚动。保留实际已有桌/炉、员工、资产，不伪造营业事件或订单；收工图景使用只读非营业预览，清晨、营业和探索不变。
## 实装与数据
复用 restaurantView/drawDiner/y2CameraFrame，日报与成长都忽略已结束的服务快照；真实当前厨房与桌位来自同一布局。后厨相机完全复用 prep 参数（position 5,15,16 / target 5,0,4.2 / half max(5.6/aspect,3.65)）。餐桌相机按真实桌位前后中心平移 Z，保持俯角、横向尺度与相机距离；视野外后厨允许裁切。切换是内存UI状态，不写存档、不改经营时间/账本/升级条件。云港仍2D，原2D fallback保留；不改角色专项、核心版本和依赖。报告滚动、账本抽屉、晋升/继续路径不变。
## 验收
320/375/390：准备、日报、升级相同后厨镜头和舞台高度规则；实际WebGL报告且无客单/模拟推进，扩建3D真实更新、餐桌近景与后厨可互切，账单及继续操作可达，无重叠；截图三页。数学/源码测试验证相机同源、餐桌平移等距、世界/服务预览边界、旧档及无交易副作用；完整17项CI、离线与Pages分别记录，真实iPhone画面待玩家确认。
## 决策
为了避免再出现远景小家具，升级页默认后厨、另设餐桌切换；这是本轮实施选择，未把用户截图误当成要求同时显示全店。下一步Z2d收尾及Z3。
