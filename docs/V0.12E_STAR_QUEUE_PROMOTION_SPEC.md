# 《怪味食堂》v0.12-E · 晋升提醒 × 首星客流 × 四桌等位与经营价值
**日期**：2026-10-15。**状态**：用户已明确批准直接开发；实现过程必须避免仅靠UI伪造等位。**前序**：v0.12.0-alpha.3 / PR #56 员工像素升级完成。

## 玩家诉求与现状判断
1. 员工工作经验真实累计，但晚间日报只显示「XP+数字」，缺少「经验已够→可以晋升」提醒；晋升实际还需在备餐/成长阶段人工付费。
2. 第四桌是220金币真实空间升级，但普通自然客流仍和两/三桌基本相同；受三波分散到店与相对低顾客总数影响，四桌后极少发生真实等位，投入未获得收益反馈。
3. 餐馆不能只是扩建后数值性多赚；须引入首星带来的自然口碑需求，**三/四桌面对同一需求**，空间扩建改善真实吞吐与弃排，而不是第四桌自己凭空生出人。

## 本版承诺（目标alpha.4）
### A. 日报/备餐双入口即时晋升
- 生成营业日报后遍历**真实** `game.crew` 工作XP与`crewPromotion`。只要达到阈值，日报「员工成长」区明确展示 `阿火可以晋升 Lv2（28金币）` 等，且为有真实事件/状态依据的信息。
- 在日报直接提供可点击「去安排晋升」，打开既有员工面板并**允许此时确认真实付费晋升**。因为当日晚间工资已结算、当晚班次快照已冻结，晋升只影响之后营业；沿用唯一`promoteCrew`交易，明确扩展合法阶段到report（prep/upgrade原样），无需构造日报虚假直升新事务。随后在下一营业准备时员工按钮显著提示「N人可晋升」。
- 晋升金币不足仍看到达标提示，显示「待筹28金币」而不是隐藏；达到Lv3无晋升提示。
### B. 首星后的可解释自然客流
- **首星口碑**而非「四桌自动添客」触发可重现的自然需求升级；未获星章前、评星进行中的基础人数与原流程完全不变，已在进行的营业不可重排。
- 已获首星以后，按场景/声望增加约3–5位自发食客，每晚自然顾客不超过19。现有付费营销客仍然逐个添加真实订单，费用照旧。
- 玩家可以选择暂不买第四桌：仍接到同样的真实到店需求，但三桌更容易排队或损失顾客；买第四桌会真实增加两席，减轻等位和失客、提高实际可服务订单/收益。不能强制每晚必有排队；高峰场景的概率和峰值应较明显。
### C. 店外排队与耐心
- 收工后的矿工、集市晚高峰采用更集中的**真实预约波次/到店时间**，且**不会只在4桌时出现**：首星后的所有桌数共享同一个高峰客流计划。
- 订单只能在有座位时进入餐厅，目前`spawnArrivals`正确采用实际桌位。没有座位的已到店食客留在门外**进入等位状态**；已有门外Canvas像素排队视窗应从实际`waiting`订单绘制，顶部简短等位数量实时更新。
- 门外食客等候达到合理容忍时间（本版24个营业秒）会**真实流失**：只能记录为`queue_left`且不能出品、收入、声望虚构；日结展示**等位峰值、成功等位入店、放弃等位**三项。仅依实际events统计，不编商业利润。恢复旧存档时不改变既有订单计划，旧班次兼容新字段缺失。
- 在门外等位不会重置耐心：客人实际入店时记下真实等待秒数，点单时扣减约每秒1.15点耐心（上限24，点单后至少8秒），避免三桌利用排队得到原先不合理的免费缓冲。该规则对三/四桌一致；无队列的首星前旧餐厅保持原有耐心。\n- 座位释放后按已到店顺序入席；保留现有结伴座位、餐桌碰撞、服务路线。第三厨位/新员工/二星/传送门本次不做。
### D. 上线前量化试验与验收
- Node针对性单元：首星前后人数、3/4桌同计划、排队只在满座发生、弃排不会收入、队列峰值真实、手动晋升可达标提示、保存恢复冻结旧服务、单日工资与营销没有重扣。
- 受控`scripts/simulate-management-v012e.mjs`至少80固定种子 × 3/4桌 × 不同员工/营销/低库存：真实引擎从开门到结算，比较等位峰值、成功接待、流失、真实服务/利润及经济边界。**是否有效以结果为准，如4桌并无实际改善则迭代参数，不假装通过。**
- 320×568、375×667、390×844真Chrome：备餐晋升提示、日报反馈、门外真实排队、返回员工面板、存档/离线版本、触控入口。不得将CI当作iPhone玩家主观验收。

## 兼容性与明确边界
- save schema4、ledger去重、XP累计规则、培训费、原有工资、食材、顾客满意、两锅站位、第一星评分阈值全部不改。
- 晚间在星章颁发时刚解锁首星，当晚已建立的服务订单计划**保持原样**，新口碑客群从次日开始生效。
- 这是**中后期自然需求/服务吞吐率经济试验**，不确保任何玩家无备料情况下能接完高峰订单；客人真实流失正是经营问题。若仿真发现盈利仍滚雪球，另行平衡而非偷偷加税。

## 实施边界与发现（开发阶段，2026-10-15）
- 新单源`src/restaurant_demand_v012e.js`为首星口碑顾客需求/到店波次/门外24s期限/队列审计；`src/engine.js`运行真订单与真实入座、弃排和结算，日结排队字段来自唯一`v.events`；`src/app.js`日报直接晋升及备餐提醒并显示峰值、成功等位及流失。
- 第一轮固定种子模拟曾显示**四桌流失较少但完成反而较少**，原因是旧入座系统外面排队时耐心不减少、进门点单时重置计时。这不符合真实顾客体验，也让狭窄三桌得到无意的时间优势。代码更改为门外等位产生真实耐心消耗，不依桌数人为送额外订单。
- 设计自检：比较的两组使用**相同seed、自然访客和菜单**，只切换三/四桌的真实座位容量，不能把新星章自然客群算作第四桌本身创造的订单，顾客必须入座→完成实际餐食→成交才有收入。低库存下第四桌不能凭空赚钱。80种子综合回归与移动Chrome以Actions记录为准。
- 本版不新增后厨工位：当前真实限制依然是两口锅；第四桌投入的回收周期可能仍较长，需用实际成本/收入和后续第二星章再评估。首星之前队列不强制出现，不能假装每晚有排队。iPhone实际手感与经营节奏由玩家验收。
