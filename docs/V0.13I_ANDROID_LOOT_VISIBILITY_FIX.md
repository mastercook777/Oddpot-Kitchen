# v0.13-I · 安卓探索掉落物可见性兼容修复

## 事件与证据（2026-10-16）

玩家提供 Android Chrome 实机截图：v0.13.0-alpha.7、营业第14天、探索第2/3段，背景/道路/像素主角/操作按钮均能看到，HUD和自动拾取提示“采到 铁角野牛肉 ×1”正常，但用户报告地上物品渲染缺失。本截图是在已拾取且可结束区段的瞬间，不能单凭截图证明拾取前是否不可见，更不能声称资源数据或掉落规则坏了。

**源码事实**：真实游戏资源节点在 `f.nodes`，`src/scenes_v04.js` 的混合环境 `fieldSpriteArt` 分支调用 `drawHerbPixelNode`；食材 sprite 原由 `herbGetSprite` 在 16×16 离屏 Canvas 用 `fillRect` 生成，随后在地图主 Canvas 调用 `drawImage(offscreenCanvas,...)`。角色和环境分别用其他路径渲染。代码没有外部图片 URL 下载依赖；暂不确认 Android GPU / Chromium 是否实际导致失效，**硬件差异只是待验证假设**。

## 稳健性修复边界

1. **绕过掉落/采集食材的“离屏 Canvas → Canvas drawImage”二次上传**：`drawHerbPixelNode` 对普通及 Boss 食材节点在主 Canvas 以同一权威 `herbPaintFood` 16×16 像素指令和 .76 tile 大小直接绘制。保留原颜色、尺寸、上下浮动、目标四角标、阴影与NPC单独素材路径。不改任何掉落数量、战斗、地形、背包或拾取计时。
2. 仅用主 Canvas `save/translate/scale/fillRect/restore`，无需网络请求、data URI 或临时离屏 Canvas。浏览器 GPU 兼容风险相对减少，但不是已确认的特定 Android GPU 根因。
3. Canvas 像素层的合成和采集状态必须可测试：未拾取可见且无 `drawImage` 依赖；`claimed=true` 不渲染；旧首领稀有、8常规食材、商人/奇遇路由仍可绘制；低分辨率设备下不模糊，屏幕大小相对保持。
4. 版本提升到 `v0.13.0-alpha.8`、修改网站 JS cache key、重新生成离线包。保留历史草甸与8生态/14地图、供应链数值与所有经营逻辑。
5. 跑现有所有 Node / 手机 Chrome 320、375、390、离线版，另加用真实浏览器测试无跨 Canvas 的食材像素输出。真机 Android Chrome 尤其低端 GPU 仍需反馈验收。

## 用户复测问题

- 掉落前是否也看不到食材？在所有地图和所有食材中都如此吗？
- 背包与市场的食材 icon 是否可见？（DOM 中另有 data URI 路径）
- Chrome 版本、Android 版本、设备型号、能否提供“地上待捡而未捡”的画面。勿把一个已经拾取完成的截图误判为绘制错误。
