# Z2b · 料理研发、菜单与备餐的场景化交互
2026-11-25。玩家验收Z2a3并确认Hearthcraft方向，细化后置；PR124 17/17 CI全成功。进入更重要的全局UI/UX优化，延续Z1四层信息体系。
## 目标与范围
研发是实际挑选/投入/处理食材，菜单是餐厅内写下三道菜，备餐是面对真实餐厅安排厨位及预制；不是一组通用管理卡片。保留Hearthcraft实色图标、现有食材图、3D/2D、真实研发计时/工艺、库存扣减、菜单三道/隐藏菜/工艺、章节限制、实际厨位覆盖/改装费用、雇员/宣传/评鉴/库存估算、开店条件、旧存档、Z1触摸。无新增资源/数值/研发规则。其他阶段Z2c。
## 研发
- 单条阶段HUD（阶段名、日数、金币、图鉴/设置；实时研发仅阶段及设置不打开会阻塞计时的额外入口，保留原设置行为与暂停）。取消重复品牌/进度条；保留首次引导。准备工作台采用木/石桌、主厨具器物（Hearthcraft放大资产，不是假3D）、三格已选食材托盘，显示真实库存，点击格内食材取消；真实选2–3种约束，默认选中与章节筛选不变。厨具切换为横向实体器物按钮； pantry紧凑格子并可独立滚动，通过滚动访问全部库存，不隐藏不可用食材。菜谱线索置于工作台下方，最后结果/详细信息按需展开。主按钮开锅，图鉴/去菜单仍可达。
- 实时锅具或烤架拥有主要展示空间；原真实3D挂载host及2D fallback、食材状态/火候/计时、下料/翻炒/颠锅/封笼/排汽/穿串/火位/翻面/刷料/起锅不改。操作区尽量单行、短字+Hearthcraft相关资产，保持44px；实际可达条件和倒计时保持。失败/成功收据保留原属性/用途与复盘，收据3D挂载原位置不改。
## 菜单
- 木框黑板承载三张独立纸质菜签，展示真实食材组合小图（不假装是实际菜品成品图），菜名、售价、每单时间、可做份数、当前工艺；用厨具图标标明实际生产设备，点击任何菜签仍打开真实替换菜谱清单。换菜清单按厨具分组、现有禁选原因不变；共鸣、隐藏菜入口与今日客群/厨位压力保留。避免把独立可做数相加。
## 备餐
- 把原覆盖餐厅72–75%的管理面板拆成上下布局：真实餐厅独立可视区域（非截图，目标>=40%阶段高度，短屏>=135px），下方工作区可滚动；厨位对应实体器物与当前等级、已配置类型高亮、切换直接调用既有configureKitchenSlot。2/3厨位和4类厨具（所有已购）真实可达。优先展示设备覆盖/缺少、工作台、预制菜；员工、经营目标、营销、评鉴、库存保持可达且不叠盖场景。现有营销展开状态保留；滚动位置切换动作后恢复。操作区固定开门与员工入口，未覆盖禁开店，库存只预警。
