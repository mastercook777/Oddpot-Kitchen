# 怪味食堂 / Oddpot Kitchen — H5 核心玩法原型 v0.3

**在线试玩**：https://mastercook777.github.io/Oddpot-Kitchen/

原型是中文、移动 9:16 优先、离线可玩的单机游戏。当前目标是验证三种不同的乐趣能否连成一个真正有反馈的循环：**森林寻找食材 → 炒锅发现料理 → 三菜菜单构筑 → 自动营业观察顾客 → 从反馈寻找下一道菜**。

## v0.3 的重要调整（相对 v0.2）

- **全屏手机游戏而不是纵向滚动网页**。HUD / 游戏场景 / 操作区固定；图鉴、仓库等二级信息用内部滚动抽屉打开。已在 390×844、375×667、320×568 模拟视口做过基本交互验证。
- **8 种食材、12 道可发现料理**（其中一份隐藏变体）。12 道料理使用同一份规则、真实三拍温区、消耗库存才能研发成功。图鉴提供线索；研发后能进入菜单，自动标准化制作。
- **可移动森林**。两个差异路线、格子场景、障碍、定向采集、危险节点、真实背包、撤离、确定性种子、到账一次。玩家可以直接点击目标，让厨师逐格走过去，也可使用方向键。
- **可视化餐厅自动出餐**。真实桌位、客人点菜/等待/离店、WOK/POT 双工位、自动厨房；不在每张订单上重复炒锅玩法。店长保留可影响结果的「优先出餐」「招待客人（花 5 金币，耐心+9秒，每晚一次）」「波间备餐」操作。
- **营业结果反哺研发**。记录营收/利润/客人满意/工位占用与顾客反馈，提供来自真实未解锁配方的下一步线索；第三晚仍是爆炎厨王挑战，失败保留收入。

### 试玩建议

1. DAY 1 进入晨露森林，标记琥珀洋葱或地精土豆，点击地图上的目标采集点，再主动撤离。
2. 料理实验尝试「土豆＋洋葱，焖煮」，把土豆移动到锅心，烹饪三拍。
3. 把新菜放上三菜菜单，看今晚来的顾客是否喜欢、两台锅谁更繁忙。
4. 尝试一轮完全不主动干预的营业，再用优先订单或招待顾客对比结果。

## 开发与测试

- 网页入口：`index.html`（原生 HTML/CSS/JS 模块，可直接用静态服务器/GitHub Pages）。
- 实现：`src/data.js`（内容）、`src/engine.js`（纯规则/经济账本）、`src/app.js`（场景和交互）、`src/style.css`（美术占位/固定布局）。
- 独立离线测试：`standalone.html`，用 `python3 scripts/build-standalone.py` 重新生成。
- `npm test`：Node 原生单测，不要求安装额外依赖。
- 本机调试：`python3 -m http.server 8000` 后打开 `http://localhost:8000`；或安装依赖后运行 `npm run dev`（Vite 供后续工程化）。

## 当前限制，务必不要误称已完成

- 角色、环境仍是 CSS/emoji 占位；没有专门绘制的图块、美术帧或复杂动画。
- 森林是可触控移动与采集、危险格子回避原型，不是实时怪物 AI / 复杂战斗。
- 餐厅布局固定两桌双锅；还不能自由摆设、扩建、走动 NPC 路径寻路。
- 料理是 3×3 × 3 拍确定性研发；食材与菜谱数量、评分和火候数值仍需原型反馈。
- 当前无服务器、帐号或云存档；localStorage 的 `oddpot-prototype-v03` 与 v0.2 存档**隔离**，因此更新后从 DAY 1 开始。
- 第三天厨王采用共用营业规则和公开四项评分；难度平衡尚待用户试玩验证。

**测试重点**：不让三个系统变成只是以货币连接的三个小游戏，而要让玩家因顾客反馈主动想去寻另一种材料、研一道新菜。请把反馈优先放在这个闭环上。
